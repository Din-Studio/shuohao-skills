# 剧本通用内容评审

结构检查与内容评审分开。脚本只证明字段、位置、引用、计时和对账事实。评审必须阅读实际正文，不凭绿色检查状态宣称故事成立。

## 必查问题

1. 来源：原创是否明确？改编材料的保留、删除与合并是否有证据？来源不足是否说明？
2. 人物：行为是否由处境、目标、关系或价值选择产生？是否只为移动节点而行动？
3. 因果：证据出现、人物理解、行动和结果是否连贯？前后场道具、位置、知情状态是否衔接？
4. 节点：逐个 B ID 对照 setup/outcome 与核心段。认领存在不等于事件实际发生；同一结果是否被重复计数？
5. 开场与集尾：openingBeat 和 endBeat 的实际文字是否表达计划？末拍位置合法但事件未完成，仍需修订。
6. 问题：从上游 ep 查 question，从 resolves 节点查 beatClaims。是否真正回答所提问题，而非仅提到同一名词？没有 outline 时明确无法核对。
7. 节奏：依据本次策略提问。慢热是否在推进信息？密集是否重复？开放是否已经完成本次承诺？不要恢复统一短句或悬念要求。
8. 估时：证据、停顿和选择是否被压缩到不可理解？估算与表演可能偏离，是否说明？
9. 跨批次与下游：状态是否连续？上游调整后是否重投影、重认领，是否列出下游失效项？

## 记录方式

在当前工作记录或 .work 中记录：分集、B/Q ID（适用时）、[场次,节拍]、实际台词或动作、判断、修订建议、复核状态。没有证据就明确未核验。不得新增永久总分、爆款概率或门失败累积日志。

《修伞簿》可核对 E1 B02 的“纹路不能认人”、E2 B04 的自留电话、E3 B06 的继续谈话约定。它们是作者提供的复核入口，不是自动内容评审结论。
