# 写戏：从计划到可表演正文

## 开始前

读取 schema、通用评审和本次四维 profile 指南。确认人物知道什么、想做什么、已经发生什么。题材、叙事风格、结构和节奏分别选择，不从竖屏推导快节奏。

先决定故事，再安排事件，最后填写场次与节拍。大纲 opening/ending 是必须保持的计划投影；真正的动作和台词在 flow 中实现，允许不同措辞。

## 表达方法

- 人物的选择要有动机和代价。台词体现身份、关系与当下目的，不统一改成快速口语。
- 动作描述可观察或可表演的变化；一句台词单独放入 line，不藏在 action。复杂交互注明制作风险，不假称模型必然失败或已经成功。
- 观察、沉默和停留可以承担证据、关系或情绪，不因没有运动就删除。
- 台词长度、停顿、VO 与动作频率遵循有效规则和已加载指南。不强制三句插动作，不强制冷开场或集尾悬念。
- 尊重大纲实际 mode/event：closure 可以安静结束，open 要有确切停止位置，suspense 也不要求剧本复制 Q。
- 角色在场不等于多人同框。此处不安排镜头或人群拍摄方案。

## 节点核心段

按 B ID，而不是类型标签，逐项定位 setup/outcome 在正文里的核心表现。两个不同节点即使同类型也不能合成一次认领。认领顺序跟随大纲，核心段互不重叠；共用铺垫可以放在认领之外。允许同集跨场次，不为认领强行拆场。

示例：B01 是发现线结，B02 是决定不凭纹路认亲。两者可以发生在同一张工作台前，但应分别找到信息出现与人物选择的核心段。仅放入“我明白了”不能证明选择已发生。

## 时长修订

先估算，再核对真实表达。字符估时与动作固定秒数只是统一预算模型，不是表演秒表。

超出目标时依次处理重复表达、无效过渡和不影响因果的动作。保护关键证据、人物选择、后果和必要停顿。仍容纳不下时回到 outline 修订事件或目标时长。不能通过改 targetSeconds、提高容差来掩盖上游目标不同。

不足时检查是否遗漏必要行动或结果，不为补秒增加寒暄。语速参数要有表演依据，不为过检查任意加速。

## 修改与跨批次

改一拍后连读前后相关节拍，检查人物位置、道具状态和知情范围。再更新 openingBeat/endBeat/beatClaims，不依赖旧坐标仍然凑巧有效。

每批最多三集。记录上一批实际结束状态和下一批尚未兑现的承诺。不把批次末集当作全剧末集。剧本变化要告知下游认领失效范围，但本阶段不自动重写分镜。

## 来源

本指南内化本仓库的场次、结构化台词和创作策略解耦实践。没有外部运行时依赖；表达建议不是市场成功保证。
