# 可选设计：生成角色设计块

你是在为一部动画改编准备制作素材。给你一个已登记身份的名字、来自原剧本的观察记录、以及可引用的原文片段，按本次任务选择 persona、voice、image 设计，未选项不要求生成。身份字段始终按 schema.md 维护，设计块只附加在该身份上，不按名字重新归并。

**只输出 JSON，不要任何解释、不要 markdown 围栏。** 字段见 `design-schema.md`。

## 语言

调用方会给一个**报告语言** `lang`（默认 `zh`）。字段分两类：

| 类别 | 字段 | 语言 |
| --- | --- | --- |
| **给人读的** | `oneLiner`、`persona.*`、`voice.timbre/pitch/pace/accent/emotion/referenceHint`、`image.style`、`image.promptLocal` | **`lang` 指定的语言** |
| **喂给机器的** | `image.prompt`、`image.negativePrompt`、`image.tags`、`image.sheet`、`voice.prompt` | **永远英文** |

机器字段不跟随 `lang`——图像模型和 TTS 引擎吃英文最稳，跟报告用什么语言无关。

`image.promptLocal` 是英文出图提示词的本地语言译文，给人看的。**`lang` 是 `en` 时省略它**，否则就是原样重复。

**`voice` 没有 `promptLocal`，这是有意的。** 音色的六项（`timbre` / `pitch` / `pace` / `accent` / `emotion` / `referenceHint`）本来就是本地语言的必填字段，人审看那六项比看一段散文更快；再给一段中文译文只会多出一个长得一样的复制按钮，用户会把它喂进 TTS 引擎——**生产里真踩过**。报告里音色只留一条提示词，就是喂引擎的那条。

## 硬规则

1. **一切基于观察记录。** 一定要有值的项（身高、肤色、发型、服装这类设定图要画出来的外观）剧本没给时，按 [principles.md](principles.md) 第一节区分**估**和**设计**：剧本里有一句话限定它的是估，标注出来——中文报告加「（推断）」并写依据原文，英文报告加 `(inferred)`，其他语言用该语言的等价说法，**只用一种标记，不要中英都加**；剧本里没有限定它、哪个值都不和剧本冲突的是设计，直接写，不标。估和设计都只定一个具体、平常的值，不新增和剧情有关的特征。需要用户点头的选择写进交付汇报（见 principles.md 第二节）。

2. **`persona.evidence` 只能放「可引用原文」区块里的字符串，逐字照抄。** 不许翻译、不许裁剪、不许把两条合并、不许从观察记录里另找。那个区块是空的就返回空数组。**注意：引文永远保持原文语言，不跟随 `lang`**——它是证据，翻译了就不是证据了。

3. **`image.prompt` / `image.promptLocal` / `image.sheet` 里绝对不许出现角色名、别名、作者名、作品名。** 图像模型对这些偏见极重，会画成它记忆里的角色而不是你的角色。描述这个人，不要叫他的名字。

4. **族裔、年代、地域必须从原文推断出来，明确写进 `image.prompt` 和 `image.sheet`。**

   这是上一条的另一半：名字不能写，那这个人长什么样、是哪儿的人，就只能靠描述交代。**不写死，图像模型默认画当代西方白人**——民国的老船夫会出成一个穿工装的美国老头。

   三样都要落到提示词里：

   | 要素 | 写到这个程度 | 不要这样 |
   | --- | --- | --- |
   | 族裔与面部特征 | `East Asian, Han Chinese features, monolid eyes` | `an old man` |
   | 年代 | `early 20th century, Republican-era China` | `historical` |
   | 服饰与地域 | `coarse indigo cotton tunic, southern Chinese river town` | `traditional clothing` |

   **依据来自原文，不来自报告语言。** 报告出成日文不代表人物是日本人——`lang` 管的是谁来读，不是故事发生在哪。原文没明说就按文本推断：人名用字、地名、称谓、器物、节令、货币、饮食都是线索。

   推断出来的内容按第 1 条标注在 `persona.appearance` / `persona.identity` 里；**提示词里不标注**——那是给机器读的，`(inferred)` 混进去会被画进画面。实在推不出来就定一个中性但具体的设定，不要留空、不要写成泛泛的「亚洲人」。

5. `image.prompt` 是**单张表现性插画**（不是技术图，可以放开打光）：四分之三视角半身、纯中性背景、柔和方向主光 + 冷调补光、浅景深、面部最实。

   **画风不要自己想，也不要写「扁平矢量卡通」这类含糊的话。** 实测含糊的画风描述会让模型跟自己拧巴——同一批角色出来有的偏动画、有的偏写实。画风由用户在项目配置中明确提供，跑 `node scripts/mint-characters.mjs style` 取出来，把 `render` 那句**原样**放进 `image.prompt` 与 `image.sheet`，`surface` 那段跟着进去；`lighting` 那段只进 `image.prompt`，设定图的光由版式固定句定（见 `style.md`）。

   `negativePrompt` 同理：把画风那一块的 `negative` **一条不落**地带上，再补这个角色自己要禁的（戴眼镜、叼烟之类）。少一条 `validate` 会点名。

   **具体到什么程度，看画风那一块写了什么。**写实那一档的判断标准是「真实感来自不完美，不是细节量」——皮肤要可见毛孔、肤色不匀、鼻翼耳缘的细微毛细血管；眼睛要有湿润高光、虹膜纤维；**眼睑和眉毛左右略不对称**；发际线有细碎碎发破开轮廓；老年角色的**皱纹要顺着表情肌走**（法令纹、鱼尾纹、抬头纹），不是随机刻线；布料要可见织纹、肘部袖口膝盖的磨损与光泽。平涂动画那一档的标准完全相反（无毛孔、成簇发丝、平涂无织纹），照那一块写的来。

   **完整写法见 `realism.md`**：姿态要写成正在发生的瞬间、眼神要有去处、服饰要点材质名带穿着痕迹——这三样**哪一档画风都要**；毛孔、次表面散射、胶片颗粒那一组只属于写实档。那份文档还写死了摄影感的边界：**浅景深、颗粒、抓拍、偏心构图、方向光只进 `image.prompt`，一个字都不要进 `image.sheet`**——设定图是身份档案，糊了歪了就认不清人、量不了比例、抠不了图。

   **角色自己的部分才是你要写的**：五官特征、体态、服装、神情、道具。画风那几段是所有角色共用的底子，写完记得检查同批角色**不许雷同**——`validate` 按词集合算相似度，`image.prompt` 和 `image.sheet` 主体区超过 75% 都会被拦。

6. **`image.sheet` 是角色设定图：一张按 `production.image.asset.aspectRatio` 设置的横向或方形画布，白底，左边一张严格正面的脸部特写，右边三个等宽竖格画脖子以下的正面、侧面、背面。** 整张图只有左边这一张脸。完整版式、必写内容、生物和未成年人物的规则见 [sheet.md](sheet.md)，群演（`entityType: group`）改用 [crowd.md](crowd.md) 的群像图；段落顺序和纯净画质段见 [sheet-prompt.md](sheet-prompt.md)。

   和 `image.prompt` 的分工正好相反：

   | | `image.prompt` | `image.sheet` |
   | --- | --- | --- |
   | 是什么 | 单张表现性插画 | 身份档案 |
   | 姿态与表情 | 正在发生的瞬间、具体的微表情 | 中性站姿、放松平静地看向镜头 |
   | 光 | 柔和方向主光加冷调补光（`style.character.lighting`） | 固定句 `Soft even frontal studio lighting, …`，脸和衣服上没有明显阴影和色光 |
   | 摄影感 | 浅景深、轻微颗粒可以有 | 一个字都不要；最后是纯净画质段 |
   | 手持物 | 可以带 | 摘得下的东西是道具，不画 |

   提示词里必须写明：画幅实际值、`strictly frontal close-up of the face`、`from the neck down`（群像图改为 `all different heights and builds`），最后单独一段纯净画质段原文照用；版式和画风之外必须有这个角色自己的身份锁和服装段（主体区，见 [sheet-prompt.md](sheet-prompt.md) 第五节）。这几样 `validate` 都查。身上有单侧特征时写明侧面那一格画这个人自己的哪一侧。

7. `voice.prompt` 是给 TTS 音色设计引擎的：描述**乐器本身**，不是某一句台词的演绎。性别、听感年龄、音色、音高区间、共鸣、气声、语速、节奏、口音、能量、默认情绪。

   **音色设计是一个静态的声音身份。** 引擎要的是「这把嗓子长什么样」，不是「他这句话怎么说」。四类东西写进去就会让效果变差，生产里逐一踩过：

   | ✗ 不许写 | 例子 | 为什么 |
   | --- | --- | --- |
   | **文学比喻** | 「字与字之间像在秤上掂银子」「一张听得见笑、却不能信的嘴」 | 引擎映射不到任何声学参数，纯粹稀释有效信息 |
   | **表演指导** | 「威胁时从不提高音量——反而更轻更慢」 | 那是导演给演员的话。音色不随剧情变 |
   | **条件分支** | 「公堂场合能切换成过得去的官话」 | 一个 voice 只有一种口音。写「切换」只会让输出不稳定 |
   | **引号台词** | 「杀意藏在『规矩就是规矩』这类客套话里」 | 有些引擎会把引号里的字当成要朗读的内容。**`validate` 拦这一条** |

   四条里只有引号台词设了门——它判定干净。另外三条靠写卡的自觉：**关键词扫描会误伤正常描述**（「说话时」「低音区」都含「时」「区」），而误拦的门比没有门更糟。

   **写成紧凑的参数串，不要写成散文。`validate` 卡 400 字符。** voice design 引擎吃的是参数密度，铺陈的英文散文会把参数稀释掉——生产里拿同一个角色实测对比过 500 字散文与 230 字参数串，**后者明显更好**。上限 400 是量出来的：自带样例四个角色 218–245 字符，被判为冗余的散文版 490–514，中间余量很大。它拦的是「写成小作文」，不是「写得细」。

   固定的参数顺序，照抄这个形状：

   ```
   〔年龄性别〕, 〔音色〕, 〔音区〕, 〔共鸣/支撑〕, 〔动态范围〕.
   〔音量〕, 〔语速〕, 〔语调习惯〕. 〔口音〕. 〔默认情绪〕.
   ```

   ```
   19-year-old female, light breathy soprano, mid-to-high pitch, thin chest support,
   narrow dynamic range. Quiet volume, slightly hesitant pace, rising inflection at
   phrase ends. Standard Mandarin, no regional accent. Tentative and watchful.
   ```

   **从头到尾都在描述这把嗓子，一句戏都没有。**

   ### 这条提示词是给哪种引擎的

   **只有「文字直接设计音色」那一类引擎吃它**，别的引擎给了也没用：

   | 引擎 | 吃不吃 `voice.prompt` |
   | --- | --- |
   | **Qwen3-TTS Voice Design** · ElevenLabs Voice Design · MiniMax speech | **吃**。整段直接喂 |
   | CosyVoice 2/3 instruct | **不吃音色**。它的 instruct 是在零样本克隆之上加风格控制，音色仍然来自参考音频 |
   | IndexTTS / IndexTTS2 | **不吃**。音色只来自参考音频；IndexTTS2 的文本通道只管情绪，可以喂 `voice.emotion` 那一句 |

   用克隆系引擎的话，这条提示词帮不上忙——要靠 `referenceHint` 与六项去挑参考音频。**这不是提示词写得不好，是那类引擎根本没有这个入口。**

8. **同一批角色之间要能区分开，这条现在有门。** 会给你同批其他角色的名字，别把他们的长相和声线做成一个样。

   **`validate` 会逐对算独立插画提示词（`image.prompt`）、设定图主体区（`image.sheet` 剥掉固定文本之后）与 `voice.prompt` 的词级雷同度，超过 75% 报错并点名那一对；两个 sheet 主体区完全相同直接报错。** 阈值是量出来的：自带样例四个角色 `image.prompt` 两两最高 39%、sheet 主体区最高 29%，而「只改年龄与衣服颜色」的雷同用例在 95% 以上。相似度只是启发式提示，不代表语义审核。

   **最容易踩的形态不是照抄，是偷懒**：个体描述写得短，剩下全是真实感样板（毛孔、毛细血管、次表面散射、虹膜纤维）与固定的构图光照尾巴。两个年龄性别接近的角色一这么写，出来就是同一个人。**区分度要落在个体描述那一段**——主要角色之间至少在脸型、眼型、发色、发型、肤色、体型、气质里有四项明显不同，男女主与同性别配角之间尤其要一眼分开；每个人只写自己的特征，正文不提别的角色。

   `image.sheet` 只比较主体区：版式要求、正面光、画风和纯净画质段是大段固定文本，先剥掉再比，避免误拦。实际发送给图片模型的是 sheet，区分度最终落在这里，不在 `image.prompt`。

## 输入格式

```
Language: zh
Character: 老周
Also referred to as: 老伯、摆渡人
Other characters in this cast: 沈知微、陆行远、胡二爷

Observations gathered from the source text:
1. ...
2. ...

Verbatim quotes — the ONLY strings allowed in `persona.evidence`:
- ...
- ...
```

## 创作背景与视觉边界

参见 [creative-background.md](creative-background.md)。读取 production.creativeBrief 的自然语言要求，不推导策略。保留逐字证据、角色区分度、设定图版式、视觉正文和参考图挂载检查。正式身份入口读取原剧本，outline v5 仅为可选故事背景。画像、音色和图片分别按需设计，不是身份登记的强制条件。完整设计样例《渡口》与身份样例《回声台》均由本 skill 自有。
