# seedance 视频提示词 · 写法规范（内化版）

**什么时候读这份**：`production.json` 的 `video.model` 是 seedance 系列
（`seedance2.5` / `seedance2.0` / `seedance2.0 fast` / `seedance2.0 mini`）。选的是
`MiniMax H3`、或者两边都没写模型，就整份跳过，改读 `h3-prompt.md`。

**学习来源**：火山引擎官方《Doubao Seedance 2.0 系列提示词指南》
（`https://docs.volcengine.com/docs/82379/2222480`，页面最近更新 2026-08-17）。
方法论**内化成本 skill 自带文档，不依赖任何外部 skill**——搬过来的是判断，不是链接。

## 一、两套骨架为什么不通用

`videoPrompt` 的骨架按模型分流，不是文案偏好。三处是硬差别，全部来自官方口径：

| | H3 骨架 | seedance 骨架 |
| --- | --- | --- |
| 参考图怎么锚定 | 首行对齐指令把每张图钉在切点秒数上 | **身份说明句 + 全程复用的主体标签**，不提秒数 |
| 时间 | `[Shot k] At 00:06.000,` 逐镜给时刻 | **全程不许出现时刻**——官方原话「模型对精确时间（如 0–3 秒）的支持不稳定，强行限制时长可能导致生成结果异常」 |
| 台词与声音 | `<d>[Chinese] …</d>`，声景与配乐各占一个字段 | 台词 `{}`、音效 `<>`、音乐 `（）`，每镜自带音效，整体声景收尾收一句 |

所以选了 seedance 还照 H3 写，`prompt-structure` 门会直接点名时刻那一处——它正是生成
异常的直接原因。反过来也一样拦。**改了 `video.model` 就要重写这一批的 `videoPrompt`**，
不存在「两套通用的写法」。

分镜秒数照旧留在 `storyboard.json` 里：折算 `duration`、对齐配音、做剪辑都靠它，
只是不进提示词。

## 二、骨架（三道门盯着的部分）

```text
图 1 是……，下文称<主体1>。图 2 是……，下文称<场景1>。（每张分镜图一句，各给一个标签）

镜头描述：
[镜头 1] 中景, 跟拍 — ……<音效>
[镜头 2] 全景, 固定 — ……他压低声音说：{台词逐字照搬}

环境声与配乐：……（配乐写在中文圆括号里，没有就写「无配乐」）

（收尾段：画质 + 色调 + 约束词）
```

门查这四条：

1. `镜头描述：` 与 `环境声与配乐：` 两个字段齐全且按序
2. **身份说明段里每张分镜图各有一句 `图 k 是…`**——一段有几切就有几张图，少一句就是少交代一张
3. 描述正文里 `[镜头 1]`…`[镜头 N]` 逐镜齐全，每切的运镜词落在自己那一行
4. **全文不出现时刻**（`00:03.000`、`3.00-second`、`3.00 秒处` 都拦）

外加两条与 H3 共用的：认领节拍的台词**逐字**进提示词（用 `{}` 包，但门只认逐字——包不
包得住是写法，漂没漂是事故）；正文语言与 `promptLang` 双向对账（seedance 默认 `zh`）。

**身份说明的句式**：官方原句是「将<图片N>中的[核心特征]定义为<主体N>」。本 skill 统一
成 `图 k 是[核心特征]，下文称<标签>`——作用完全一样（先交代特征，再给一个全程复用的
标签），并且与 `novel-creation` 那条产线的骨架取齐，两条产线之间搬提示词不用再翻译一遍。
**标签一旦定下就全程复用**，这是官方点名的指代混乱主因。

## 三、实例（《渡口》E01-01，4 切 15 秒）

```text
图 1 是抱着旧皮箱、在雾里沿河岸奔跑的年轻女子，下文称<主体1>。图 2 是雾里浮出的木质渡口
全景，船头蹲着一个叼旱烟杆的老船夫，下文称<场景1>与<主体2>。图 3 是<主体2>立在船头拢手
喊话的构图。图 4 是挑着满担踏上跳板的中年货郎，下文称<主体3>。

镜头描述：
[镜头 1] 中景, 跟拍 — 浓雾里，<主体1>沿泥泞河岸奔跑，怀里死死抱着旧皮箱；镜头在她身后
跟拍，渡口还没露面。<急促的踏水脚步声>
[镜头 2] 大远景, 固定 — 奔跑到头，<场景1>从雾里浮出来，<主体2>蹲在船头，烟锅火星透过雾
一明一暗；镜头固定不动。<远处更夫的梆子声>
[镜头 3] 全景, 固定 — <主体2>立在船头，一只手拢在嘴边，镜头固定，他朝岸上粗声长喊：
{上船喽——过河的抓紧，雾要变天。}
[镜头 4] 全景, 跟拍 — <主体3>挑着满担快步踏上跳板，镜头跟拍他；他喘着气喊：
{等等二爷我！这雾天赶船，命都得跑掉半条。}

环境声与配乐：雾里被闷住的踏水脚步声，水拍着木桩，远处两记梆子，后段跳板上箩筐吱呀作响。
（低沉持续的弦乐，极慢，几乎贴着静音）

全片高清电影质感，冷灰绿色调，光影柔和；人物面部稳定不变形，动作自然连贯。保持无字幕，
不要生成 Logo，不要生成水印。视频全程禁止出现外形、着装完全一致的人物，禁止生成同款分身、
双胞胎效果。
```

（代码块里的折行只是这份文档的排版，实际一镜一行。这条实例同时是自测夹具，四道结构
检查逐条验证过。）

四切的秒数是 3 / 3 / 4 / 5——**一个都不写进提示词**，节奏交给分镜数量与描述本身。

## 四、分镜图当参考图：这是本 skill 走 seedance 的底牌

官方明确支持分镜图参考，案例的写法就是本 skill 的形状：

> 参考图片3中的分镜构图，女孩正在等爸爸做好饭，她说：「…」，接着镜头向右横摇，切换至
> 图片4的画面和构图，爸爸形象参考图片2，爸爸回答她：「…」

落到本 skill：段文件夹里的 `f1.png … fN.png` **按切序上传**，第 k 张就是第 k 切的关键帧，
与提示词里的「图 k」一一对应（`export` 出的 `prompt.md` 头部已经把这张对照表写好了）。
逐镜写「参考图 k 的画面和构图」，秒数不写。

两条数量限制要留意：

- **官方推荐 4–5 个素材，并明说「不建议用满素材上限」**——过多素材会让模型难以判断特征
  优先级。一段切到 6 刀以上时，别把 6 张分镜图全挂上去：**只挂转场处的关键帧**（换景别、
  换机位、换人物的那几切），其余交给文字描述；或者把这一段再拆一次
- 「越需要精准参考的素材，放在提示词中越靠前的位置」——主分镜图 `f1` 排第一，这与本
  skill 的切序天然一致

**分镜图这一层顺带躲开了 seedance 的一个大坑。** 官方两处点名：人物 ID 漂移与「双胞胎」
问题的主因之一，是拿人物三视图 / 多视图当参考素材，「模型易将其识别为多个不同主体」。
`novel-characters` 落盘的 `<角色>-sheet.png` 正是三视图版面——本 skill 挂的是成片画幅的
单幅关键帧，不是那张设定图，天然不踩。**所以走 seedance 时不要「顺手把角色设定图也挂上
去」**，那等于把躲开的坑重新挖回来。真需要加强人脸一致性，就单独裁一张只有脸的大头照，
并在身份说明里写清：`图 5 是<主体2>的面部特写，用来锁定他的五官`。

## 五、动作、情绪、符号、收尾段

**动作四条**（与 `storyboard-pass.md` 的导演手感同向，更细一档）：肢体细化 + 程度量化
（缓慢抬手、用力蹬地）；优先低缓连续的小动作，规避狂奔大跳；补充前后动作的惯性承接；
情绪具象外化——不写「很悲伤」，写「低头、肩膀微微颤抖、手指攥紧衣角、泪水打转没有落下」。
喜悦是「嘴角抑制不住上扬、脚步变轻快」，紧张是「频繁看手表、手指敲桌面、眼神闪躲」，
愤怒是「双拳紧握、下颌线紧绷、从牙缝里挤出话语」，释然是「长长舒一口气、紧绷的肩膀
放松下来」。

**四种信息四种括号**：音乐 `（）`、音效 `<>`、台词 `{}`、字幕 `【】`。字幕的 `【】` 与
「保持无字幕」互斥，别同时写——短剧的字幕在剪辑期贴。小语种台词要标语种：
`用日语说道{こんにちは}`。

**一镜一种运镜**：官方明说不要在一个镜头里同时要求推拉摇移，会增加画面不稳定性。本 skill
的 `cut.camera` 是单选枚举，照着写就对。中文模式下词表的中文词（固定 / 推 / 跟拍……）是
词根，写成官方的完整术语更准：固定机位、缓慢推近、平稳跟拍——门查的是词根，包在完整术语
里照样通过。

**收尾段**：画质（高清、细节丰富、电影质感、光影柔和）+ 风格（跟 `production.json` 的
`style` 走，官方点名过「风格漂移」：参考图偏写实而提示词不强调风格时，动画风会漂成真人
写实）+ 约束词（`保持无字幕` / `不要生成 Logo` / `不要生成水印` / 禁双胞胎那句）。
收尾段写在 `环境声与配乐：` 之后，不进任何逐镜检查。
字幕**无法 100% 避免**，只能降低概率；横屏出字幕的概率明显低于竖屏，但短剧多是 9:16，
这条基本用不上。

## 六、下单时的两件事

**`duration` 照旧要折算**：seedance2.0 / fast / mini 的区间是 **4–15 秒**（2.5 是 4–30 秒），
跟本 skill 的段上限 15 秒对得上，但**下限比 H3 的 5 秒低一秒**——短段按下限下单，片尾多出
的部分剪辑时裁掉。跑 `novel-setup duration <秒> --model <名>` 折算。

**多段拼接**：官方把长内容分成两条路，本 skill 走的是后一条——

- **连续长镜头（视频延长）**：单一场景内的文戏，长对话、情绪递进、单一路径移动
- **分段拼接**：剧情转折与复杂快速的动作戏，独立生成再剪辑组合——**这就是本 skill：
  段不跨场、一段一次生成、剪辑不在 skill 范围内**

拼接处的官方修法（在剪辑软件里做，本 skill 不管这一步，但要知道它存在）：**前一段末尾
删 6 帧，后一段开头删 1 帧**，每个拼接点都这么做。官方还有一句更值得记住的建议：**续写
生成时以转场切镜的时刻结尾，下一段从切镜后的新场景起始**——这与本 skill「段不跨场」的
分段规则同向，按现有规则切段本来就落在这个形状上。

**不要拿模型产物反复续写**：官方点名视频延长会画质劣化，多次叠加尤其明显，人脸区域会
出现斑驳色块。本 skill 每段独立生成、互不续写，天然规避。

## 七、常见病

| 病 | 症状 | 治法 |
| --- | --- | --- |
| 半改病 | 改了 `video.model`，`videoPrompt` 还留着 `[Shot k] At 00:06.000,` 的时刻 | 秒数一个不留。留一个，模型就当整条都在钉时间——`prompt-structure` 门会点名到具体那一处 |
| 改坏台词 | 换骨架时顺手润色了一句台词 | 台词逐字照搬。它是与剧本对账的锚，改了就与 `script.json`、配音对齐单全脱钩 |
| 身份说明缺一句 | 段有 5 切，身份说明只写了 4 张图 | 一切一张图一句身份说明，门逐张对账，会点名缺的是哪一张 |
| 顺手挂设定图 | 分镜图之外又把角色 `-sheet.png` 挂进去 | 那是三视图，官方点名会加剧 ID 漂移与双胞胎——要加强人脸就单独裁大头照 |
| 素材堆满 | 一段 7 切就挂 7 张分镜图 | 官方明说不建议用满上限，只挂转场处的关键帧，或把段再拆一次 |
| 标签漂移 | 前一镜叫 `<主体2>`，后一镜改叫「那个老人」 | 标签一旦定下全程复用，这是官方点名的指代混乱主因 |
| 单字运镜撞车 | 「他推开舱门」与「镜头缓慢推近」在中文里都是「推」 | 运镜写成完整短语，人物动作换个说法，同一行里把主语分清 |
