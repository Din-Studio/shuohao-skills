# novel-video-prompt

`{baseDir}` 是本文件目录。Node 18+，只有标准库依赖。整个目录可以单独拷走：不读取其他 skill 的实现或指南，不依赖第三方 skill。

你是**编写方**。产物是工作单，不是 creation.json，也不是视频。审核由另一个独立的审核方完成；你不填写审核意见，不修改审核状态为 approved。

## 1. 确认拿到的材料

调度方（或用户）应当提供：

- 这一集的节拍底稿：每场的场景编号、在场人物、道具、逐拍的动作或台词原文与估时。
- 资产表：人物、场景、道具的编号与名称，以及哪些资产已有设定图。
- 项目要求 `creativeBrief`（可以没有）、有效视频模型、提示词语言、单段时长上限。
- 工作单目录。
- 修改轮次还会有：上一轮的审核意见（已写在工作单里）。

材料格式见 `examples/第七盏灯/输入材料.json`。缺少节拍底稿或视频模型时停止并说明缺少什么，不自行编造剧情、台词或资产编号。

## 2. 读取指南

按顺序完整读取：

1. `references/分镜指南.md`——怎样分段、认领节拍、安排景别与停留。
2. `references/worksheet.md`——工作单格式、分镜结构字段与两张枚举表。
3. `references/creation-prompt.md`——提示词骨架，跨模型通用。
4. 模型填法指南，由视频模型决定：

```bash
node {baseDir}/scripts/novel-video-prompt.mjs guide --model "seedance2.0"
```

MiniMax H3 读取 `references/h3-prompt.md`；seedance 系列读取 `references/seedance2-prompt.md`；其他模型没有填法指南，只照通用骨架写，并在回报中说明能力未核实。不要拿另一族的指南代替。

## 3. 编写

先确定这一集怎样分段，再逐段写。每段一份工作单：

```bash
node {baseDir}/scripts/novel-video-prompt.mjs new E01-01 --out <工作单目录> --model "MiniMax H3" --scene 1
```

在工作单里填写两处：

- 「分镜结构」的 json 代码块：`cuts`（节拍认领、秒数、景别、运镜、画内人物与道具）和 `images`（参考图挂载，数组顺序就是 Picture 序号）。
- 最后一条分隔线之下的提示词正文。正文里不能出现单独成行的 `---`。

硬性要求：每段不跨场次；全集节拍恰好被认领一次且顺序不倒退；台词逐字不改；段秒数之和不超过单段上限；每个 `[Shot k]` 行自带景别短语与运镜短语；身份说明句数量等于参考图数量。不为缩短时长删除证据、选择或结果，不新增剧本没有的事实。

## 4. 自查并提交

```bash
node {baseDir}/scripts/novel-video-prompt.mjs lint <工作单目录>/E01-*/prompt.md
node {baseDir}/scripts/novel-video-prompt.mjs submit <工作单目录>/E01-*/prompt.md
```

`submit` 先自查，全部通过才把状态改为 `in_review` 并把轮次加一；有一份不通过就一份都不提交。自查只覆盖不需要剧本就能确定的事。节拍覆盖、台词逐字、时长与参考图文件由调度方拿着剧本做完整结构检查；调度方退回的结构问题与审核意见同等对待，修正后再次提交。

## 5. 修改被退回的工作单

状态为 `changes_requested` 或 `blocked` 时（`blocked` 表示审核方登记了你无法单独解决的问题，调度方协调之后才会再次派发）：

1. 读「审核意见（仅本轮）」。每条 `[必须修改]` 都要处理；`[建议]` 自行判断，不采纳要说明理由；`[阻塞]` 按调度方给出的协调结果处理。
2. 修改分镜结构与提示词正文。不要改动审核意见区。回应里需要小标题时使用三级标题或加粗，不使用二级标题。
3. 在「编写回应（仅本轮）」逐条写明怎样处理。回应只保留本轮，覆盖上一轮内容。
4. 再次 `submit`。没有填写回应时提交会被拒绝。

不同意某条必须修改时，在回应里引用剧本节拍或项目要求说明依据，由审核方再次判断；不要悄悄忽略。意见要求改动剧本台词或新增事实时，说明这超出编写方权限，需要回到上游。

已经批准的工作单再被修改，批准自动失效，必须重新提交审核。批准还绑定这一段依据的输入（认领节拍的原文、参考图内容、模型与参数、项目要求）：调度方告知某段的批准因为输入变化而失效时，对照新的输入材料检查这一段，再次提交。

## 6. 回报

向调度方回报：写了哪些段、每段秒数与分镜数量、各工作单当前状态、没有采纳的建议及理由、自己发现但无权解决的问题（例如台词估时装不下、缺少设定图、模型没有填法指南）。不要把自查通过说成审核通过。

## 样例与自测

`examples/第七盏灯/` 是本 skill 自有样例：故事提案、输入材料，以及两份已提交审核的工作单（MiniMax H3，英文提示词）。先有故事，后有分镜。

```bash
node {baseDir}/scripts/selftest.mjs
```

本地确定性检查，不调用模型，不访问网络。
