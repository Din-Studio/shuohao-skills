# 分块读取与来源覆盖

短剧本直接读取。长剧本按已有集场边界与实际负载拆分；超长场次沿完整话轮或行动分开。工具行数分块只是候选，遇到跨行话轮要人工调整负责范围。不得使用“每批三集”或窗口大小证明读全。

## 操作

1. 保存不可覆盖的原件，确认确属剧本，而非小说或大纲。
2. source-document 读取原始字节生成相对路径、SHA256 和物理行数。不能仅凭剧名登记来源。
3. chunk --kind script --id 文档ID 生成 .work/source-chunks-<文档ID>.json，同一工作目录可以分别切多份文件。分界识别集场标题，允许 Markdown 标题前缀（如 `## 第3场`）。每块有 owned（负责范围）及 context（用于理解的相邻范围），含首尾行号；原行不裁剪、不改写。输出独占创建，已有文件不覆盖。
4. 阅读每一块；在 .work 中记录局部对象、事件、原句、疑问及实际负责范围。工具生成分块不代表人或模型已经读过。并行读取时，每批读取者写一份 fragment（合法的 v5 partial outline），见[分集并行派发](dispatch.md)。
5. 统一发布者核对 B/Q 稳定 ID，并集登记 coverage。并行读取时由 merge 确定性合并 fragment、全局重新编号，再经串联和核验后 publish。上下文重复不产生新事件；不同位置的同句仍是两次发生。按位置核对边界，无空隙、无重复丢失后才能声明所提供文档完整。
6. scope=complete 还需明确全剧总集数与实际 1..N。只拿到第 4、6 集，应登记 partial，不能补写第 5 集。

## 分集文件夹输入

每集一份 Markdown 时，先执行 `source-folder 剧本目录 --out outline/.work/sources.json`。只登记第一层 `.md` 文件，不递归，忽略隐藏文件。集号只从文件名解析（`第N集`、`EP N`、文件名开头的数字；N 可以是阿拉伯数字或中文数字），不按内容猜测；正文集标题与文件名不一致时报错。文档 ID 由集号决定（`D01`、`D112`）。缺集写进 missingEpisodes，不等于知道全剧总集数。

分集文件通常不需要再切块；某一集过长时，读取者在自己的批目录执行 `chunk --id`。一集只由一个读取者负责，不拆给两个读取者。

## 剧情描述与跨集状态

先记录出现位置和证据，不建立人物、地点或道具表。原文支持同名不同人时，写“修理师周宁”“来取件的学生周宁”及各自出处。别名、隐藏身份和尚未揭晓的说话者不在本阶段归并，未知就明确记录未知。

场次顺序不是地点资产身份。同一物品的交接、受损、恢复及闪回状态，以自然语言和有出处 notes 记录，不分配 C/S/P ID。人物分档、主场景、出图和复用由各自阶段处理。

客观事实与角色猜测、谎言、转述分开。只交接必要的前情、状态和揭晓禁区，不因后文出现姓名而提前泄露当时身份。未提供的动机、侧别和过渡保持未知，制作补定不能冒称原文事实。

## 核验边界与学习来源

来源核验读取原件并比对摘要和行号；内容审核仍需逐处对照事实、发声及授权。逐字证据与覆盖方法、原“剧本读取与记录／合并与正式交付”方法，以及长剧本连续性研究已内化于本指南；不需要第三方 skill，不在运行时读取学习材料或兄弟样例。不建设图数据库、全剧知情矩阵或失败日志。
