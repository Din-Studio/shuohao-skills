# 大纲创作指南

## 目标与职责边界

先确立故事，再建立重要事件，最后整理分集。大纲交付人物处境、因果、事件结果及资产交接，不提前写完整剧本、不设计镜头、不生成媒体。JSON 保存内容和稳定引用；本指南提供创作方法，不是可执行规则，也不以版本或摘要阻断作品。

## 从要求确认创作方向

阅读用户实际材料，区分明确要求、偏好与待确认判断。确认集数、分钟数、题材、原创或改编方式，以及希望读者获得什么体验。题材是作品描述，不自动决定结构。项目要求只在 production.creativeBrief 保存；独立创作可在大纲保存，接入项目时人工合并。

先以自然语言复述：关注谁、处境为何持续、人物如何选择、结束意味着什么。若用户希望“温暖但不强行和解”，不能机械套入圆满结局。未确认故事前不写分镜。自动驾驶只改变审批方式，不取消内容评审。

## 组织因果与人物

从触发事件到人物选择，再到实际后果，逐项查找缺环节。目标、阻力和代价直接写入 premise/throughline，不另建重复驱动对象。静态人物和单元配角可以没有变化弧，但行动仍应可理解。群像允许不同立场，不要求唯一胜利主角。

正例：合伙人拒绝掩盖亏损，公开账目后失去部分合作机会。
反例：只写“双方冲突升级”，没有新信息、选择或后果。
检查：人物为何此时行动？知道什么？有何替代选择？代价由谁承担？若人物始终不变，是否仍推动了他人的处境？

## 题材、情绪与节奏的选择空间

- 生活题材：劳动、照顾、交换和边界协商都可以成为事件。正例是夜班者参与调整值日约定；反例是普通邻里议题解决后突然加入陌生威胁。没有犯罪主题时，不必为了悬念虚构阴谋。
- 悬疑：区分人物和观众掌握的信息。证据应改变下一步调查。正例是编号跳号促使核对班次；反例是连续写“更加扑朔迷离”而无新事实。不要求每条线索分类或立即揭晓，但关键答案应由已建立的材料支持。
- 人物剧情：关注选择及其关系成本，而非胜负标签。反复争执只有产生新后果才值得登记多个重要事件。
- 强烈表达：逐步压缩可选方案，给观众理解后果的时间。证人撤回签字迫使负责人承担责任，比重复更换指责者更有推进。并非所有故事都需要连续反转。
- 克制表达：以行动和可理解的沉默承载感情。提前离开却替对方买好返程票，比抽象情绪标签更具体；但不能把省略动机误作克制。
- 温暖表达：互助回应具体需要，同时承认成本与拒绝权。邻居承诺两周接送并共同寻找长期方案，比一句道歉解决多年伤害更可信。若作品关注不可修复的损失，不强求和解。
- 高频结果：每次回报须回应真实期待并改变局面，不把同一证明被多人看见登记成多次兑现。理解成本过高时应留出消化结果的段落；不套用每集次数或固定间隔。
- 渐进累积：线索的获取、解释、修正支持后续揭示；没有兑现也可以有推进。反复“仍在寻找”却毫无变化不是慢热。
- 舒缓观察：允许劳动、日常与关系理解形成段落价值，不强制每集重大状态改变。共同修椅时重新协商分工比“大家相处很好”更具体。观察已有意义时，不必强加任务转折。

上述方法可以组合，也可能冲突。优先具体创作要求与当前故事；不以题材名称自动选定某套要求。

## 连续、单元与集尾

连续故事可跨集累积线索，也可在中途收束局部问题。单元故事以共同人物或议题联系，前集达成的约定不应无故重置。追更故事的集尾应来自尚未完成的真实行动，不必每集登记一个问题。

suspense、closure、open 描述实际停点，不限定题材。明确承诺回答的问题才登记 Q；required 必须有后续唯一解决节点，显式期限必须遵守；optional 可以保留余味，理由按需说明。不能删除未解决的 required 来伪造闭环。开放结局不是遗漏承诺的借口。

正例：本集核对完一人的行程并收束，结果改变下集对另一份记录的判断。
反例：前文承诺查明车辆去向，末集直接改成 open 并不再处理。
阶段规划仅适用于确有阶段目标的长篇；不强迫全剧覆盖或兑现终点。

## 改编与来源

阅读真实材料，说明覆盖范围与缺口。保留、砍掉、合并、风险各按实际决定记录，不为了填表虚构取舍。来源不完整时写 sourceNote；evidence 保持原语言逐字引用，不把摘要改成引文。人物涉及来源时保留 from；原创通常省略 adaptation 与 from。

正例：两个原作角色承担同一调查职能，合并后注明独有信息如何转交。
反例：未阅读原文便声称“删去冗余支线”。题材常识不能替代来源证据。
长篇材料的技术操作见分卷指南；摘要不能冒充全文覆盖。

## 骨架、节点与分集

骨架先建立处境、贯穿线索、结束意义、人物、场景及必要道具。确认方向后登记不能遗漏的事件：setup 是承接处境，outcome 是事件及后果。B ID 不为分类变化重新编号；同集按数组顺序。position/kind/weight 只在确有用途时提供。endingBeatId 明确全剧结束节点，不取数组最后一项替代其含义。

分集 synopsis 供人阅读，beats 供重要事件交接，两者不是互相替代。opening 描述实际开场处境，不意味着必须冷开场。每批建议不超过十集；明确此前状态、信息、时间与未解决承诺后再考虑并发。制作 warnings 提示困难，但人数不等于同框人数。

## 内容评审问题

每条意见引用集号、B/Q ID 或原文片段，区分事实、创作判断和未验证效果：

1. premise、throughline 与 ending 是否描述同一个故事？
2. 人物动机是否由材料支持？有没有靠巧合跳过选择？
3. 重要事件是否真实进入对应梗概？有没有重复登记同一结果？
4. 解决节点是否真正回答问题，而不只是引用 Q ID？
5. 本集提供了什么行动、信息或关系理解？是否把词语改写误作推进？
6. 跨批次时间、证据归属、人物状态与未解承诺是否连续？
7. 道具 function 是否有实际作用？场景同集关联不能证明事件落点。
8. 改编取舍、材料缺口、逐字证据是否诚实？是否夸大未读范围？

结构通过不证明故事成立。工具固定显示“内容评审未执行”；已经执行的人工或 Agent 评审在交付说明中链接本次工作记录，不新增永久评分或失败累积日志。

## 交接与修订

保持 C/S/P/B ID 稳定。删除事件前查下游认领，改变内容后检查认领正文是否仍真实表达结果。目标时长变化后重估剧本与镜头计划。explicit budget 是作者制作限制；工具参考值只提示。不要提前根据同集出现推断道具精确节点或人物同框。

项目要求变化后分别汇报“结构检查已完成”和“创作要求尚未重新评审”。完整下游验证仍由对应阶段执行；本地接口检查只检查实际引用、坐标和目标，不声明模型技术与媒体交接全部通过。
