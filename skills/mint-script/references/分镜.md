# 分镜

## 任务

剧本 JSON 确定之后，为它编写分镜文件 `<剧本名>-storyboard.md`。分镜按叙事和表演把每一场划分为视频段，确定段数、各段包含的完整剧本节拍以及段间如何衔接。它是交给用户阅读的文档，也是制作阶段（mint-creation）分段、编写视频提示词和审核的依据。

这里的「段」是用于视频生成的叙事单元。段内切镜和运镜由视频模型决定，分镜不写镜号、景别或运镜。分镜不改动剧本：台词、动作、场次和揭晓顺序都以剧本 JSON 为准；需要改剧本时先改 JSON，再重新生成受影响的「本段剧本」。

## 生成骨架

```bash
node {baseDir}/scripts/mint-script.mjs storyboard 作品-script.json --limit 15 > 作品-script-storyboard.md
```

骨架为每一场生成一段，覆盖整场，并写好「本段剧本」。字段全部留空，检查不会通过；作者按下文拆段并填写。单段上限取有效视频模型一次生成的上限（MiniMax H3 与制作阶段的默认值都是 15 秒），不要沿用其他工作流的 30 秒。

## 拆段规则

1. 通读整场，找出人物的目标、情节的关键变化，以及观众何时得知每条关键信息。把需要连起来看的动作、对白、反应和结果先组织在同一段。每段可以包含多个相连的事件。
2. 按自然表演节奏估算对白、动作、必要停顿和段首复写所占的时间。对白与动作同时发生时，共用的时间只算一次。超出单段上限时，优先在一个结果已经看清、下一步行动尚未开始的位置拆开。长对白或连续动作必须跨段时，选语意完整的停顿或动作阶段的交界，写清下一段从哪里继续。拆开后逐段复核。工具按剧本估时口径检查：台词估时之和超过上限必然无法容纳，直接阻断；包含动作的整段粗估超过上限只提醒，因为同时发生的部分可以只算一次。
3. 逐对检查相邻段。先看前一段的行动是否还在继续、后果是否在下一段才出现，或人物情绪是否在两段之间连续发展。地点、时间或说话人变化时，也按这一条判断。内容需要连起来看时，满足以下两个条件就合并：合并后符合时长上限；观众仍能辨认时空变化、看清情绪转折，并按剧本安排感受悬念和得知关键信息。短段能独立承担明确的叙事作用时可以保留。定下段界后，再填写总段数和每段推动的变化。
4. 一段只属于一场，不跨场次；同一场的节拍按顺序恰好归属一段。段号按集内顺序连号，例如第 1 集依次为 E01-01、E01-02，跨场继续编号。制作阶段的段号与分镜一一对应。
5. 收到审核意见后，调整受影响的段。段界改变时，同步更新分段表、段号、相邻段的状态与复写，以及受影响的字幕和声音。

## 段间衔接

1. 「段首状态」直接写出本段开场时已经成立的情况，使本段可以独立使用。「段尾状态」写本段最后一个事件结束后留下的情况。只记录影响本段或后续剧情的时空、位置、朝向、目光、姿态、接触、道具归属与持物手、伤势和未完成动作。位置和朝向通过现场可见的人、物或结构定位；左右以角色自身为准。按剧本、场次 notes 和已确认的前情填写，补足动作成立所需的细节，并与已有资产及前后动作一致。状态由剧情中的事件改变。
2. 只有剪辑需要两段都生成同一小截连续动作时，才安排复写。从上一段末尾选最短且可辨认的片段，写清从哪个动作开始、到什么状态结束。把同一文字填入上一段的「供下一段复写的内容」和下一段的「段首复写」，两处逐字相同。有复写时，下一段的「段首状态」写复写开始那一刻的情况，复写完成后才进入「本段剧本」。成片择一使用。仅需接续动作结果时，复写字段留空，在下一段「段首状态」写明仍然成立的结果。
3. 复写只包含动作，不包含台词。台词跨段延续由制作阶段的 audioRefs 表达，同一次发声不重播。复写只在同一场的相邻段之间安排：场内第一段的「段首复写」与最后一段的「供下一段复写的内容」留空。复写时间计入下一段时长，所以要短。
4. 同场内换时空、进入回忆或转入另一条叙事线时，分别记录离开的时空和进入的时空各自的状态。回到原时间线时，从离开时的状态继续，并计入剧本明确发生的变化。

## 逐段填写

- **本段推进**写在分段表里：这一段带来的具体变化，不只写「关系发生改变」。
- **本段剧本**由 storyboard 命令从剧本 JSON 生成：一拍一行，行首是场内拍号，动作以 △ 开头，台词写局部人物标记、发声方式（画外、旁白、内心）与表演说明，字幕与声音分别标注。不手工改写这一块；剧本改动后重新生成，工具逐字核对，各段按顺序拼回应与本场正文一致。补写的状态与复写内容分别填入对应字段。
- **必须呈现的信息**只写观众必须看见或听见的事实，以及决定理解的因果、反应和揭晓顺序。有先后要求时，写清哪件事发生后观众才能得知什么。依据来自剧本节拍、事件认领、场次 notes 中的限制，以及开场与集尾计划。
- **人物说明、场景说明、故事理解**用于后期字幕。触发时填写「标注文案｜出现时机」。人物说明写当时可公开的身份和姓名，放在人物清楚出现或开始说话时；尚未揭晓的身份不能提前标注。场景说明使用剧本中的地点或时空称谓，放在场景可辨认时。首次、隔集等跨集标注沿用已确认的标注结论。本场剧本明确的时空变化可据实填写。故事理解在时空跳转、并行叙事或画外关键信息确实需要解释时，使用一句话帮助观众理解，按剧情揭晓时机安排。未触发的字段留空。
- **环境音、音效、背景音乐**每段必填。优先遵循剧本 sound 节拍、notes 或用户明确的声音安排，其余根据本段的场景、动作和情节判断。某项没有合适内容时填「无」。
  - **环境音**写在该场景中自然持续或反复出现的声音。需要跨段延续或随场景变化时，写清延续、变化或停止的位置。
  - **音效**写由具体动作或事件触发的声音，并标明在哪个动作或事件发生时响起。
  - **背景音乐**写适合本段情节的音乐类型或情绪风格，并写明从哪个剧情节点进入、到哪个剧情节点退出。贯穿本段或跨段延续时，写清从段首进入、延续自上一段、持续至段尾或延续到下一段等实际安排。若一段内有多处配乐，逐处写明类型和起止。背景音乐和字幕交由后期处理，生成视频本身不带配乐和字幕。
- **台词对照**只填写「本段剧本」中实际发声语言与中文原句不同、且已有定稿译文的台词。按原顺序逐条填写「说话人｜语言及地区｜中文原句｜实际发声台词」。实际发声台词就是剧本 line；中文原句经 sourceRefs 回查原件；语言及地区来自 transformation.reason 或 notes。无需翻译或缺少定稿译文时留空。

## 文件格式

文件是 Markdown，标题、字段名和顺序固定，便于工具解析。除「本段剧本」外，每个字段占一行；需要分条时在下一行以两个空格缩进续写。不适用的可选字段保留名称并留空。影响叙事理解、拆段或连续性的具体问题写入文件头或该场的「待确认事项」。

````markdown
# 分镜 · 作品名

- 剧本：作品-script.json
- 单段上限：15 秒
- 待确认事项：

## 第 1 集 第 1 场

- 集号：1
- 场号：1
- 总段数：2
- 待确认事项：

| 段号 | 节拍 | 本段推进 |
| --- | --- | --- |
| E01-01 | 1–3 | 本段带来的具体变化 |
| E01-02 | 4–7 | 本段带来的具体变化 |

### E01-01

#### 本段剧本

```text
[1] △ 动作
[2] C01：台词
[3] C02（画外）：台词
```

#### 分镜说明

- 段首状态：
- 段首复写：
- 必须呈现的信息：
- 段尾状态：
- 供下一段复写的内容：
- 人物说明：
- 场景说明：
- 故事理解：
- 环境音：
- 音效：
- 背景音乐：
- 台词对照：
````

## 检查与审核

`validate`/`checkup` 自动读取剧本 JSON 旁边的分镜文件（或 `--storyboard FILE`）并检查：场次覆盖、段号连号、节拍恰好归属一次、本段剧本逐字一致、总段数与分段表、字段名与顺序、必填字段、占位符、复写配对与不含台词、台词估时与单段上限。`--production-ready` 要求分镜存在。检查通过不代表分镜写得好；分镜写完后在独立上下文按 [分镜审核](分镜审核.md) 审核，结论写入当前工作记录。

## 学习来源

内化自用户提供的 storyboard-video「分镜」规则。按本仓库的数据契约调整：段与剧本节拍对账、单段上限取有效视频模型、复写不含台词并改由 audioRefs 延续发声、段号与制作阶段一一对应、文件与剧本 JSON 同目录。运行不依赖原 skill 或临时目录。
