# 骨架：先确定作品承诺

1. 阅读实际材料和四份选定策略指南。先说明故事处境、关注人物、贯穿线索、观众期待与结束意义。没有确认故事之前不写节点，更不写分镜。
2. 改编取舍记录到 adaptation.keep/cut/merge/risks。每项说清理由，关键决定附可核对的逐字 evidence；来源不足写 sourceNote。原创允许空 cut/merge，不伪造原文。
3. 角色保留稳定 C ID、分档与 from；from 记录来源，不替代 adaptation.merge 的取舍理由。功能角色可无变化弧，群像无需固定胜利主角。
4. 场景与道具按实际叙事需要登记。预算只读 params.thresholds；缺项按报告列出的制作预算默认值。一次性场景允许没有 reusePlan。道具 function 描述其叙事作用，beatIds 可关联任意 kind。
5. 写完上述骨架先运行 skeleton。确认方向后建立重要事件，按 event/pressure/turn/payoff 如实分类；payoff 才填写 minor/major。不能为了数量把铺垫、施压和同一结果拆成多份兑现。
6. 节点写 setup/outcome、所属集、粗位置，按发生顺序排列。story.endingBeatId 必须指向最终集节点，不要求 payoff。可选 arcs 管理不重叠阶段及其终点，不默认全覆盖。
7. 运行 beats，确认作品承诺、改编取舍、节点与结束位置，再开始分集。快版与细版都检查；自动驾驶自行审批但明确记录理由。

内容审查关心因果、行动选择和结果，不把字段齐全当成质量保证。单元故事可以由共同人物和议题贯穿。慢热允许延迟揭示，但每次信息应有实际影响。
