# 大纲通用内容评审

本地方法来源：本仓库创作策略解耦设计及既有改编实践；无第三方 skill 运行依赖。本指南不声称经过真实投放验证。

## 必须引用证据

每条意见引用 ep、B ID、Q ID 或原文片段。区分已知事实、创作判断与尚未验证的表现效果。评审材料放当前 .work，不记录永久总分、爆款概率或失败历史。

1. 材料来源是否可靠？关键 keep/cut/merge 是否有实际依据？原创是否明确标注？摘要是否隐瞒未读范围？
2. 人物为何作出选择？事件与后果之间是否缺环节？贯穿线索与结束意义是否一致？
3. opening/synopsis/ending 是否描述实际事件而非情绪标签？B 节点是否真的发生，是否重复登记同一结果？
4. required 的解决节点是否真正回答对应 Q？optional 的理由是否作品边界而非遗漏借口？
5. stateChange 的差异是否实质认知、关系或处境改变，而不是改写词语？
6. 批次之间的角色状态、证据归属、时间和未解决承诺是否连续？
7. 道具 function 与节点有何实际关联？场景同集出现只是统计关联，不证明节点在该场景发生。
8. 若有下游，认领文本是否表达节点 setup/outcome？时长目标变化是否重估？最终开放或收束是否被错误改成追更悬念？

## 策略特定评审

必须另读本次四份 guide。密集兑现防重复计数；渐进累积防空转；舒缓生活防无选择的流水账。慢热不意味着不能有兑现，单元不意味着不能有贯穿线索。自然语言指南之间的冲突不能由参数合并器保证消除。

报告内置状态始终为“内容评审未执行”，因为渲染器不能读取或推断会话评审。若人工或模型已评审，在交付说明中链接本次评审材料并明确范围，不改写原始 JSON 冒充自动通过。
