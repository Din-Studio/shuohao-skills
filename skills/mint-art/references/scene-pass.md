# 场景设定 · 怎么填

先独立阅读原剧本，人工或模型确认地点身份和美术资产取舍；seed 不识别地点。只有任务需要设计、designStatus 为 planned/ready 时，才根据本阶段身份及原件证据产出完整场景设定。登记身份而不设计时不执行本页设计要求。**只输出 JSON，不要解释、不要围栏。**结构见 `schema.md`；全局原则见 [principles.md](principles.md)，术语见 [glossary.md](glossary.md)。

## 先识别：什么是一个场景

- **场景是空间**，连同那里的天气和现场效果（雨、雪、雾、烟、火）。天气和现场效果写进光照状态或变体，不另建资产。
- 场次不是地点身份。同一空间的晨晚、闪回、清空状态不自动建立新地点。
- **场景变体只在两种情况下拆**：光的状态持续变了（开灯、关灯、天色变化），或空间状态变了（清空、破损、布置）。人物情绪和剧情时刻不改变光，也不构成变体。
- 有题材时，先判断这个场景的每一场落在题材分区表的哪个区（`genres/` 里对应的题材文件，判据是分区名和「用在」那一行）。落在不同区、剧本写出了天色、主光或空间状态差别的，拆成不同光照状态或变体；剧本没写出差别的，合成一个。
- 只需要文字约束的光照差别留在 `lighting` 的后几个状态里；需要单独出图的变体建成 `variantOf` 加 `changes` 的变体场景。

## 先想清楚：这是 AI 短剧，不是实拍

场景不是「找个地方拍」，是**要被生成几十次还得长一样的环境资产**。实拍时场地本身替你保证了所有没写下来的东西——门在哪、光从哪来、机位站多高；AI 这边**没写下来的每一样都会每次重新猜**。你写的每个字段都在为一致性服务：

| 字段 | 它在解决什么 |
| --- | --- |
| `summary` 里的结构骨架 | 切镜头时门还在不在左边、桌子还在不在窗边——AI 没有场地，空间关系只能靠文字写死 |
| 锚点 | 观众靠什么认出「又回到这里了」；QC 靠什么判断生成的镜头没漂 |
| 锚点里的方位 | 3–5 个带方位的锚点连起来就是一张文字版平面布局图，分镜写反打、写走位都引用它 |
| 光照状态 | 换时段 = 换提示词重新生成，不是现场重新打灯；主光方位定了，角色进场才不像贴上去的 |
| 设定图的四宫格和平面图 | 四个方向都画出来，反打和切到人物背后时背景不用现编；平面图交代东西在哪 |
| 空景 | 人是另一层资产（mint-characters 负责），环境参考图里有人，一致性全毁 |

## 硬规则

1. **`summary` 写设计意图，不写户型说明。**「小到人与人躲不开视线的审讯室」是设计意图；「约十平米，六排坐板」只是测量数据。空间要为戏服务，先说它为哪场戏存在。

2. **`summary` 末尾补一句「结构骨架」：分区 + 动线 + 主光方位 + 实际大小。**一句话说清：入口在哪边、主要家具与结构件的相对位置、人从哪走到哪、主光从哪个方向进来、空间大约多大（「约长 6 米、宽 4.5 米」，剧本限定了就标「估」，见 [principles.md](principles.md)）。

   例：「入口在菜摊左侧通道，台面沿后缘横向展开，挂钩在左立柱，主光从右侧透明棚板漫射进来，人物从通道走到台面前；棚下约长 4 米、进深 2.5 米。」

   这句是这个场景所有镜头的公共底稿。它的空间关系还要在 `image.sheet` 里按四个方向落成英文（每个方向看得见什么），实际大小作为比例描述写进去，不画成文字。

3. **空间默认方正。**剧本没有特别说明时，空间写成方正的长方形或正方形——墙面平直、转角成直角、地面平整，画面不畸变。用正面的句子写：`the whole space is a regular rectangle, walls straight, corners square, floor level`。剧本写明了圆形大厅、山洞、船舱、异形建筑的照剧本写。

4. **功能性元素一个都别漏。**写之前先把剧本和资产清单扫一遍，下面四类都要落进 `image.sheet`，各自出现在它该在的方向格里，在平面图上位置对得上：
   1. **人物交互锚点**：剧本写了人物靠在、被绑在、推向、拉开、触碰、走向、打开、关上的东西（门框、栏杆、窗台）。
   2. **路径关键物**：人物移动路线上的参照物（走廊尽头的窗、楼梯口的座钟、大厅中央的吊灯）。
   3. **剧情驱动设施**：可能推动剧情的设施（监控摄像头、饮水机、打印机）。
   4. **光源物体**：设定图里会画出来的光源，就是这个状态的主光和局部光的灯具。不只写「有光」，写出光从哪个物体来（吊灯、壁炉、落地灯、窗、蜡烛）。

5. **锚点要「可画、可认、可核对」，`desc` 必须带方位。**锚点仍是 3–5 个（validate 查），从功能性元素和关键生活痕迹里挑最能认出这个空间的几个。好锚点：棚沿水痕、左立柱弯钩、右端补板——生成图里一眼找得到，缺了立刻发现。坏锚点：「陈旧的氛围」「岁月的痕迹」——没法核对的不是锚点是形容词。`desc` 写清它在空间里的位置（「雨棚右沿」「左立柱上方」「台面右端」），方位按场景自己的前后左右。

6. **光照状态写光影锁，不是氛围色调。**按 [scene-lighting.md](scene-lighting.md) 选光、命名、写句子。每条 `lighting.prompt` 交代：主光源的物理来源与方向、光质（硬光或柔光）、色温数值（如 `about 6500K`，lighting-kelvin 门查）、它落在空间的哪些表面上、暗部保留什么。

   坏：`cold moody light, cinematic atmosphere`——氛围词，模型每次都能编出不同的打光。
   好：`The light comes mainly from the single window on the left wall, entering as hard late-afternoon sun at about 3000K, lighting a shaft across the floorboards; the unlit right half of the room stays dim but the cabinet outlines remain readable.`

   为什么较真到方向：下游要把角色放进这个空间，角色的受光方向跟环境对不上，人就像后期贴进背景的。**基准设定图画 `lighting[0]`**；状态从剧本反推，用不上的状态不写。

7. **窗外、门外看得见什么要定下来，全剧一致。**剧本没写的照 [principles.md](principles.md) 第一节设计一个具体、平常的窗外景，写进基准，所有变体照抄，否则每段视频换一个窗外景。

8. **机位是普通人拍得出来的高度。**设定图的四宫格固定是空间中央、平视高度。`image.prompt`（单张空景）也写明取景高度（`eye-level framing`）。贴地超低机位、极端俯拍交代的空间信息跟后面绝大多数镜头对不上。

9. **要生活痕迹，不要样板间。**空景是「没有人」，不是「没人在这儿生活过」。写进提示词的是使用痕迹：褶皱的坐垫、喝到一半的水、翻开扣在桌上的书、磨白的木纹、水渍、包浆。判据是**「像有人刚离开不久」**；但默认世界是完整的、有人照料的，破损和脏污要有剧情原因（见 `genres/general.md`）。**关键痕迹要固定成锚点**，否则每张图都会重新编一套痕迹出来。反向边界也要写死：不要样板间与展厅感，不要为了气氛把景做成恐怖片夸张布景，不要把日常空间升格成非日常规格。

10. **提示词永远英文，永远空景。**`image.sheet` 的版式段写明 `No people anywhere in the image`，`negativePrompt` 必须禁人。**绝不出现角色名、作者名、作品名**——图像模型会把它认识的东西画进去。

11. **画风整套取用。**跑 `node scripts/mint-art.mjs style` 拿这部剧的 `style.scene`，`image.sheet` 与 `image.prompt` 的 `Overall style:` 段带上渲染句原文，`negative` 的每一条进 `negativePrompt`，不要混搭两种画风。不要把角色那一块的表面处理（毛孔、皮下散射）带进来。

12. **按实际空间关系决定是否复用。**每多一个独立环境就多一份一致性维护。需要独立视觉变体的场景，用 `variantOf` + `changes` 挂到母场景上；一次性独立场景不需要复用方案，不为检查伪造变体。变体的结构骨架跟着母场景走——`changes` 只写改动，平面图不动，换了入口和动线就不是变体是新景。变体的 `image.sheet` 按 [sheet-prompt.md](sheet-prompt.md) 第三节四块写。

13. **题材只给视觉取向，不给事实。**有题材信息时查 `genres/` 里适用的文件取光照基线、色板、材质；剧本事实和用户要求优先，题材文件里列的典型场景不是要补齐的清单。

## 脚本查不了的几条，交之前自己过一遍

validate 查的是数量、语言、禁词、画风、版式短语、色温数值这类能确定性判定的东西。下面几条只有你能保证：

- `summary` 末尾有没有那句结构骨架，`image.sheet` 四个方向的英文描述和它对得上
- 四类功能性元素是不是都写进了 sheet，各在该在的方向
- 每个锚点的 `desc` 有没有方位
- 每条 `lighting.prompt` 有没有说清主光从哪来、什么光质、落在哪
- 窗外景定下来了，变体照抄了
- `negativePrompt` 有没有挡住样板间

## 输入格式

```
画风（production.json 的 style.scene，整块原样取用）：
  render: …
  surface: …
  negative: …
  tags: […]
题材：（有就写，对应 genres/ 里的文件）
Scene: S01 菜摊雨棚（主场景）
出现集：1–3　显式关联节点：有证据才填写，不按同集出现推断

原件来源及本阶段独立核验的空间事实：
- ……
- ……

同批其他场景：S02 公共水池、S03 雨棚清空状态
```

同批其他场景要知道名字——空间气质要能区分开，别把每个景都写成同一种「破旧」。

**学习来源**：规则 2、5 的方位要求内化自刺猬星球《【提示词创作第六十七节】AI资产怎么做，画面才稳定？》第五章「场景资产：不要只给AI一张好看的空间图」；规则 8、9 内化自《【提示词创作第七十九节】为什么AI人物总有「假人感」？》第三章「场景不要只追求漂亮，要符合真实拍摄逻辑」。原文第五章的解法是多角度图 + 平面布局图；本 skill 的设定图采用四方向宫格加正交平面图（版面见 `sheet.md`），并保留带方位的锚点表与结构骨架句作为文字约束。场景的识别口径、空间默认方正（规则 3）、功能性元素四类（规则 4）、窗外景全剧一致（规则 7）与变体只改光影锁和空间状态（规则 12）内化自短剧资产图片提示词 skill（assets）的《术语》《场景》。

## 创作背景边界

先读 [creative-background.md](creative-background.md)。creativeBrief 仅作为项目自然语言要求，不推导规则。视觉正文必须来自 production.style.scene。outline v5 只提供故事背景，不提供场景或道具身份；节点无需分类。只保留有依据的 beatIds 引用，不凭同集出现推断精确节点归属。正式样例先确定《雨棚留言》故事提案，再设计资产；没有分镜或真实图片。
