# 场景设定 · 怎么填

给你一个场景的骨架（seed 预填了 id/名称/主场景标记/出现集/关联剧情节点）+ 原文或大纲里关于这个空间的全部信息，产出完整的场景设定。**只输出 JSON，不要解释、不要围栏。**结构见 `schema.md`。

## 先想清楚：这是 AI 短剧，不是实拍

场景不是「找个地方拍」，是**要被生成几十次还得长一样的环境资产**。实拍时场地本身替你保证了所有没写下来的东西——门在哪、光从哪来、机位站多高；AI 这边**没写下来的每一样都会每次重新猜**。你写的每个字段都在为一致性服务：

| 字段 | 它在解决什么 |
| --- | --- |
| `summary` 里的结构骨架 | 切镜头时门还在不在左边、桌子还在不在窗边——AI 没有场地，空间关系只能靠文字写死 |
| 锚点 | 观众靠什么认出「又回到这里了」；QC 靠什么判断生成的镜头没漂 |
| 锚点里的方位 | 3–5 个带方位的锚点连起来就是一张文字版平面布局图，分镜写反打、写走位都引它 |
| 光照状态 | 换时段 = 换提示词重新生成，不是现场重新打灯；主光方位定了，角色进场才不像贴上去的 |
| 空景 | 人是另一层资产（mint-characters 管），环境参考图里有人，一致性全毁 |

## 硬规则

1. **`summary` 写设计意图，不写户型说明。**「小到人与人躲不开视线的审讯室」是设计意图；「约十平米，六排坐板」只是测量数据。空间要为戏服务，先说它为哪场戏存在。

2. **`summary` 末尾补一句「结构骨架」：分区 + 动线 + 主光方位。**一句话说清：入口在哪边、主要家具与结构件的相对位置、人从哪走到哪、主光从哪个方向进来。

   例：「入口在菜摊左侧通道，台面沿后缘横向展开，挂钩在左立柱，主光从右侧透明棚板漫射进来，人物从通道走到台面前。」

   这句是这个场景所有镜头的公共底稿——下游写第二个机位时，靠它知道反打过去会看到什么。它的空间关系还要在 `image.prompt` 里有对应的英文表述（门窗与主家具的相对位置），别只活在中文里。

3. **锚点要「可画、可认、可核对」，`desc` 必须带方位。**好锚点：棚沿水痕、左立柱弯钩、右端补板——生成图里一眼找得到，缺了立刻发现。坏锚点：「陈旧的氛围」「岁月的痕迹」——没法核对的不是锚点是形容词。

   每个锚点 `name` 短到能进核对表；`desc` 除了特征还要写清它在空间里的位置（「雨棚右沿」「左立柱上方」「台面右端」）。带方位的锚点表才核对得了「门是不是还在左边」，不带方位就只能核对「这块补丁还在不在」。

4. **光照状态要写清光是从哪来的，不是只写氛围色调。**每条 `lighting.prompt` 至少交代四件事：主光源的物理来源与方向、光质（硬光/漫射）、色温、它落在空间的哪些表面上。

   坏：`cold moody light, cinematic atmosphere`——氛围词，模型每次都能编出不同的打光。
   好：`late-afternoon sun entering low through the single window on the left wall, hard directional shaft across the floorboards, warm falloff into the unlit right half of the room`。

   为什么较真到方向：下游要把角色放进这个空间，角色的受光方向跟环境对不上，人就像后期贴进背景的——这是「假人感」最常见的来源之一。光还要**允许有缺陷**（阴影、逆光、窗框投影、光柱里的浮尘），均匀布光是渲染感的另一半根源，见 `realism.md` 第 2 节。

   状态**从分集反推**：这个场景在出现的那些集里经历了什么时段和天气，就写哪些状态。别凭空写一套「白天/夜晚/黄昏」全家桶——用不上的状态是维护负担。

5. **机位要是普通人拍得出来的高度。**`image.prompt` 里写明取景高度（`eye-level framing` / `chest-height handheld camera position`）。贴地超低机位、极端俯拍这类摄影作品机位能出好看的参考图，但它交代的空间信息跟后面绝大多数镜头对不上，反而更容易漂。真为某个特殊机位存在的场景另说，那就在 `summary` 里说清楚为什么。

6. **要生活痕迹，不要样板间。**空景是「没有人」，不是「没人在这儿生活过」。样板间式的干净是 AI 环境图的默认失败模式：家具摆得规整、桌面空着、每样东西都在最舒服的位置——一眼假。

   写进提示词的是使用痕迹：褶皱的坐垫、喝到一半的水、翻开扣在桌上的书、还插着的线、磨白的木纹、水渍、包浆。判据是**「像有人刚离开不久」**。怎么写才不落回形容词，见 `realism.md` 第 1、3 节——**关键痕迹还要固定成锚点**，否则每张图都会重新编一套痕迹出来。

   反向边界也要写死：不要样板间与展厅感（`showroom interior, staged furniture display, catalogue photography, unnaturally tidy`），不要为了气氛把景做成恐怖片夸张布景，不要把日常空间升格成非日常规格（社区球馆不是大赛场馆）。画风的 `negative` 里已经有同类条目就不重复。

7. **提示词永远英文，永远空景。**`image.prompt` 里明写 empty scene / no people，`negativePrompt` 必须禁人。**绝不出现角色名、作者名、作品名**——图像模型会把它认识的东西画进去。

8. **画风整套取用。**跑 `node scripts/mint-art.mjs style` 拿这部剧的 `style.scene`（`render` / `surface` / `negative` / `tags`），`image.sheet` 与 `image.prompt` 里整段带上渲染句和表面处理句，`negative` 的每一条进 `negativePrompt`，不要混搭两种画风。

9. **按实际空间关系决定是否复用。**AI 生成一个新环境很便宜，但**每多一个独立环境就多一份一致性维护**。outline 里带复用方案的场景（seedNote 会提示），用 `variantOf` + `changes` 挂到母场景上：改时段、换天气、换前景、删道具，挂钩、台面等细节可以复用。一次性独立场景没有 reusePlan 合法，不为检查伪造变体。变体的结构骨架跟着母场景走——`changes` 只写改动，别把入口和动线也换了，换了就不是变体是新景。

10. **不要把角色 skill 的表面处理带进来。**毛孔、皮下散射是皮肤的事——那是 `style.character` 那一块。环境用 `style.scene` 那一块（写实那一档的真实感来自**用旧的材质**：掉漆、水渍、包浆、磨白的木纹）。两块是同一个画风的两种落地，别互相搬。

## 脚本查不了的四条，交之前自己过一遍

`validate` 的 确定性检查查的是数量、语言、禁词、画风这类能确定性判定的东西。下面四条只有你能保证：

- `summary` 末尾有没有那句结构骨架（分区 + 动线 + 主光方位），`image.prompt` 里有没有对应的英文空间关系
- 每个锚点的 `desc` 有没有方位
- 每条 `lighting.prompt` 有没有说清主光从哪来、什么光质、落在哪
- `image.prompt` 有没有机位高度和生活痕迹，`negativePrompt` 有没有挡住样板间

## 输入格式

```
画风（production.json 的 style.scene，整块原样取用）：
  render: …
  surface: …
  negative: …
  tags: […]
Scene: S01 菜摊雨棚（主场景）
出现集：1–3　关联剧情节点：清理、核对、归还

原文/大纲里关于这个空间的信息：
- ……
- ……

同批其他场景：S02 公共水池、S03 雨棚清空状态
```

同批其他场景要知道名字——空间气质要能区分开，别把每个景都写成同一种「破旧」。

---

**学习来源**：规则 2、3 的方位要求内化自刺猬星球《【提示词创作第六十七节】AI资产怎么做，画面才稳定？》第五章「场景资产：不要只给AI一张好看的空间图」；规则 4、5、6 内化自《【提示词创作第七十九节】为什么AI人物总有「假人感」？》第三章「场景不要只追求漂亮，要符合真实拍摄逻辑」。原文第五章的解法是九宫格多角度图 + 平面布局图，本 skill 的资产形态是一张 L 形设定图（版面见 `sheet.md`）+ 一份文字资产，所以把「平面布局图」这件事落成带方位的锚点表与结构骨架句——下游视频创作需要明确的空间文字约束，不能只靠一张平面图推断。

## 创作背景边界

先读 [creative-background.md](creative-background.md)。creativeBrief 仅作为项目自然语言要求，不推导规则。视觉正文必须来自 production.style.scene。节点无需分类；道具只保留显式 beatIds 引用，节点结果用于阅读，不凭同集出现推断精确节点归属。正式样例先确定《雨棚留言》故事提案，再设计资产；没有分镜或真实图片。
