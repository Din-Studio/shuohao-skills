# 道具设定 · 怎么填

独立阅读原剧本的物品线索，先**选择**再**登记**，需要视觉设计时再填写设计字段。seed 不自动理解物品；designStatus: none 不执行本页设计要求。**只输出 JSON，不要解释、不要围栏。**结构见 `schema.md` 的 props 段。

## 先选择：什么配当叙事道具

是否需要特写连续性、跨集复现或承载剧情，可以作为建立美术资产的制作依据，不要求三个条件同时满足。口头提及不自动建立资产；背景陈设也不自动成为道具。记录 decision 与来源，无法判断时保持待确认。3–8 件只是参考，不是最低数量或隐式硬预算；明确预算保存在 art.budgets。

| 类型 | 归属 | 例子 |
| --- | --- | --- |
| **叙事道具** | 入选，单独建资产 | 旧留言板（代存与归还）、夹纸铁盒（核对归属） |
| 场景陈设 | 场景锚点已覆盖，不入选 | 挂钩、棚板、排水槽 |
| 一次性手部道具 | 按实际连续性需要决定，通常不独立建立资产 | 一碗茶、一份报纸 |

拿不准就问一句：这件东西被镜头怼着拍过吗？观众记得住它吗？剧情少了它转不动吗？三个都不是就不入选。

## 硬规则

1. **`summary` 写戏剧功能，不写商品描述。**「需要归还给邻居的私人留言记录」是戏剧功能；「棕色牛皮材质」只是材质。先说它在剧里干什么。

2. **锚点要经得起特写。**道具的锚点比场景的更小更细：绿色边框的掉漆位置、铁盒角上的凹痕。特写镜头会把这些放大到全屏，**缺了立刻穿帮，多了核对不过来**——照旧 3–5 个。

3. **状态变体从剧情反推。**留言板有夹纸/取纸，铁盒有合上/打开——道具的状态弧跟着剧情走，需要设计时每个状态一条英文提示词；是否单独生成参考由实际任务决定。没有状态变化的道具写一个主状态即可。

4. **尺度必须写死。**`scale` 三档（手持级/桌面级/家具级），`image.prompt` 和 `image.sheet` 里**必须出现对应英文短语**（handheld scale / tabletop scale / furniture scale）——AI 把手持道具画成家具尺寸是高频事故，validate 会对着查。

5. **白底、无人、无手。**道具参考图要被贴进各种镜头，必须纯白背景可抠；**拿着道具的手是最常见的污染**，反向提示词必须禁 hands/fingers。validate 三样都查。

6. **关联要挂上。**`relatedScenes` 挂它主要出现的场景（id 必须存在），`carrierRefs` 明确引用 characters 已确认的 C ID、依据和 sourceRefs，不能使用自由名称猜测身份。这两样进报告，是排生成任务时查「这场戏桌上该有什么」的索引。

7. **提示词永远英文，绝不出现角色名**——图像模型会把它认识的名字画进去。画风整段取用 `style.scene` 的渲染句（与场景同一套）。

8. **磨损要指名道姓。**`vintage` / `worn` / `used` 太抽象，模型会画成崭新的复刻品。要写清坏在哪：珐琅缺了一角、皮带边缘磨毛、黄铜氧化发暗、杯沿一圈茶渍、常年被手握的那一处磨得发亮。这跟规则 2 是同一件事的两面——**能写进锚点的磨损，才是能核对的磨损**。展开见 `realism.md` 第 4 节；画风非写实的那几档只取它通用的那半边。

9. **反向词按道具自己的需要写**，不必把画风那一块的每一条都带上——道具参考图是纯白背景，画风里冲着「环境别太干净」去的那几条正好和白底自相矛盾。必须有的三样另有门管着：**禁人**、**禁手**、**纯白背景**。

## 输入格式

```
画风（production.json 的 style.scene，渲染句与场景同一套）：
  render: …
候选物品线索（独立读取原件并记录 sourceRefs）：
- 许桂兰找出邻居代存的旧留言板，核对后归还（第 1–3 集）
- 夹纸铁盒暂存已分清归属的便条（第 2–3 集）
- 菜摊边的空塑料筐（没有独立剧情功能）
已有场景：S01 菜摊雨棚、S02 公共水池、S03 雨棚清空状态
```

上面第三条就该落选——既无独立连续性需要，也不承载剧情；不是因为名词出现就要建资产。

## 创作背景边界

先读 [creative-background.md](creative-background.md)。creativeBrief 仅作为项目自然语言要求，不推导规则。视觉正文必须来自 production.style.scene。节点无需分类；道具只保留显式 beatIds 引用，节点结果用于阅读，不凭同集出现推断精确节点归属。正式样例先确定《雨棚留言》故事提案，再设计资产；没有分镜或真实图片。
