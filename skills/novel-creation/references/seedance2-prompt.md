# seedance2.0 提示词指南 · 内化版（选了 seedance 系列模型才读这份）

**学习来源**：火山引擎官方《Doubao Seedance 2.0 系列提示词指南》
（`https://docs.volcengine.com/docs/82379/2222480`，页面最近更新 2026-08-17）。
方法论**内化成本 skill 自带文档，不依赖任何外部 skill**——搬过来的是判断，不是链接。

**什么时候读这份**：`production.json` 的 `video.model` 落在 seedance 系列
（`seedance2.5` / `seedance2.0` / `seedance2.0 fast` / `seedance2.0 mini`）。
选的是 `MiniMax H3` 就整份跳过，改读同目录的 `h3-prompt.md`；挂的是别的模型，两份都不读，照 `creation-prompt.md` 的通用骨架写。

**跟 `creation-prompt.md` 的分工**：那份定骨架（基础检查查的结构），这份讲**骨架里怎么填**
才对得上 seedance 的口味。骨架一个字不改——身份说明句、`[镜头 k]` 逐镜分行、认领台词逐字，
一样都不许少。

## 一、seedance 与本 skill 的骨架天然对得上的地方

| 官方口径 | 本 skill 的现状 | 结论 |
| --- | --- | --- |
| 「模型对精确时间（如 0–3 秒）的支持不稳定，强行限制时长可能导致生成结果异常」 | 提示词里本来就没有切点时刻、没有对齐指令（那是多图按秒对齐的骨架才有的） | 天然对上。挂 seedance 时 `prompt-model-fit` 门还会盯着，写进去一个时刻就拦 |
| 时间轴化分镜：「镜头 1 / 镜头 2 / 镜头 3」按事件顺序组织 | `[镜头 k]` 逐镜分行，本来就是这个形状 | 天然对上 |
| 一个镜头只指定 1 种运镜，「不要同时要求推拉摇移」 | `cut.camera` 是单选枚举，一切一个运镜 | 天然对上 |
| 参考人物超过 4 人时输出稳定性下降 | `crowd` 门卡在同框 ≤ 3 人 | 门比官方还严一档，照跑 |
| 素材推荐 4–5 个，「不建议用满素材上限」 | 段级挂载是「这一格实际引用的」，不是全集 | 挂载时按这条收敛，一段 `images` 尽量 ≤ 5 张 |

段秒数不进提示词，它只有两个用途：折算下单的 `duration`（`clampDuration`，seedance2.0
系列的区间是 4–15 秒、2.5 是 4–30 秒），以及配音对齐单。**不要把秒数写进 `prompt`**——
从多图对齐那套提示词里搬东西最容易带过来的就是 `[Shot 2] At 00:03.000,` 里的时刻，
`prompt-model-fit` 门会点名到具体那一处。

确定性检查包括 `0–3 秒观察，3–5 秒停留`、`0.5～3.25 秒`、`第 3 秒`、`3 秒后`、`3.00-second`、`at 3.5 seconds`、`0–3s` 和 `00:03` 等数字秒数／区间／时间码。`videos` 读取投产包后也会检查，不允许修改 prompt.md 后绕过。顺序表达如“随后”“缓慢观察”不受此门限制。数字检查不能证明自然语言提示词的全部语义有效性。

## 二、语言：挂 seedance 时默认就是 `zh`

`promptLang` 不写就跟着模型走，挂 seedance 系列默认整条中文。默认这么定，理由三条，
都不是口味问题：

1. **官方的句式、术语、全部实战案例都是中文**——「中景」「缓慢推近」「固定机位」这些词
   模型吃得最准，英文是二手翻译。
2. **官方要求「台词语言需统一，避免中英文混用（专有名词除外）」**。剧本台词是中文，
   整条英文正文配中文台词，正是它点名的混用。
3. **`zh` 模式下 `prompt-no-names` 门放行人名**，而 seedance 官方恰恰要求给每个主体一个
   **稳定标签**并全程复用——标签用角色名最省事。`en` 模式禁人名，跟这条顶着来。

中文模式的骨架 token：`图 k 是` / `[镜头 k]` / `镜头描述：` / `环境声与配乐：`。真要写英文
（比如整部剧统一走英文提示词），在 `production.json` 或 creation.json 顶层显式写
`"promptLang": "en"` 就能盖掉默认值——但上面三条也就一起放弃了。

## 三、一条既过门又对 seedance 口味的提示词（《收书人》E01-01）

```text
图 1 是抱着一本布面旧诗集、穿深色外套的年轻男子，下文称<主体1>。图 2 是只在深夜开门的
旧书铺内景，书架挤满旧书，一盏暖黄台灯，下文称<场景1>。图 3 是那本布面旧诗集，封面因年久
发软，下文称<道具1>。

镜头描述：
[镜头 1] 全景, 跟拍 — 深夜的<场景1>，<主体1>伸手把门推开走进来，铜铃轻响，他在高耸的
书堆之间放慢脚步，<道具1>抱在胸前；镜头平稳跟拍他的背影。<铜铃轻响><纸页翻动的窸窣声>
[镜头 2] 中景, 推 — <主体1>停在柜台前，一只手仍托着<道具1>，喉结动了一下，压低声音试探着
问：{还开着吗？我想卖一本书。}；镜头缓慢推近他的脸。

环境声与配乐：深夜的低沉环境声，书堆深处纸页翻动的轻响，铜铃余音渐弱。无配乐。

全片高清电影质感，暖黄低饱和色调，光影柔和；人物面部稳定不变形，动作自然连贯，无卡顿
无闪烁。保持无字幕，不要生成 Logo，不要生成水印。视频全程禁止出现外形、着装、配饰完全
一致的人物，禁止生成同款分身、双胞胎效果，同一画面中仅保留单个对应人物。
```

（代码块里的折行只是这份文档的排版。真正写进 `prompt` 时，**一切就是一行**，`[镜头 k]` 到
下一个 `[镜头 k+1]` 之间不断行。）

逐条对照——**左边是门在查的，右边是 seedance 在吃的**：

| 位置 | 门查什么 | seedance 要什么 | 怎么同时满足 |
| --- | --- | --- | --- |
| 开头 | `refimage-labeled`：`图 k 是` 逐句数，数量等于 `images` 长度，不多不少 | 主体定义：「将<图片N>中的[核心特征]定义为<主体N>」 | 写成 `图 k 是<2–3 个稳定静态特征>，下文称<主体N>` ——前半句给门，后半句给模型 |
| 正文指代 | 不查 | 「每次提到主体时都应使用同一标签」 | 全程用 `<主体1>`，不要一会儿「他」一会儿「图片 1」 |
| `[镜头 k]` 行首 | `size-phrase` / `camera-phrase`：中文景别词与运镜词必须落在这一切自己的行里 | 标准运镜术语，一镜一种运镜 | **门查的词和模型吃的词是同一批**：全景/中景/特写、推/拉/摇/移/跟拍——照枚举写就对 |
| 台词 | `dialogue-verbatim`：纯文本子串匹配，逐字 | 台词用 `{}` 包裹 | `{}` 包在外面不影响子串匹配。**台词一个字、一个标点都不许改** |
| 收尾段 | 不查（`promptCutSlices` 只切 `镜头描述：` 到 `环境声与配乐：` 之间） | 画质 + 风格 + 约束词 | 一律写在 `环境声与配乐：` **之后**，写在前面会被算进最后一切的行里 |

**`images` 数组的顺序就是上传顺序，也就是官方说的「图片 N」的 N。** 官方还有一条：
「越需要精准参考的素材，放在提示词中越靠前的位置」——所以**主角的角色图排第一**，
场景、道具往后排。挂载时想清楚顺序，别凭印象。

## 四、⚠️ 设定图是三视图，这是官方点名的雷区

本 skill 直接挂 `novel-characters` 落盘的 `<角色>-sheet.png`。那张图的版面是
**左栏半身像 + 右上全身三视图 + 右下细节格**——官方两处点名这种素材：

> **人物 ID 漂移**：人物参考使用大头照 + 全身照即可，**不建议使用人物多视图**。多视图素材
> 包含同一人物的不同角度，模型易将其识别为多个不同主体，反而加剧 ID 漂移问题。
>
> **双胞胎问题**：以人物三视图 / 多视图作为参考素材时，易造成模型人物识别混淆，从而生成
> 重复同款人物。

也就是说，**「挂现成设定图直出」这条路走 seedance 时，踩在官方点名的两个坑上**。这不是
理论风险，是要在下单前就有对策的事。四条，按代价从低到高：

1. **提示词兜底**（零成本，必做）：收尾段写死那句全局约束（示例里最后一句），主体定义
   句把核心特征写足 2–3 个，让模型有依据区分。
2. **重要素材前置**（零成本，必做）：主角图排 `images[0]`。
3. **换一张单人图下单**（推荐，一次手工换全片复用）：从 sheet 图裁出左栏那张半身像，
   另存 `characters/images/<角色>-face.png`；`export` 之后把 `manifest.json` 另存一份
   `manifest.seedance.json`，把该角色的 `path` 改指向 face 图，再
   `videos manifest.seedance.json`。
   **`images[].path` 由 `ref` 推导、creation.json 里写不了别的路径**，所以这一步只能落在
   manifest 上；`videos` 收的是位置参数，任何文件名都认。重新 `export` 会覆盖
   `manifest.json`，所以改动做在另存的那一份上，不会被冲掉。
4. **拆段**（有代价）：一段里参考人物压到 2–3 个。`crowd` 门已经卡了同框 ≤ 3 人，
   通常不需要额外做什么。

场景与道具的设定图同样是多格版面，但它们是环境与物件、不是人脸，模型混淆的代价小得多，
按现状挂就行——**要处理的是人**。

## 五、动作与情绪：官方四条

跟 `creation-prompt.md` 的「常见动作原则」同向，更细一档：

1. **肢体细化 + 程度量化**——具体到手、腿、头部、肩背，补幅度/速度/力度：缓慢抬手、
   快速转头、用力蹬地、微微低头。
2. **优先低缓连续的小动作**——规避狂奔、大跳、剧烈翻滚这类高爆发大动态。
3. **补充动作过渡衔接**——写明前后动作的惯性承接：借着转身惯性顺势抬手。
4. **情绪具象外化**——不写「很悲伤」，写身体细节：

| 抽象情绪 | 外化成动作与细节 |
| --- | --- |
| 悲伤 | 低头、肩膀微微颤抖、手指无意识攥紧衣角、泪水在眼眶里打转但没有落下 |
| 喜悦 | 嘴角抑制不住上扬、眉眼舒展、脚步变轻快、忍不住原地转个圈 |
| 紧张 | 频繁看手表、手指不停敲击桌面、呼吸急促、眼神闪躲 |
| 愤怒 | 双拳紧握、下颌线紧绷、胸口剧烈起伏、从牙缝里挤出话语 |
| 释然 | 长长舒一口气、紧绷的肩膀完全放松、抬头望向远方 |

## 六、特殊符号：四种信息四种括号

| 信息类型 | 符号 | 示例 |
| --- | --- | --- |
| 音乐 | `（）` | `（背景中播放着快节奏的摇滚乐）` |
| 音效 | `<>` | `<远处传来狗叫声>` |
| 台词 | `{}` | `{还开着吗？我想卖一本书。}` |
| 字幕 | `【】` | `【第一章：启程】` |

**字幕的 `【】` 与收尾段的「保持无字幕」互斥**，别同时写。短剧的字幕通常在剪辑期贴，
所以本 skill 的默认是要「无字幕」那一句。

台词是小语种（非中英文）时官方要求标注语种：`用日语说道{こんにちは}`。

## 七、收尾段：画质、风格、约束词

三件事一段写完，放在 `环境声与配乐：` 之后：

- **画质**：高清、细节丰富、电影质感、色彩自然、光影柔和
- **风格**：跟 `production.json` 的 `style.phrase` 走——官方点名过
  「风格漂移」：参考图偏写实而提示词不强调风格时，动画风会漂成真人写实
- **约束词**：`保持无字幕` / `不要生成 Logo` / `不要生成水印` / 双胞胎那句全局约束。
  官方明说字幕**无法 100% 避免**，只能降低概率；横屏出字幕的概率明显低于竖屏，
  但短剧多是 9:16，这条基本用不上，只能靠约束句加抽卡

## 八、官方指南里用不上的部分（划清边界，别照搬）

编辑视频、延长视频、轨道补全、视频参考、音频参考、素材库 Asset ID——**本 skill 一段一次
生成、只挂静态设定图，这些一条都用不上**。特别是「视频延长」：它是剪辑期的玩法，本 skill
到每段一个 mp4 为止（见 `video-order.md` 的边界）。

官方的「文字生成」（广告语、字幕、气泡台词）同理：短剧的字幕与花字在剪辑期做，
提示词这一层要的是「无字幕」。

## 九、常见病

| 病 | 症状 | 治法 |
| --- | --- | --- |
| 抄秒数病 | 看到官方讲「时间层」，就把「0–3 秒」写进镜头行 | 官方明说精确时间支持不稳定，强行限制会让生成异常——秒数只留在 creation.json 里 |
| 单字运镜撞车 | 「他推开门」和「镜头缓慢推近」在中文里都是「推」，模型分不清是机位动了还是人动了 | 运镜写成完整短语（镜头缓慢推近），人物动作换个说法（伸手把门推开），同一行里把主语分清 |
| 标签漂移 | 前一镜叫 `<主体1>`，后一镜改叫「那个年轻人」 | 标签一旦定下全程复用，官方点名这是指代混乱的主要来源 |
| 编号错位 | 提示词里 `图 3` 指的其实是 `images` 数组第 2 个 | 编号顺序必须与 `images` 数组顺序一致，它同时也是上传顺序 |
| 收尾段串行 | 画质与约束词写在 `环境声与配乐：` 之前 | 会被算进最后一切的 `[镜头 k]` 行里，逐镜的门跟着一起脏——挪到最后 |
| 台词改字 | 为了让模型读准，把生僻字换成同音字 | **台词不许动**，`dialogue-verbatim` 逐字比对必被拦。发音问题只能改台词之外的旁白与地名（官方示例：螭龙山→吃龙山），台词真读错就回 `novel-script` 改剧本 |
| 素材堆满 | 一段挂了 8 张设定图，想着信息越多越好 | 官方明说不建议用满上限，过多素材会让模型难以判断特征优先级——一段收敛到 5 张以内 |
