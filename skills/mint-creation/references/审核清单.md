# 视频提示词审核清单

## 审核的对象与依据

审核对象是一集的全部工作单：每段的分镜结构与提示词正文。依据只有四样：节拍底稿（剧本）、资产表、项目要求、视频模型口径。提示词写得再漂亮，与这四样对不上就是问题；与这四样都对得上，文风不合自己的口味不是问题。

批准表示：这条提示词忠实于剧本，观众看得到应当看到的东西，模型大概率能够完成，可以进入付费生成。批准不表示成片一定成功。

## 七个维度

每个维度先列阻断问题（写成 `[必须修改]`），再列非阻断问题（写成 `[建议]`）。

### 一、忠实于剧本

阻断：

- 新增了剧本没有的事实、结果或心理结论。例：节拍只写「把回执对折，放进工牌套」，提示词写成「她终于原谅了母亲，露出释然的微笑」。
- 省略了人物的选择或选择的结果。
- 台词被改字、截断、合并，或者换了说话人。
- 画内人物、道具与该节拍不符。
- 项目要求明确不回答的问题，被画面或措辞悄悄回答了。

非阻断：动作细节比剧本更具体，但没有改变事实（例如补了手的位置）。

### 二、观众看得见

阻断：

- 支持推断的证据没有可读的停留：文字、印章、物件比对与台词挤在同一镜里，或者镜头推向了别处。
- 泄露了此刻观众不应当知道的信息。
- 情绪只写成形容词（「情绪复杂」「内心挣扎」），没有任何可见的动作或物件承载。

非阻断：停留偏紧但仍可读；可以换一个更清楚的景别。

### 三、切换与停留

阻断：

- 一个分镜塞进了两件需要分别看清的事。
- 台词估时明显装不下所在分镜。
- 长时间没有任何变化的画面，只在提示词里声称「逐渐紧张」。

非阻断：切换偏多或偏少但不影响辨认。没有通用的建议时长，不以「每镜应当几秒」为由退回。

### 四、开场与集尾

阻断：

- 材料标注了开场节拍，对应镜头没有表达开场意图。
- 集尾扩大或取消了上游的承诺：单元故事被加上新悬念，或者应当保留的悬念被提前解答。

### 五、段间连续

阻断：

- 相邻两段的人物位置、姿态、手持物或光线互相矛盾，且提示词没有交代过渡。
- 一段开头没有交代人物此刻在哪里、在做什么——模型不记得上一段。

非阻断：服装与环境声的细微不一致。分次生成本身的连续性风险写进回报，不作为退回理由。

### 六、参考图与身份

阻断：

- 身份说明句的编号与 `images` 顺序不一致，或者说明的对象与资产不符。
- 同一个人在一段里有两种说法或两个标签，模型会当成两个人。
- 英文提示词正文出现了角色名（台词引号内除外）。
- 这一段明显需要的人物没有挂载参考图。

非阻断：挂载超过五张；主角没有排在第一。

### 七、模型口径

只按工作单状态头里的 `model` 判断。没有收录的模型不套用下面任何一族的规则，在回报里说明能力未核实。

MiniMax H3，阻断：

- 出现对齐指令、切点时刻、`<d>` 标签或说话人编号——那是多图对齐模式的语法，这里没有落点。
- 自行增加了 `shots:` 与 `ambience:` 之外的字段。
- 声景与画面动作矛盾。声景也是动作指令：声景写撞击，视频就会演出撞击。

MiniMax H3，非阻断：说话人第一次出现时没有给足身份、年龄段与音色；画外音没有补唇形闭合的半句。

seedance 系列，阻断：

- 出现数字秒数、秒数区间或时间码。
- 主体标签中途更换（前一镜 `<主体1>`，后一镜「那个年轻人」）。
- 一个镜头要求两种以上运镜。
- 画质与约束词写在 `环境声与配乐：` 之前，混进了最后一个镜头。
- 人物动作词与运镜词同字且主语不清（「他推开门」与「镜头推」），分不清是谁在动。

seedance 系列，非阻断：收尾段缺少风格或约束词；动作偏向高爆发大动态；情绪没有外化成身体细节；台词没有使用 `{}` 包裹。

两族共同，阻断：写了模型难以稳定完成的精确物理交互或微表情，并且这个动作承载着本镜的关键信息。

## 写意见的规则

- 每条意见单独一行，写成 `- [必须修改] 位置：……`、`- [建议] 位置：……` 或 `- [阻塞] 位置：……`。位置为 `镜头 k`、`整段`、`参考图` 或 `声景`，并引用原句或节拍编号。
- 意见区里不使用二级标题；需要小标题时使用三级标题或加粗。在条目之外不要提到 `[必须修改]` 与 `[阻塞]` 这两个标签——批准命令会把它们当作尚未解决的问题。
- 说清问题和要达到的效果，不替编写方写出整条新提示词。
- 一个问题只写一条。同一个根因造成的多处症状合并说明。
- 意见只保留本轮。不记录历史，不打分，不做累积统计。
- 第一行写「结论：」，一两句话概括本轮判断。

## 判定

- 没有任何必须修改，也没有阻塞 → `approved`。还有建议也批准，建议留给编写方与后续轮次自行取舍。
- 至少一条必须修改，没有阻塞 → `changes_requested`。
- 至少一条阻塞 → `blocked`。阻塞只用于编写方无法单独解决的问题：这一段需要的设定图不存在、剧本台词本身有误、目标时长无法容纳认领的节拍、输入材料互相矛盾。同时存在必须修改时一并写出，结论仍为 `blocked`。
- 逐段判定。一段的问题不连带退回其他段，除非问题就是两段之间的矛盾——此时两段都退回，并在各自意见里写明对方段号。

## 复审

- 先逐条核对上一轮的必须修改是否解决，对照「编写回应」。
- 编写方不同意并给出了剧本或项目要求上的依据时，认真重新判断；依据成立就撤回意见。
- 修改引入的新问题照常提出。上一轮已经接受、本轮没有改动的内容，不重新挑剔。
- 同一条意见往返两轮仍未解决，在回报里标明这是分歧而不是疏漏，交调度方转给用户决定。

## 不属于审核方的事

- 不修改分镜结构与提示词正文。
- 不要求编写方修改剧本、台词或资产；这类问题写成 `[阻塞]`，登记 `blocked`，并写进回报。
- 不评价尚未生成的视频质量，不核对费用与下单参数。
