# outline 剧情与资产拆分方案

## 目标与原则

将剧本的故事分析与资产拆解分开：

- `mint-outline` 只提取故事、剧情节点、分集和节奏相关事实。
- `mint-characters` 独立阅读原剧本，判断人物身份、别名及身份归并，并按需要完成角色设计。
- `mint-art` 独立阅读原剧本，识别场景和物品，并按需要完成美术资产设计。
- `mint-script` 整理正文、场次和声音表达，并对照已完成的故事及资产产物。
- `mint-creation` 根据前序产物进行制作规划与交接。

**完整流程固定为五个阶段：outline → characters → art → script → creation。** 依照用户列出的五个阶段执行，不跳过、倒序或并行推进。每个阶段完成并交接后再进入下一阶段。完整流程使用项目级统一流程状态记录阶段完成与推进；它不替代各阶段产物校验，也不记录失败累积日志或统计。

**阶段独立**指职责和判定权分开，而不是完整流程可以跳过上游。各阶段对自己的任务和产物负责，可以读取前序产物进行交接与对账，但不代替其他阶段作判断。独立运行能力仍可保留，不能冒充完整流程或跨阶段对账已通过。

人物身份判断由 characters 负责。script 可以按原文记录说话者和行动主体，但不能把自己的局部标记冒充 characters 已确认的身份，也不能要求 characters 接受 script 的归并结论。art 负责场景和物品的资产识别与设计；script 中的场次边界不等于 art 的地点身份。

各 skill 必须自包含、可单独复制。跨阶段可以消费数据文件，不依赖兄弟 skill 的脚本、样例或第三方 skill。原剧本及用户明确提供的项目配置是共同输入，不等于阶段之间相互依赖。

本方案的职责拆分及流程已实施。当前版本、逐项验收和验证边界见[剧情与资产拆分实施验收](剧情与资产拆分-实施验收.md)，入口与消费者矩阵见[阶段交接与版本支持](阶段交接与版本支持.md)。以下实施前状态保留用于说明迁移来源。

## 实施前状态

实施前 `outline.json` 使用 schemaVersion 4，契约见 `skills/mint-outline/references/schema.md`。它同时保存故事数据和资产数据：

| 数据 | 当前内容 |
| --- | --- |
| `characters` | 角色 ID、姓名、定位、分档、人物变化、别名、出场方式和来源 |
| `scenes` | 地点 ID、名称、是否主场景和来源。这里是地点身份，不是剧本场次 |
| `props` | 道具 ID、名称、叙事功能、关联剧情节点和来源 |
| `episodes[].characterIds / sceneIds / propIds` | 每集引用的角色、地点和道具 |
| `story.focusCharacterIds` | 故事关注的角色 ID |
| `notes` 中的资产 ID 和 `speakerId` | 将连续性、限制或角色说法关联到资产身份 |
| `params.thresholds` | 角色、主场景和道具数量预算 |

`characters` 和 `scenes` 是必需数组，允许为空；`props` 可选。outline 还负责资产数量检查、资产清单、分集调度矩阵和 `assets` 命令。

现有角色和美术阶段可从 outline 资产表 seed；script 的场次、对白和声音身份使用 C/S/P ID，部分检查从 outline 的资产表核验。creation 及派发材料也消费相关身份和来源。因此，不能只删除三个数组而不调整下游。

## 阶段职责

### outline：故事与剧情结构

保留：

1. **来源和覆盖**：原剧本文件、版本摘要、已读取范围和事实出处。
2. **整体故事**：故事摘要及确实已知的结局位置。
3. **剧情节点**：事件发生前的处境、事件及其结果、叙事顺序。
4. **分集信息**：每集梗概、开场、集尾事件及问题。
5. **节奏相关事实**：节点顺序、问题提出和回答的位置、悬念或收束方式。
6. **必要的故事连续性**：前情、信息限制、人物说法与客观事实的区别。

outline 可以写“师傅把断尺交给学生”，也可以记录物品状态或人物知情边界；这些是故事事实，不等于建立人物表、场景表、道具表或判定资产身份。同名人物、身份未揭晓或说话者未知时，使用原文可支持的描述与来源区分；不能为了消除歧义猜测身份。

节奏先表示原剧本中能核实的结构和顺序。不自动增加节奏评分、类型标签、目标时长，也不强制每集设置悬念。当前 v4 已移除的旧节奏规划字段不因本方案恢复。

outline 不负责分配 C/S/P 身份、角色分档、主场景、资产预算、出图范围、资产复用或分集资产调度。

### characters：人物身份与角色设计

- 独立读取原剧本，判断人物身份、别名和归并，区分同名不同人、无台词人物、声音主体和仅被提及的人物。
- 在本阶段建立和维护稳定的角色身份，以及来源事实和必要的未知项。
- 是否制作角色画像、音色、提示词或参考图，由实际任务与制作需求决定；出现人物不等于必须出图。
- 完整流程中读取已完成的 outline 作为故事背景，并回查原剧本独立判断人物；outline 的称呼不是人物身份判定结果。发现冲突时回查原文，不静默覆盖任一产物。

### art：场景与物品识别、资产设计

- 独立读取原剧本，识别地点和物品，判断哪些需要作为美术资产，并维护资产身份和来源事实。
- 处理主场景、复用、变体及视觉设计；区分原文事实与制作补定。
- 完整流程中参考已完成的 outline 和 characters 产物，并回查原剧本独立判断美术资产。人物身份由 characters 负责；原文中的场次不自动等于地点身份，提及物品也不自动意味着需要建立道具资产。

### script：正文整理与表达

- 独立读取原剧本，整理原有场次、动作、对白、字幕、声音及非发声说明，保留来源与必要的表达约束。
- 按原文记录说话者、听者、人物称呼、地点和物品。为表达正文所需的引用可以使用局部标记或来源坐标，但其作用域仅限 script，不能视为全项目资产身份。
- 不负责人物身份归并及角色资产分档，不把未确认的同名、别名、声音主体强行合并；必要时保留歧义和来源依据。
- 完整流程中读取已完成的 outline，认领和核对剧情节点；读取 characters/art，核对正文引用与已确认身份。存在冲突或不确定映射时保留待确认，不按名字猜测。
- 独立运行时可以不提供其他阶段产物，但不宣称已完成完整流程或跨阶段对账。

保留 script 独立创作入口及其原有授权边界；本方案不把已有剧本解析的约束扩展为禁止独立创作。

### creation：制作规划与交接

- 完整流程中读取前序阶段所需产物，核对正文、剧情节点、资产身份和来源后开展制作规划。
- 对实际使用的身份和素材进行对账；缺少必要输入或存在未解决的映射冲突时，不得宣称联合制作交接通过。
- 固定顺序不意味着前序阶段必须生成所有图片或其他媒体；生成与否仍由制作需求和授权决定。

## 目标流程与交接

```text
原剧本
  ↓
1. outline      故事与剧情结构
  ↓
2. characters   人物身份与角色设计
  ↓
3. art          场景、物品识别与美术设计
  ↓
4. script       正文、场次、声音及前序产物对账
  ↓
5. creation     制作规划与交接
```

这是完整流程的固定顺序。下一阶段开始前，上一阶段须完成本次任务范围内的产物和必要交接；失败或尚未完成时不能跳过。阶段完成范围及未决问题要明确记录，不把局部范围冒称全剧完成。

角色、场景和道具的出图不因顺序固定而自动成为前置条件。独立使用单个 skill 仍可按其自身入口运行，但不属于此完整流程，不能声明前序阶段已完成。

### 局部引用与联合映射

- script 的局部引用只标识正文中需要区分的对象或出现位置；它不是 characters/art 的稳定资产 ID。
- characters 和 art 各自维护本阶段身份。script 不通过名称相同自动认定映射，尤其不能合并同名人物。
- 完整流程中，script 根据已完成的 characters/art 产物及原文证据，核对实际需要的引用；未知、歧义或冲突保持待确认。creation 再核验制作实际使用的映射。
- 映射应有唯一权威保存位置、可追溯依据及失效规则；具体放在哪个现有产物或交接材料中，实施前结合现有 creation 接口确定，不预设新增文件、独立阶段或统一身份服务。
- 用户明确决定是否存在同一身份时，记录决定及依据；不把制作补定冒称原文事实。

同一次原文发声、场次与剧情节点的顺序仍以 script 及其来源为准。跨阶段身份映射不能改变正文、提前揭晓信息或把同一句不同位置的台词合并。

## 修改方案

### 1. 缩小 outline 契约

建议新的正式契约使用 **outline v5**，避免同一个 v4 版本出现两种不兼容含义。保留 `source`、`provenance`、`story.summary`、剧情 `beats`、分集、开场、集尾、问题与回答及 `sourceRefs`。

从 outline 移出 `characters`、`scenes`、`props`、`focusCharacterIds`、分集资产 ID 数组、notes 中的资产 ID 和 `speakerId`，以及资产数量 `thresholds` 和资产调度。保留剧情所需的状态、知情边界和说法，使用原文支持的自然语言与来源表达；说话者不能确定时明确标记未知。

删除人物身份字段不意味着人物变化、人物关系和动机等故事内容必须从摘要中删除；只是不再把它们组织成角色资产表。

### 2. 调整独立阶段输入和产物

- **characters**：替换“有 v4 outline 就以其人物清单为准”的规则，支持直接从原剧本提取和判定人物身份。模型或人工负责语义识别，脚本负责可确定的骨架、格式、引用及来源校验；不把 seed 描述为自动理解原文。
- **art**：替换从 outline 资产表复制场景和道具的默认流程，支持独立从原剧本识别及制作。场次与地点、正文物品与道具资产之间不能机械等同。
- **script**：取消对 outline 资产身份的依赖；完整流程读取已完成的 characters/art 并对账，独立模式仍能在没有这些产物时表达原文。保留说话者、听者、场次和物品的必要区分与来源；具体字段和局部引用形状以现有契约及独立运行需求为基础设计。
- 各阶段明确输入文件、来源路径基准、覆盖范围及缺失原件的行为。缺少可选上游标记 skipped；已提供但损坏、版本错误或不匹配的输入不得伪装成缺失。

### 3. 定义联合制作对账

实施前逐项盘点 script、creation、工作单、提示词和审核中对 outline 资产的现有依赖，建立“现有读取位置 → 新权威来源 → 无上游状态 → 联合制作时的阻断条件”对照表。

- 剧情节点及问题以 outline 为准，正文及正文位置以 script 为准。
- 人物身份由 characters 判断；场景和道具资产身份由 art 判断。
- 对确实需要资产身份的正文引用，显式核对映射和原文依据。同名、未知或存在多种合理映射时不自动猜测。
- 完整流程必须按顺序交接，缺少该流程要求的前序产物或交接未完成时不能进入下一阶段；单独运行时缺少可选产物可继续，跨阶段对账为 skipped。实际制作依赖某个身份但映射缺失或冲突时，相关制作交接应阻断，不能声称联合校验通过。
- 原件摘要、文档身份及相关负责范围须在联合输入间对账。版本变化或相关事实不在已核验范围内时，受影响的映射和审核需重新核验；不宣称其他无关部分自动失效。
- 确认角色、场景、道具的身份变更如何影响工作单、参考图路径、输入摘要和审核结果；不将内容审核结论替换为结构检查结论。

### 4. 身份生命周期

characters/art 增量处理时参考本阶段既有产物。重排或新增剧集不能无故改变已确认 ID；已分配 ID 不复用于另一个对象。身份合并、拆分、纠正或删除时保留显式映射和依据，并重新核验受影响的联合引用。局部 script 标记与资产 ID 不因字符相同就视为已映射。

具体增量机制应复用各阶段现有产物和迁移能力，不为此额外建立共享身份服务。

### 5. 报告、预算和命令

- outline 报告删除人物表、场景表、道具表、资产预算及分集资产矩阵；移除或退役 `assets` 命令。
- 保留来源核验、剧情节点顺序、分集和问题引用检查。
- 用户明确设置的资产数量预算不得静默丢弃或降级。角色预算保存在 characters 阶段产物，美术预算保存在 art 阶段产物；各阶段分别检查。参考值提醒与明确预算阻断保持区别。迁移须保留原值，并明确未能自动归属的情况。

### 6. 旧数据迁移和版本切换

保留原 v4 文件，不覆盖。生成 outline v5 草稿时，只投影剧情相关数据；资产及关系导出为对应阶段的待核对迁移材料，不直接冒充已审核的资产产物。

迁移必须逐字段处理人物、地点、道具、来源、别名、资产 notes、分集资产引用、道具节点关联、焦点角色、说话者及旧预算。无法直接投影的关系保留原字段路径、原值和处理状态，不静默删除。尽可能保留原 C/S/P ID，并检查已有 script、creation、图片路径及审核材料；ID 沿用不等于身份映射已通过审核。

实施前列出各消费者的版本支持矩阵、升级顺序、旧项目继续运行或显式迁移的方式，以及不兼容输入的报错。完成迁移后重新核验来源和受影响的跨阶段引用。不要通过隐式双读使同一版本出现不同语义。

## 验收重点

1. **职责**：outline 不输出资产清单、资产分类或资产预算，仍保留剧情需要的事实和出处；characters 独立判定人物身份，art 独立识别美术资产。
2. **顺序与独立性**：完整流程严格按 outline → characters → art → script → creation 顺序交接；前序未完成时不能跳过。单个 skill 的独立入口仍可运行，但不能冒充完整流程或已完成联合对账；各 skill 可单独复制。
3. **语义**：覆盖同名不同人、别名、无台词人物、匿名声音、未知说话者、非人主体、场次与地点区别、物品交接和状态变化；未知信息不靠名字猜测。
4. **联合交接**：覆盖局部引用与资产 ID 相同但未映射、明确映射、歧义、冲突和缺失；只对制作实际依赖的身份要求完成映射。
5. **来源与变更**：覆盖 partial、原件改版、不同来源版本、来源范围缺口，以及身份重排、合并、拆分对相关工作单和审核的影响。
6. **迁移**：覆盖 v4 资产及其全部关联、原字段可追踪、旧 ID 和预算保留、不可自动映射项及版本不兼容提示。
7. **回归**：检查各阶段校验、报告、命令、现有独立创作入口、creation、提示词和审核链路。结构和来源校验不冒充语义忠实度、内容审核或成片审核。
