# Skills 创作策略解耦改造方案

> 历史资料：本文记录 v2 profile 体系及当时验收，不是当前操作指南。创作配置和产物精简以 [创作产物与指南精简实施计划](skills-创作产物与指南精简实施计划.md) 为准；历史测试结果不代表 v3 已通过。

- 状态：已实施并完成本地验收。本文保留目标架构、数据契约、修改范围和验收标准；当前实现、测试证据及未验证效果见 [验收记录](skills-创作策略解耦验收.md)。未执行真实图片或视频生成，未提交或发布。
- 取代文档：`mint-outline-竖屏密集爽点改造方案.md`。旧方案整体作废，不再作为并行实施依据；需要保留的设计已经重新写入本文。
- 审查基线：开发分支 `dev`，本轮检查时 HEAD 为 `d932ed7`；当前 outline/script 为 1.5.0，setup 为 2.0.0，creation 为 1.3.0。实施前重新核实实际文件与版本。
- 核心目标：保持 skill 职责、工作流程和数据接口稳定。用户通过各 skill 自带的 references 选择或新增题材、叙事风格、结构与节奏策略，不为每种表现方式修改主流程和校验代码。
- 首批交付：通用契约、策略加载机制，以及密集兑现连续剧、慢热悬疑、单元生活剧三种组合的完整验证。
- 非目标：不承诺任意艺术形式都能无代码接入，不建设通用插件运行平台，不生成分镜图片，不调用付费模型，不新增质量门失败累积日志或统计功能。

## 1. 决策摘要

1. 六个 skill 的职责与产物目录保持。故事、剧本、角色、美术、视频创作仍然分层。
2. `SKILL.md` 负责流程与边界；通用 references 负责数据契约与基础方法；策略 references 负责可替换的内容表现方法。
3. 将密集兑现作为一种可选策略，不再作为所有作品的默认合法结构。
4. 题材、叙事风格、故事结构、叙事节奏、视觉风格、制作约束分别管理，不以画幅推导节奏，不以题材推导全部表现方式。
5. 策略采用本地 JSON 描述文件和 Markdown 指南，不执行策略文件里的代码，不建设表达式语言。
6. 项目记录策略选择；每个阶段在显式应用策略时，将本阶段生效参数写入自己的产物。运行校验和渲染时不偷偷重新应用模板。
7. 保留稳定节点 ID、剧本节点认领、上游目标时长对账、显式版本和结构／内容评审分离。
8. 开场、集尾、终局和阶段节点采用中性契约。是否必须兑现、是否必须悬念、是否限期解决，由选定策略决定。
9. 基础引用、字段类型、实际位置和明确承诺的自洽性不能被策略关闭。
10. outline、script、creation 一起完成策略传递；setup、characters、art 和合并报告完成必要适配。不能只修改大纲后宣称全管线解耦。
11. 各 skill 自包含。允许交换项目 JSON，不允许读取兄弟 skill 的 references、import 兄弟代码或借用兄弟正式样例。
12. 对内容有效性的判断仍由模型或人工评审完成。字段齐全不等于故事成立，估算时间不等于成片效果。

## 2. 问题与本次修改范围

### 2.1 当前耦合

| 位置 | 当前情况 | 修改方向 |
| --- | --- | --- |
| outline 的主流程、指南和校验 | 以爽点安排作为通用故事组织方式 | 通用事件计划与可选兑现策略分离 |
| 旧方案的 pacing | 每集至少一次兑现，所有数值必须为正整数，没有关闭路径 | 规则显式启用，关闭不靠超大阈值或伪造节点 |
| 旧方案的集尾与终局 | 非最终集必须悬念，最终集必须大兑现 | 每集独立声明集尾方式，终局节点不预设情绪结果 |
| 旧方案的阶段结构 | 阶段必须连续覆盖全剧并以大兑现结束 | 通用阶段只管理有效范围与里程碑，覆盖与兑现要求归策略 |
| script 的写作指南 | 快速冷开场、短台词、密集动作等作为通用纪律 | 保留可执行表达要求，创作节奏转入策略 |
| creation 的指南与默认参数 | 2–5 秒切镜、第一切主体运动等快节奏假设 | 镜头表达策略与模型生成限制分离 |
| references 加载 | 固定读取少数指南；已有按视频模型加载指南，但没有创作策略选择机制 | 增加本地策略发现、选择、应用和来源展示 |
| 视觉风格 | 已通过 `production.json.style` 提供完整正文 | 复用现有机制，不建立第二份视觉风格来源 |

creation 的镜头时长上下限已经允许参数覆盖。本次补齐的是策略到参数的传递、指南切换和一致性检查，不把现状描述成完全不可配置。

### 2.2 应保留的工程改进

- JSON 为唯一编辑源，Markdown 和 HTML 为派生视图。
- 人物、场景、道具与剧情节点使用稳定 ID。
- 大纲重要事件在剧本中按 ID 定位，不能仅按类型名称认领。
- 保留 `episodes[].scenes[].flow`，动作与台词结构不改为分镜。
- 上游集号、目标时长、节点所属集与下游重新对账。
- 场次、节拍、镜头和生成段各有职责，不把制作调度塞回大纲。
- 字段、引用与顺序检查和内容评审分别汇报。
- 骨架阶段、独立运行、缺少上游均明确说明验证边界。

## 3. 稳定层与可变层

| 层级 | 保持稳定的内容 | 可替换的内容 |
| --- | --- | --- |
| 工作流 | 参数确认、读取策略、创作、校验、评审、修订、交付 | 每一步采用的创作方法 |
| 数据契约 | ID、引用、场次、节拍、资产、目标时长、版本 | 事件内容、题材标签、台词、视觉正文 |
| 基础校验 | 类型、引用存在、位置有效、跨阶段身份一致 | 不允许关闭 |
| 策略校验 | 固定的规则接口与计算实现 | 启用状态、严重程度、阈值与适用范围 |
| 内容评审 | 引用具体证据，区分事实与判断 | 题材、风格、节奏对应的评价问题 |
| 制作适配 | 模型能力与调用契约 | 模型、画幅、分辨率和合法生成参数 |

“框架稳定”不等于永远不升级 schema。本轮先完成一次必要的通用化；以后在已支持的规则能力内新增策略，只增加 references，不修改主流程、schema 和校验代码。

新策略若需要新的数据语义或新的确定性计算，必须明确提出框架扩展，不能通过任意 JSON 字段、提示词或可执行代码绕过契约。

## 4. 创作维度与项目选择

### 4.1 维度分工

| 维度 | 示例 | 管理位置 |
| --- | --- | --- |
| `genre`：题材方法 | 悬疑、爱情、生活 | 创作策略选择及各阶段 references |
| `narrativeStyle`：叙事风格 | 克制、温暖、荒诞 | 创作策略选择及各阶段 references |
| `structure`：故事结构 | 连续故事、单元故事 | 创作策略选择及大纲／剧本 references |
| `pacing`：节奏 | 密集兑现、渐进累积、舒缓推进 | 创作策略选择及大纲／剧本／视频创作 references |
| 视觉风格 | 真人实拍、水墨、黏土 | 现有 `production.json.style` |
| 制作约束 | 画幅、模型、分辨率 | 现有 `production.json.image/video` |

本轮每个创作维度选择一份 profile。混合题材可填写作品描述，或提供一份组合后的题材 profile；不引入任意数量 profile 叠加、继承链和隐式优先级。

竖屏不能自动选择密集兑现。悬疑不能自动选择慢热。视觉写实不能自动要求快剪。用户可以组合不同维度，冲突必须显式处理。

### 4.2 项目选择入口

在 `production.json` 增加可选 `creative`，与现有视觉 `style` 分开：

```json
{
  "creative": {
    "version": 1,
    "selection": {
      "genre": { "id": "mystery", "version": "1.0.0" },
      "narrativeStyle": { "id": "restrained", "version": "1.0.0" },
      "structure": { "id": "serial", "version": "1.0.0" },
      "pacing": { "id": "gradual", "version": "1.0.0" }
    }
  }
}
```

- `creative` 只保存选择，不复制各阶段全部阈值和指南正文。
- 版本必须明确，不保存 `latest`、版本范围或随运行变化的别名。
- setup 负责写入和检查选择结构，不跨目录读取其他 skill 的策略文件，也不保证每个阶段已经安装对应实现。
- 消费阶段负责验证自己需要的本地策略是否可用。
- 全新项目没有选择时，提出组合建议并确认；自动驾驶下依据材料作出明确选择并汇报，不能默认为密集兑现。
- 既有项目缺少 `creative` 不自动获得任何新策略，不以“兼容”为名套入新的创作限制。
- `params.genre` 可以保留为作品题材描述，不作为程序分支条件，也不与 profile ID 互相猜测转换。

### 4.3 参数的唯一来源

| 内容 | 唯一编辑来源 |
| --- | --- |
| 项目想采用的创作组合 | `production.json.creative.selection` |
| 当前大纲的有效叙事规则与生成默认值 | `outline.json.params.rules` 与 `params.defaults`，分别保存检查规则和生成默认值 |
| 当前剧本的有效表达与估时参数 | `script.json.params` |
| 当前分镜的有效镜头表达参数 | `creation.json.params` |
| 全剧节点、阶段、悬念与结局计划 | `outline.json` |
| 视觉正文与制作模型 | 现有 `production.json.style/image/video` |

profile 是模板，不是第二份实时生效配置。显式应用后，参数写入上述指定位置。校验器只检查当前产物中的有效参数及所提供的上游，不在 render/validate 时重新合并 profile 默认值。

大纲节奏规则不复制到剧本和分镜。下游通过大纲节点消费其结果；台词与镜头的本阶段表达规则在各自产物中保存。

## 5. References 策略格式与加载

### 5.1 本地文件组织

以需要应用策略的 skill 为单位，建议组织如下：

```text
references/
├── schema.md
├── profile-contract.md
├── review-core.md
├── 原有通用阶段指南.md
└── profiles/
    ├── genre/<id>/<version>/profile.json
    ├── genre/<id>/<version>/guide.md
    ├── narrative-style/<id>/<version>/...
    ├── structure/<id>/<version>/...
    └── pacing/<id>/<version>/...
```

- profile 发现通过扫描本 skill 的 `references/profiles/` 完成，不在脚本中写题材 ID 的 switch，也不要求修改 `SKILL.md` 才能发现新 profile。
- 使用 JSON 和 Markdown，Node 标准库即可解析，不增加 YAML 或模板引擎依赖。
- 路径必须限定在本 skill 的 references 内，不允许绝对路径、目录逃逸或通过符号链接读取目录外文件。
- 同维度、同 ID、同版本重复出现时拒绝，不以目录遍历顺序决定结果。
- 不建立仓库根共享运行库。各 skill 保存自身所需的解析代码、契约说明、指南和测试。

### 5.2 Profile 内容

每份 `profile.json` 至少包含：

- `profileSchemaVersion`：本轮固定为 1。
- `dimension`、`id`、`version`：明确身份。
- `stage`：本份实现所属阶段。
- `guide`：相对于 profile 目录的 Markdown 路径。
- `rules`：本阶段支持的规则对象，可以为空；键名与参数见第 7.1 节。
- `defaults`：可选的生成默认值对象；本轮仅 outline 支持 `questionResolveWithin`。它不是校验规则，不带 level，不回写既有问题。

`guide.md` 应包含：适用目标、表达方法、应避免的做法、正反例、内容评审问题及来源说明。不得要求修改基础字段、忽略上游计划或关闭基础检查。

题材与叙事风格可以只有指导正文，不强行制造数值。结构主要配置集尾、阶段和问题解决要求；节奏主要配置兑现频率、开场位置、台词和镜头建议。

不同 skill 中相同 profile 身份表示同一套创作选择，但各自指南只描述本阶段职责，不复制整套兄弟指南。

### 5.3 组合与冲突

1. 先检查版本、字段和本阶段支持的规则键。
2. 按第 7.1 节注册键合并。每个 `rules.<key>` 的完整对象是一个比较和替换单位；每个 `defaults.<key>` 的完整值是一个单位。不合并规则内部字段。对象键顺序不影响相等性，集尾模式数组按集合比较；重复元素拒绝。不同键可组合，同键同值可接受，同键不同值报告冲突。
3. 不按照加载先后覆盖。用户须显式选择本项目的覆盖值，或修改 profile。
4. 用户覆盖写入阶段有效参数，并在应用结果中列出；不能声称仍按模板原值通过。
5. 技术能力限制和基础数据契约不能被用户覆盖或创作 profile 放宽。
6. 自然语言方法的冲突由内容评审指出，不宣称脚本已经判断全部风格相容性。

仅处理已声明的规则能力。未知规则键、未知级别、非法参数或无法支持的版本必须报错，不能静默忽略。

### 5.4 加载、应用与来源记录

outline、script、creation 增加同口径的策略发现、查看和显式应用入口；具体命令参数在各自 schema/CLI 文档中统一，不创建另一套后台服务。

显式应用统一执行以下流程，不另设一套覆盖处理流程：

| 步骤 | 操作与限制 |
| --- | --- |
| 读取 | 读取项目选择，或独立模式下提供的选择；按第 5.5 节确定本阶段必须加载的维度 |
| 解析 | 加载匹配版本的本地 JSON 与指南，检查身份、规则参数、来源漂移与组合冲突；缺失必需文件或无法解决的冲突时停止 |
| 重建 | 从中性基线重建本阶段注册参数：规则均为 `{ "level": "off" }`，生成默认值为 null，再应用新组合。不在旧参数上增量合并；未声明的旧阈值移除，空 rules 不表示沿用旧规则 |
| 展示差异 | 展示当前值、新组合值与已有覆盖。未记录的手工差异同样列出。集数、目标时长、资产预算、估时和技术参数不属于此次重建范围，保持不变 |
| 确认覆盖 | 用户逐项选择保留、放弃或重新填写完整规则／默认值。旧覆盖不自动沿用；自动驾驶下同样逐项决定并汇报。仅记录覆盖路径，数值仍取有效参数 |
| 整体写入 | 先备份原产物，再整体写入本阶段参数与 creativeContext。取消、配置错误或写入失败不留下半新半旧文件；未成功写入前不更新来源记录 |
| 重新检查 | 检查本阶段及已知下游，报告失效项；不自动重写故事。故事不满足新策略属于应用后的检查结果，不伪称应用已经修复内容 |

同一组合重新应用和更换组合都执行上述流程。`validate/render` 不执行应用步骤。报告只称“当前有效配置”，不能仅凭来源 ID 宣称“模板默认策略通过”。

`creativeContext` 的字段职责固定为：

- `selection`：本次应用的完整四维选择快照；不是第二个项目选择入口。有 production 时与项目选择对账，不匹配表示待同步。
- `references`：仅保存本阶段实际加载的 profile 身份、stage 和 SHA-256 摘要，不为未加载维度伪造来源记录。摘要覆盖描述文件与指南，序列化和文件顺序在契约中固定。
- `overridePaths`：只保存完整规则或默认值路径，例如 `params.rules.cutDuration`；不记录内部字段路径，不复制数值。已确认的覆盖从当前有效参数读取。

来源处理按操作类型区分：

| 情况 | 已有产物 validate/render | 继续创作或显式应用 |
| --- | --- | --- |
| 必需 profile 未安装 | 按已有有效参数检查，提示来源不可核验，不冒称已核验来源 | 安装所选版本，或明确升级选择；不能换成相似策略 |
| 同身份、同版本的内容摘要变化 | 按已有有效参数检查，提示来源漂移，不重算参数、不更新摘要 | 禁止以确认差异为由接受原版本的新摘要；必须恢复原文件，或创建新版本并更新选择 |
| 明确升级到新版本 | 旧产物可读，项目选择对账显示待同步 | 加载新版本并执行完整应用流程，成功写入后才更新快照与摘要 |

恢复原文件且摘要重新匹配后，可以按原版本继续。升级允许替换已漂移的旧来源，不要求先恢复旧文件。独立模式更新本次显式选择；项目模式先更新 production 的选择，随后逐阶段应用。

来源不可核验和内容漂移属于历史读取的来源提醒，不阻止按既有参数执行结构检查，也不计入结构通过项；项目选择不匹配则不能宣称完整联合交付。摘要只识别来源变化，不证明创作质量，也不建立永久版本注册库。

### 5.5 各阶段消费范围

下表为本轮固定的 stage × dimension 适用矩阵，加载器不得根据“本地恰好存在文件”改变消费范围：

| 阶段 | genre | narrativeStyle | structure | pacing |
| --- | --- | --- | --- | --- |
| setup | 仅记录 | 仅记录 | 仅记录 | 仅记录 |
| outline | 必须加载 | 必须加载 | 必须加载 | 必须加载 |
| script | 必须加载 | 必须加载 | 必须加载 | 必须加载 |
| creation | 必须加载 | 必须加载 | 仅记录 | 必须加载 |
| characters | 仅记录 | 仅记录 | 不适用 | 不适用 |
| art | 仅记录 | 仅记录 | 不适用 | 不适用 |

- **必须加载**：应用和继续创作时读取本 skill 的所选版本 JSON 与指南，加入本阶段 references 来源列表；缺失时失败。有实际指导正文、rules 为空的 profile 合法，不算空占位。
- **仅记录**：读取选择作为项目身份或表达背景，不加载该维度的本地 profile，不生成规则或 profile 摘要。setup 记录目标选择；其他阶段使用已提供的项目背景，不因此新增第二份选择入口。
- **不适用**：本阶段不解释该维度、不加载文件、不执行规则。无需创建占位 profile；仍可读取上游实际故事和资产内容。

outline/script/creation 的 creativeContext.selection 均保留完整四维快照，用于项目身份对账；references 列表仅包含“必须加载”的维度。例如 creation 记录 structure 选择，但无需 structure 文件，其集尾表现直接遵循剧本 ending。

characters/art 本轮不增加独立的 profile 应用流程或 creativeContext，继续从 production.style 消费视觉正文。需要补充题材或叙事风格方法时，作为各自通用指南引用的本地参考材料，不宣称已自动应用选定 profile；不能用通用方法替代缺失的视觉正文。后续若扩展为策略加载，须显式更新本矩阵和测试。

## 6. 通用数据契约

### 6.1 版本与产物

outline 与 script 采用明确的 `schemaVersion: 2`。缺版本的旧数据不能静默解释为新版。软件版本与数据版本分开。

目录保持：

```text
<工作目录>/
├── production.json
├── outline/
├── characters/
├── art/
├── script/
└── creation/
```

不增加第二份顶层创作配置文件。`.work/` 仍为临时草稿与评审材料，不成为下游依赖。报告 HTML 不进入版本控制。

### 6.2 Story：明确作品承诺，不强制单一胜利模型

大纲 `story` 保存：

- `focusCharacterIds`：主要叙事关注人物的有效 ID 数组，允许群像。
- `premise`：作品的核心处境。
- `throughline`：串联全剧的行动线、关系线或主题线。单元剧可以是共同人物与共同议题，不强制全剧只有一个任务。
- `audiencePromise`：希望观众持续获得或期待的体验，不限于爽感。
- `ending`：本次交付的结束方式和意义。
- `endingBeatId`：最终集中的有效剧情节点，不要求固定为兑现或 major。

具体主角目标、阻力、失败代价可以作为 `drive` 对象补充。哪些作品必须建立明确行动目标由策略指南与内容评审决定，不把所有故事强制改写成主角战胜对手。

`skeleton` 阶段允许暂缺 `endingBeatId`；节点阶段和完整阶段必须存在。开放结局也必须说明作品实际停在哪里，不能以“开放”掩盖未完成的交付。

### 6.3 剧情节点

保留统一 `beats` 表：

| 字段 | 通用要求 |
| --- | --- |
| `id` | `B` 加至少两位数字，全剧唯一且稳定 |
| `episode` | 所属集号的唯一来源 |
| `position` | `opening/early/middle/late/ending`，粗略表达区段，不等于五等分秒数 |
| `kind` | `event/pressure/turn/payoff` |
| `type` | 自由的题材化标签，不参与代码分支 |
| `setup` | 本事件承接的处境、材料或期待 |
| `outcome` | 实际发生的事件及后果 |
| `weight` | 仅 payoff 使用 `minor/major`；其他 kind 不填写 |
| `resolves` | 可选，解决的集尾问题 ID 数组 |

`event` 用于不属于施压、转折、兑现的重要事件，避免为了入表伪造爽点。不是要求为每个动作、每个氛围段都登记节点。

只有 payoff 参与兑现统计。一个事件同时转折并兑现时优先记为一个 payoff，不用多个近义节点虚增数量。重大性与语义重复仍由内容评审判断。

节点按集号、粗略位置和数组顺序组织。分集不重复保存节点编号列表。

### 6.4 分集与集尾

每集保留 `ep`、`opening`、`synopsis`、资产引用，新增中性的 `ending`。`stateChange` 可以表达处境、关系或认知变化，提供时必须为包含非空字符串 `before/after` 的对象；是否每集必须提供、是否拒绝完全相同的前后文本，由第 7.1 节 stateProgress 规则决定。文本不同不证明语义上确有推进。

集尾结构：

```json
{
  "mode": "suspense",
  "event": "调查者准备离开时，门内的人说出了失踪者从未公开的名字。",
  "question": {
    "id": "Q01",
    "text": "门内的人为什么知道这个名字？",
    "resolution": "required",
    "dueByEp": 4
  }
}
```

- `mode` 为 `suspense/closure/open`，分别表示悬念、收束、开放余味。
- `event` 必填，是实际结束事件，不是效果标签。
- suspense 必须提供 question；closure 禁止携带 question 字段；open 可以附问题，也可以只保留余味。
- `question.resolution` 为 `required/optional`。optional 表示允许在本次交付结束时仍未回答，须附非空 `reason`；不表示可以填写虚假的解决记录。
- `dueByEp` 可省略。填写时必须满足提出集 < 期限 <= 总集数；有明确期限即构成必须履行的承诺，不允许 optional 同时携带期限。
- 最终集不由框架强制 closure。允许哪些模式、是否允许 optional，由结构策略约束。

完整阶段：required 问题必须恰好由一个后续节点解决；optional 可以不解决，解决时仍须满足唯一引用和时间顺序。最终集不能声明本次交付内无法履行的 required 问题。

策略允许开放问题，不代表允许未知 Q、重复解决、提前解决或超出明确期限。无问题的作品不需要伪造 Q。

只跟踪主要集尾问题，不建立所有伏笔的数据库。新建 required 问题且未明确给出期限时，按 `params.defaults.questionResolveWithin` 填写实际 `dueByEp = min(提出集 + 默认值, 总集数)`；默认值为 null 时不自动添加期限。optional 问题不应用此默认值。切换默认值不重写既有问题，校验器只检查已写出的明确承诺。

### 6.5 阶段里程碑

`arcs` 可选，字段为 `id/startEp/endEp/goal/endBeatId`。

- 通用检查：ID、合法范围、按起始集排序、阶段不重叠、终点节点属于阶段结束集。
- 不默认要求覆盖全剧，不默认要求终点是大兑现。
- 是否连续覆盖、是否必须 major payoff，由策略规则决定。
- 本轮不支持重叠的多线阶段模型。需要该能力时单独扩展，不用放宽引用检查冒充支持。

### 6.6 角色、场景、道具与改编说明

- 保留现有资产 ID、角色来源、分档和引用。
- `characters[].from` 与改编合并决定职责不同，不合并成一个字段。
- `reusePlan` 为可选建议；一次性场景不再因没有复用方案失败。
- 删除大纲 `crowdPlan`。人物在场不等于多人同框，拍摄拆解属于 creation。
- `props[].beatIds` 可以引用任意节点，不限于兑现。
- 资产数量属于制作预算，不由题材名称硬编码。保留可配置上限和明确的生效值展示。
- 改编材料保留 keep/cut/merge/risks 与证据，来源不足须说明。原创样例明确标注原创，不伪造原作证据。
- 不新增手写顶层资产汇总，使用集数和关联类型均从当前数据计算。

## 7. 策略规则与基础校验

### 7.1 规则形状

每项检查规则使用 `level: off | warn | error`。关闭对象必须恰好为 `{ "level": "off" }`，不保留无效阈值；启用对象必须包含 level 和下表规定的全部参数，禁止未知字段。以下注册表是本轮规则键、存储路径和消费方式的唯一规范来源。

所有检查规则由 `profile.rules.<key>` 写入对应产物的 `params.rules.<key>`；冲突、覆盖和替换均以一个完整规则对象为单位。表中的“启用参数”不重复列出 level。

| 阶段 | 规则键 | 启用参数 | 检查语义 | 旧字段处理 |
| --- | --- | --- | --- | --- |
| outline | `payoffCoverage` | `minPerEpisode`：正整数 | 每集 payoff 数量下限 | 删除旧 maxBeatGap，不直接换算 |
| outline | `firstMajor` | `byEpisode`：正整数 | 必须有 major，首次不晚于 min(byEpisode, 总集数) | 新增 |
| outline | `majorGap` | `maxGap`：正整数 | 相邻 major 所在集号去重后的差值上限；不足两个时不适用 | 新增 |
| outline | `endingPayoff` | `minWeight`：minor/major | endingBeatId 必须为 payoff，强度不低于指定级别 | 新增 |
| outline | `endingModes` | `nonFinal/final`：非空、无重复的模式数组 | 各集 mode 位于相应允许集合，全集末集身份取 outline 集数 | 新增 |
| outline | `optionalQuestions` | `allow`：布尔值 | false 时不得出现 optional 问题 | 新增 |
| outline | `stateProgress` | 无额外参数 | 每集必须提供 stateChange，且 before/after 不得为完全相同文本 | 新增 |
| outline | `arcCoverage` | 无额外参数 | 提供非空 arcs 时要求连续覆盖全剧，否则不适用 | 新增 |
| outline | `arcPayoff` | `minWeight`：minor/major | 提供非空 arcs 时检查各终点 payoff 及强度，否则不适用 | 新增 |
| script | `openingWindow` | `maxBeats`：正整数 | openingBeat 不晚于全集第 maxBeats 拍 | 迁移旧 params.hookWindow 后删除旧字段 |
| script | `lineLength` | `maxChars`：正整数 | 按既有台词字数算法检查单句长度 | 迁移旧 params.maxLineChars 后删除旧字段 |
| creation | `cutDuration` | `minSeconds/maxSeconds`：有限正数，前者不大于后者 | 每个 cut 秒数位于闭区间内 | 迁移旧 params.minCutSeconds/maxCutSeconds 后删除旧字段 |

生成默认值单独登记，不伪装成可以 pass/fail 的检查：

| 阶段 | Profile 键 | 唯一有效路径 | 类型与消费时机 |
| --- | --- | --- | --- |
| outline | `defaults.questionResolveWithin` | `params.defaults.questionResolveWithin` | 正整数或 null；仅按第 6.4 节新建问题时消费，无 level；完整值为冲突与覆盖单位 |

规则参数中的正整数必须为有限数值，不接受字符串、零、负数或小数。minWeight 使用 minor < major 的固定顺序；模式仅允许 suspense/closure/open。缺少 arcs 与空数组均按未提供阶段处理。

应用完成的产物必须显式保存本阶段全部注册规则；未启用项写 off。outline 还必须保存 questionResolveWithin，包括 null。新契约校验拒绝缺失注册项和旧平铺字段，不在读取时补旧默认值。尚未应用的骨架只能作为不完整草稿，不能按完整配置交付。

旧字段只在迁移辅助步骤读取，level 由本次确认的策略决定；运行时不设新旧双读。同步修改 validate/checkup/render 的消费位置，必须删除旧 maxLineChars 和镜头上下限的无条件硬门，防止 off/warn 被旧检查再次阻断。语速、动作估时、时长容差与模型生成限制不迁入 rules。

以下是 creation 的完整 profile 输入示例。其他必需维度的 profile 在此例中只提供指南、rules 为空；当前非策略参数为 maxSegmentSeconds=15、maxOnScreen=3、tolerance=0.15，本次没有保留旧覆盖：

```json
{
  "profileSchemaVersion": 1,
  "dimension": "pacing",
  "id": "dense-payoff",
  "version": "1.0.0",
  "stage": "creation",
  "guide": "guide.md",
  "rules": {
    "cutDuration": { "level": "warn", "minSeconds": 2, "maxSeconds": 5 }
  }
}
```

显式应用后的完整 params 如下；creativeContext 按第 5.4 节另行记录，不包含参数副本：

```json
{
  "params": {
    "maxSegmentSeconds": 15,
    "maxOnScreen": 3,
    "tolerance": 0.15,
    "rules": {
      "cutDuration": { "level": "warn", "minSeconds": 2, "maxSeconds": 5 }
    }
  }
}
```

切换到未声明 cutDuration 的组合后，该规则整体变成 `{ "level": "off" }`，minSeconds/maxSeconds 不残留，非策略参数不变。真实 cut 的秒数仍须为有限正数并满足技术限制。

表达提示和自然语言评审问题只放 guide，不进入规则注册表。基础字段合法性与明确承诺始终检查：关闭悬念要求后，已经声明 required 的 Q 仍必须解决；关闭兑现下限后，已经声明 payoff 的字段仍必须完整。

### 7.2 首批组合的明确差异

初始策略采用以下约定，数值是可替换的创作起点，不是通用规律：

| 配置项 | 连续追更＋密集兑现 | 连续故事＋渐进累积 | 单元故事＋舒缓推进 |
| --- | --- | --- | --- |
| structure profile | `serial-cliff` | `serial` | `episodic` |
| pacing profile | `dense-payoff` | `gradual` | `measured` |
| 每集兑现下限 | error，至少 1 次 | off | off |
| 首次大兑现 | error，不晚于 min(3, 总集数) | off | off |
| 相邻大兑现间隔 | error，集号差不超过 5 | off | off |
| 终局大兑现 | error，最终节点为 major payoff | off | off |
| 非最终集集尾 | 仅 suspense | suspense/closure/open | suspense/closure/open |
| 最终集集尾 | closure | closure/open | closure/open |
| optional 问题 | 不允许 | 允许，必须说明理由 | 允许，必须说明理由 |
| 新问题默认期限 | 后续 2 集内，按总集数截断 | 不自动加期限 | 不自动加期限 |
| 每集 stateChange | error，必须填写 | error，允许认知或关系变化 | 不强制，但填写后检查结构 |
| 阶段全覆盖／阶段大兑现 | 不提供 arcs 时不强制；提供时检查全覆盖与 major 终点 | off | off |

集尾允许模式和 optional 许可由 structure profile 声明，均为 error 级；阶段覆盖与阶段终点规则由 structure 声明，serial-cliff 启用 error，其余为 off。兑现密度、终局兑现和进展要求由 pacing 声明。默认期限由 pacing 的 defaults 提供，不带 level。此表是组合结果，不把整列复制为一份不可拆分的大预设。

无明确期限的 required 问题仍须在本次完整交付内解决。默认期限不能为最终集生成不可能履行的承诺，应由集尾模式限制和基础校验明确拒绝。

题材与叙事风格分别选择，不在上述 profile 中写死。剧本与镜头指南随 pacing 切换：密集兑现可以建议较早进入事件和较短切镜；渐进与舒缓不继承这些要求。首批镜头范围作为 warn 级建议，实际取值按故事和模型能力确认，不恢复统一 2–5 秒硬门。

### 7.3 三类结果

1. **基础契约检查**：身份、类型、引用、范围、时长目标对账和已声明承诺的自洽性。
2. **策略检查**：按当前 level 和参数执行，失败或提醒取决于配置。
3. **内容评审**：通用因果／表达问题与本次策略特有的问题，引用具体集号和节点。

检查对象采用 `status: pass | fail | skipped`，同时保存检查类别与规则严重程度，不再维护可能矛盾的 `ok` 布尔值。

- 基础失败或 error 级策略失败使 validate/checkup 返回非零。
- warn 级策略未满足记录 `status=fail, level=warn`，界面显示“提醒”，不阻断交付，不计为通过；只有基础失败或 error 级失败计入阻断失败数量。
- off 规则为 skipped，原因 `policy-disabled`。
- 其他 skipped 原因分别为 `missing-upstream`、`stage-incomplete`、`not-applicable`。
- 缺少检查条件与策略不要求必须分开展示。
- 提供了损坏、版本不支持或不可读的上游时失败，不能退化成 missing-upstream。

语义评审是否执行单独说明。渲染器只展示结构事实与评审材料，不能自行生成“故事精彩”“内容评审通过”等结论。

### 7.4 分阶段运行

- `skeleton`：选择、参数、故事说明、资产、改编材料；暂不检查尚未创建的节点和分集。
- `beats`：增加节点、终局引用和适用的节点计划规则；未生成的集尾问题与真实分集检查明确跳过。
- `full`：全部数据契约与适用策略规则。

只有 full 完成且无阻断失败，才能按完整大纲交付。骨架通过不代表完整故事通过。

## 8. 剧本与视频创作联动

### 8.1 剧本通用字段

剧本继续使用场次与 `flow`，采用中性的 `opening/openingBeat/ending/endBeat`，不保留 hook/cliff/closure 并行结构。剧本 ending 的字段白名单只有 mode 和 event：

```json
{
  "ending": {
    "mode": "suspense",
    "event": "调查者准备离开时，门内的人说出了失踪者从未公开的名字。"
  }
}
```

mode 必须为 suspense/closure/open，event 必须是非空字符串；拒绝 question、questionId、dueByEp、resolves 及其他额外字段。它是上游意图的投影，不是另一份问题计划。

seed 映射固定如下：

| 来源 | 剧本字段 | 行为 |
| --- | --- | --- |
| 大纲本集 opening | opening | 字符串原样搬运 |
| 大纲本集 ending.mode | ending.mode | 枚举原样搬运 |
| 大纲本集 ending.event | ending.event | 字符串原样搬运 |
| 大纲本集 ending.question | 无 | 不复制、不另建引用字段；报告按 ep 查询上游 |
| 大纲本集节点 ID | beatClaims[].beatId | 按大纲顺序搬运，start/end 留 null |
| 尚未编写的正文 | scenes、openingBeat、endBeat | scenes 为空数组，两个位置均为 null，不伪造落点 |

`openingBeat` 为 1 起始的 `[场次序号, 场内节拍序号]`；`endBeat` 使用相同坐标，必须指向本集最后一拍。完整剧本不接受空位置；开场窗口由 openingWindow 控制，不能用关闭窗口代替有效坐标。

校验分工：

- 无 outline：检查 opening 非空、ending 白名单／类型、位置合法和本地策略。剧本 suspense 不要求 question；不能套用大纲 ending 的字段规则。Q 计划、全剧末集身份和上游意图一致性对账均跳过。
- 有 outline：先按 ep 找到上游，再严格对账 opening、ending.mode 和 ending.event 的值；不以同义改写或批次末集身份代替对账。要调整计划先修改大纲，再重新投影。实际表现可以在 flow 中改写，不要求台词逐字复述计划。
- Q 的提出、期限和解决完整性归 outline 检查；script 不维护第二套 Q 表。报告通过上游 resolves 所在节点和 beatClaims 定位实际正文，内容评审核对是否真的回答问题。
- openingBeat/endBeat 指向的动作、台词是否表达开场／集尾意图，由内容评审判断，不用位置合法冒充语义正确。creation 直接消费上述 mode/event，不补造 Q 或追更悬念。

### 8.2 按 ID 认领节点

`beatClaims` 使用 `beatId/start/end`，范围为包含两端的实际节拍坐标。

- 当集所有大纲节点分别认领，包括 event、pressure、turn、payoff。
- 禁止漏领、多领、错集、重复 ID、无效端点和倒序。
- 本轮采用按大纲顺序排列、互不重叠的核心表现段；共同铺垫可以在认领范围之外，允许同集跨场次。
- 不要求一个节点占一整场，不因共享铺垫强行拆场。
- 报告并排显示节点 setup/outcome 与实际动作、台词。
- 核心段存在不证明语义落地，必须内容评审。

该契约支持按明确表现顺序组织的事件计划，不宣称覆盖需要交织、重叠认领的全部实验叙事。本轮不增加第三个决定性位置字段，也不以 profile 关闭非重叠检查。

### 8.3 时长与内容保护

- 提供 outline 时重新对账每个 ep 和 `targetSeconds = minutesPerEpisode × 60`，不能只信 seed。
- 剧本实际估时与目标容差是另一项检查，不能用于放宽上下游目标差异。
- 保留现有语速／动作估时参数与同一估时函数。显示逐拍估算时间轴，不声称是真实表演时间。
- 开场位置、节点范围与集尾时间均由相同累计方式计算。
- 有 outline 时才能确定哪些认领段是 payoff；无 outline 时不猜测分类。
- 不新增统一秒级爽点硬门。

删除“写超先删除动作”“开场必须运动”等通用纪律。压缩顺序为重复表达、无效过渡、不影响因果的动作，保护关键证据、人物选择和结果。仍无法容纳时回到 outline 修订事件或时长。

台词密度、停顿、VO 使用和动作频率由策略指导，不把全部作品改成同一种快速口语。

### 8.4 视频创作

- 保留 segment/cut、节拍认领、参考图挂载、通用提示词骨架和模型指南。
- 模型合法时长、参考图与提示词接口属于技术限制，创作策略不能放宽。
- 镜头表达范围统一读取 `params.rules.cutDuration`，按 level 处理；旧 minCutSeconds/maxCutSeconds 只在迁移时读取。2–5 秒不是所有短剧的硬规则。
- “第一切必须主体运动”“三秒一切”“每段末尾必须悬念”移出通用指南，只能成为具体策略建议。
- 停留、观察和缓慢镜头在技术范围允许时可以通过，不因缺少密集剪切判为失败。
- 若希望的长镜头超过模型单次能力，明确限制并调整制作方案；不能把多次生成包装成已经保证连续长镜头。
- 模型提示词指南与创作指南分别加载，模型选择不替代创作策略，创作策略不改写模型接口。
- 最终集的开放余味或收束，不应在下游被重新改成追更悬念。

## 9. 工作流、独立运行与切换

### 9.1 通用流程

1. 读取项目与输入材料，确认集数、时长和创作选择。
2. 加载本阶段通用契约与对应策略指南，应用本阶段参数。
3. 先确定故事方向和样例故事，再安排重要事件。
4. 建立骨架，执行该阶段检查并确认方向。
5. 分批创作，传递已发生的状态、信息与后续约定。
6. 执行基础检查与策略检查。
7. 执行通用内容评审及选定策略评审。
8. 修订并重新检查，生成 Markdown/HTML，分别汇报检查与评审状态。

保留 outline 每批最多 10 集、script 每批最多 3 集。默认顺序衔接；只有边界状态与跨批次承诺明确时才允许并发。

自动驾驶只转移审批权，不取消策略确认记录、结构检查、内容评审、费用告知或失败止损。

### 9.2 独立运行

- 单独拷走一个 skill，连同自己的 references、脚本和样例即可运行。
- 没有 production 时，可以显式提供创作选择，应用到本地产物并记录 creativeContext；不能依赖兄弟 skill 才能生成骨架。
- 已有产物可以按其有效参数独立校验。缺少 outline/art 时，仅跳过真正依赖上游的对账，本地类型、位置、重复与时长检查继续执行。
- 无 production 的独立模式不能声称与项目级选择一致；无 outline 的剧本不能声称全剧节点和结局已对账。
- 完整联合交付必须完成上游对账与项目选择对账，不以独立模式的零退出码替代。
- 角色和美术生成仍需要合法视觉参数；创作 profile 不能作为缺失画风的隐式默认值。

### 9.3 切换策略与失效范围

切换不是只修改报告标签：

| 变化 | 必须重新处理 |
| --- | --- |
| 题材、叙事风格、结构、节奏选择 | 显式应用相关阶段；重新评审故事、剧本与分镜，重新校验已生成产物 |
| 仅调整本阶段规则参数 | 显示覆盖，检查本阶段及实际受影响下游 |
| 视觉 style | 核对角色／美术提示词和参考图，按影响决定重出资产及视频 |
| 视频模型与画幅 | 重新读取模型指南、核对生成限制、提示词和投产包 |
| reference 模板升级 | 不自动改变旧产物；明确升级版本并显式应用 |

跨阶段身份采用同一套项目 selection 对账；各阶段内容摘要只用于本地实现来源，不要求兄弟 skill 的文件摘要相同。

下游仍引用原节点 ID，不为换策略无差别重编号。事件真实删除或重写时更新对应认领并报告失效，不能仅调整标签让检查通过。

## 10. 报告与评审

### 10.1 报告信息

优先展示：

1. 作品承诺、创作组合、当前有效参数与覆盖项。
2. 故事／分集／剧本正文。
3. 当前策略关注的视图：兑现、信息推进、阶段或集尾方式等。
4. 上游计划与实际文本／位置的对应关系。
5. 资产清单、制作限制和估算说明。
6. 基础检查、策略检查、提醒、跳过原因、内容评审状态。

不再固定把“爽点密度”作为所有类型的首页 KPI。相同通用图表可以继续展示事件与引用，但没有启用的策略指标不显示成缺陷。

### 10.2 评审分工

通用评审检查：来源可信、人物行为有依据、事件与结果连贯、叙事信息可理解、跨批次状态一致、上下游实际表达相符。

策略评审检查：选定题材的期待、叙事风格的表达方法、结构承诺、节奏是否有效。慢热不等于空转，开放不等于遗漏，密集不等于重复计数。

内容判断必须引用集号、节点或实际台词，不记录永久总分、爆款概率或失败历史。评审过程材料放当前工作记录或 `.work/`。

界面文本正常转义。中文标签使用完整词语。导出 JSON 与输入保持一致，不偷偷写入默认值、统计或评审结论。

## 11. 迁移与兼容

1. 实施前备份真实旧产物，不原地盲目转换。
2. 新旧数据采用明确版本边界，不建设长期双语义解析层。
3. 旧节点逐个判断 event/pressure/turn/payoff，不能把旧爽点全部自动认定为兑现。
4. 重建 story 和实际集尾方式，不能仅重命名 hook/suspense。
5. 旧 `beatsClaimed` 不能可靠映射多个同类节点，必须按 ID 和真实文本重新认领。
6. 旧 pacing/阈值不直接换算成新策略；先确认希望采用的创作组合，再应用有效参数。
7. 旧剧本的 hookBeat 仅可作为 openingBeat 候选，必须核对内容；重新填写 ending/endBeat。
8. 更新 creation 参数与指南来源，防止上游舒缓、下游仍默认快剪。
9. 重新校验并渲染所有受影响产物；不把迁移成功称为内容评审通过。

outline/script 的软件主版本建议升级到 2.0.0；setup、characters、art、creation 按实际破坏性变化决定版本。每个直接消费者必须声明自己接受的字段和数据版本。

只提供结构搬运辅助，不新增自动“语义迁移”。旧文件可由旧提交读取；新版拒绝时给出该 skill 自己可携带的迁移说明。

## 13. 样例与测试计划

### 13.1 故事先行

每个 skill 的正式样例使用自己的故事、原文或本地上游夹具。先确认故事提案，再写原文、事件与剧本，不为了覆盖字段倒推人物动机，不提前出分镜图。

不把 outline 的正式故事复制给 script 作为其正式样例。跨阶段字段传递测试使用隔离目录中的同一故事 fixture，与各 skill 正式样例分开。

### 13.2 三种组合验收

| 组合 | 必须表现的差异 | 不能靠什么通过 |
| --- | --- | --- |
| 连续结构＋密集兑现 | 每集兑现、阶段大兑现、普通集悬念，终局兑现 | 重复事件、多次认领同一结果 |
| 连续结构＋慢热悬疑 | 至少一集没有 payoff，仍有有效信息或处境推进；允许更长的揭示周期 | 把施压改名为兑现、超大阈值伪关闭 |
| 单元结构＋舒缓生活 | 至少一个非最终集 closure；单元可独立完成；镜头可在模型能力内持续观察 | 伪造追更问题、强制三秒切镜 |

三种组合使用相同的核心 schema、seed、validate 和 render 实现。差异由 references、项目选择、有效参数与故事内容产生，不允许按 profile ID 在代码中分支。

### 13.3 策略解析与应用

- 新增一个合法 profile 目录后可被发现，不修改主流程或代码。
- 必须加载的 profile 缺失／重复身份、错误版本、未知字段、未知规则、目录逃逸、缺失指南均失败。
- 按阶段矩阵测试：creation 缺 structure 文件仍可应用；缺 pacing 必须失败；characters/art 不因缺少本地创作 profile 失败，也不伪造来源摘要。
- 同一规则对象的内部字段不能从不同 profile 拼接；同键不同值冲突，明确覆盖完整对象后才可应用。对象键顺序与模式集合顺序不制造假冲突。
- off/warn/error 的边界和退出码正确。
- 缺 production 可独立应用；提供损坏 production 不冒充缺失。
- 修改 reference 不改变既有产物参数；显式应用才改变。
- 密集兑现切换为未声明兑现规则的策略后，旧下限恢复 off，旧阈值移除；空 rules 不能保留旧限制。
- 旧覆盖分别验证明确保留、明确放弃与取消应用；未记录的手工差异进入预览，取消或错误不改原文件。
- 策略切换不改集数、目标时长、资产预算、估时参数和技术配置。
- 同版本内容变化后，历史校验／渲染仅提示来源漂移，不改参数或摘要；同版本确认差异后重写摘要仍须拒绝。
- 恢复原文件可继续原版本；创建新版本并更新选择后可应用，旧文件无需先恢复；取消或写入失败不更新摘要。
- 未安装原 profile 的已有产物仍可按参数校验；新应用缺少必需 profile 失败，版本改变后旧产物明确待同步。
- 不同 skill 本地文件摘要不同不会被误判为项目选择不一致。

### 13.4 基础契约与策略不可越权

- 非法 ID、未知引用、重复节点、错误集号、无效位置始终失败。
- 关闭逐集兑现要求后，合法无 payoff 分集通过；开启后对应分集失败。
- 未启用悬念要求时，无 Q 的 closure 通过。
- optional 问题按策略可保留；required 未解决、未知 Q、重复解决、提前解决或超期均失败。
- 最终集开放模式按策略通过或失败，不固定要求 major payoff。
- 阶段不全覆盖在通用层合法，启用全覆盖策略后按规则检查。
- 用户覆盖不能放宽模型能力、引用完整性或上游目标时长对账。
- 注册规则缺失、off 携带阈值、错误类型和旧平铺字段均拒绝；lineLength/cutDuration 关闭或警告时，旧硬门不能再次阻断。
- questionResolveWithin 只作用于新建且未指定期限的 required 问题；null、optional、既有问题和明确期限均不被自动改写。
- warn 未满足记录 fail 但不计入阻断失败；其结果不得计为通过。

### 13.5 上下游与内容落点

- 同集同类型不同 ID 必须分别认领；漏领、多领、错集、重复、越界、倒序、重叠均失败。
- 共用铺垫、同场多个节点、同集跨场次核心段通过。
- 开场窗口关闭后不要求前若干拍；openingBeat 本身仍须有效。
- endBeat 必须是最后一拍；普通集收束和最终集开放都能传递到 creation。
- seed 只复制 opening、ending.mode/event，不复制 Q；剧本 ending 多余字段拒绝，无 outline 的 suspense 不因缺 question 失败。
- 有 outline 时开场／集尾投影值变更必须报错；flow 可以采用不同表达，由内容评审判断，不能用字符串对账证明表演成立。
- 大纲时长变更后，剧本旧目标必须失败；不能靠估时容差绕过。
- 缺上游为明确 skipped，损坏上游为失败；独立通过不宣传联合通过。
- 所有估算使用同一函数，无效范围不按零秒计入图表。
- 慢节奏镜头配置传到 creation，不被旧指南重新写成快剪。

### 13.6 自包含、渲染与回归

- 各 skill 单独拷贝到隔离目录后，自己的样例与自测可运行，不访问兄弟目录。
- 移除原有 script 自测对兄弟样例的读取。
- 视觉正文、参考图挂载、模型提示词约束、现有生产参数仍然有效。
- Markdown、HTML、中英界面、合并报告、导出原始 JSON、转义与交互覆盖。
- 基础检查、策略提醒、关闭规则、缺上游和内容未评审不会混成“全部通过”。
- 浏览器检查窄屏报告、节点对照与策略信息；未执行时明确标注。
- 测试不调用付费模型、不生成真实图片或视频。只清理本轮隔离资源，不删除历史产物。

## 14. 实施顺序与完成标准

### 阶段 A：冻结通用契约和策略接口

- 将第 5 节的阶段适用矩阵、来源漂移解除路径和 creative/profile/creativeContext 固化为本地契约与测试夹具。
- 将第 6、8.1 节的通用数据与剧本集尾投影固化为字段白名单、seed 映射和独立／联合校验规则。
- 按第 7.1 节注册表固定实际存储路径、完整对象冲突语义和旧字段迁移，列出旧硬门的全部消费位置，不能只增加新包装。
- 确认三种组合的行为矩阵与各 skill 自有故事方向。

完成标准：不存在把密集兑现当隐式默认的字段；不存在两处可编辑的同一有效参数；不读取兄弟 skill 的策略文件。

### 阶段 B：实现策略应用和联合数据接口
