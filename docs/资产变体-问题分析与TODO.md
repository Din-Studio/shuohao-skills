# 资产变体：问题分析与 TODO

> 背景：设定图准则从 assets skill 拆分进 mint-characters 和 mint-art 时，约束为 cast v1 和 art v1 的数据结构不变。变体是受这条约束影响最大的部分。本文记录现状、问题和后续改法。
> 现行版本：outline 5、script 4、production/creation 3、cast/art 1。

## 一、assets 原规则对变体的要求

| 资产类型 | 什么算变体 | 出图方式 | 保持什么（只点名，不重写描述） | 只改什么 |
| --- | --- | --- | --- | --- |
| 人物 | 剧本里出现的另一种稳定外观：换装、伤痕、湿透、憔悴、跨年龄 | 以基准图为参考，整张重新出图，脸部特写和三格一起换 | 五官、脸型、肤色、瞳色、身高体型、版式 | 服装、配饰、发型、伤痕、污渍等可见状态；单侧特征需要时写明画哪一侧 |
| 群演 | 规则里没有单列 | — | — | — |
| 场景 | 光的状态持续变化（开灯、关灯、天色变化），或者空间状态变化（破损、陈设变化） | 四宫格整张重新出图，平面图不变 | 建筑结构、布局、四个方向的视角、家具位置和数量、平面图 | 天色、光影锁、剧本写了的空间状态 |
| 道具 | 破损、燃烧、浸湿、打开、带血等状态 | 三格整张重新出图 | 版式、结构、材质、形状、比例、颜色、右格的手或人 | 变化后的状态 |

几条共同原则：

- 变体以基准图为参考，由四块组成：照抄块、指向参考、保持什么、只改什么。
- 一张设定图只画一种稳定外观，不写跨集状态的概括。
- 设定图只画这个变体的光影锁；镜头使用哪个变体，就挂载哪张参考图。
- 未成年人物的睡衣、泳装、湿透等状态不出变体图，在条目里写明不出图和理由。

## 二、现状（拆分后）

| 资产类型 | 数据里怎么表示 | 出图计划 | 下游能否引用 |
| --- | --- | --- | --- |
| 人物 | **无法表示**。cast v1 每个身份只有一个 `image` 块；变体写法只作为备用说明写在 `sheet-prompt.md` 里 | 只有基准图 `images/<C ID>-sheet.png` | script 场次只写 C ID，creation 固定挂载基准图 |
| 场景（方式一） | 新建一个 S ID，写 `variantOf` 和 `changes` | 独立任务，依赖母场景的成图 | 可以引用：script 通过 `assetMappings` 映射到变体的 S ID，creation 挂载它的 sheet |
| 场景（方式二） | 同一场景的 `lighting[1..]`，只有文字 | **不出图** | script 场次的 `lighting` 文本可以引用，`refs-scenes` 门会核对状态名；creation 仍挂载 `lighting[0]` 画的基准图 |
| 道具 | `states[0]` 是基准，`states[1..].prompt` 是完整的变体提示词 | 任务 `P01.s2`，文件 `images/<imageStem>-state2-sheet.png`，依赖基准图 | **不能引用**。script 场次只写 P ID，creation 只解析 `<imageStem>-sheet.png` |

样例《雨棚留言》的当前数据：

- S01 有两个光照状态：「阴天清晨·天光」「傍晚·天光」，第二个不出图。
- S03 是 S01 的变体，状态为「夜·路灯」。
- P01 有「夹纸未取」「归还整理」两个状态，P02 有「盒盖合上」「分类打开」两个状态。两个道具的第二个状态都会进入出图计划。

## 三、问题清单

### A. 表示层

**A1　人物变体无处可放（严重）**

- 换装、受伤、湿透、跨年龄是短剧最常见的连续性需求。题材参考里也有很多现成例子：末世题材的「据点 / 外出」着装、古装题材的「初始 / 过渡 / 高位」、霸总题材的「通勤 / 居家 / 礼服」。
- 现在只能出一张基准图。镜头里人物受伤以后，视频模型拿到的仍是没有伤的参考图，伤只能靠文字描述，每个镜头的伤都可能不一样。
- 唯一的「绕法」是给同一个人另建一个身份。这违反 characters 的身份契约（同人不拆分），而且会改变 C ID 映射和预算。

**A2　场景变体有两套表示，而且混进了身份层**

- 同一件事（同一空间换光、换状态）可以写成 `variantOf` 新 S ID，也可以写成 `lighting[n]`，选哪种全凭写手判断。这接近 CLAUDE.md 禁止的「同一份数据同时接受两种格式」。
- `variantOf` 会占一个 S ID，进入 registry，计入 `scenes` 预算，单独做 identityReview。这和 art 自己的原则「场次不是地点身份，同一空间的晨晚、清空状态不自动建立新地点」相矛盾：变体本来是外观，不是身份。
- assets 的定义是「平面图不变，只改天色、光影锁、空间状态」，正好就是同一身份的另一种外观。

**A3　道具状态没有稳定 ID（会导致图片错配）**

- 任务 ID 和文件名按数组序号计算（`P01.s2`、`-state2-sheet.png`）。在中间插入一个状态、删掉一个、调整顺序，`state2` 就会指向另一个状态，已经生成的图会挂到错误的状态上。
- 身份层坚持「不按出现次序编号、退役 ID 不复用」，状态层却按序号编号，前后标准不一致。
- `inputDigest` 包含整个道具对象，所以内容变了计划能发现，但旧文件名下的图片不会被识别为「过期」。

**A4　变体没有来源和使用范围**

- `lighting[]`、`states[]` 只有 `{state, prompt}`，没有 `sourceRefs`，也没有记录使用它的集和场。
- 无法核对「这个状态是剧本写的还是写手设计的」（违反全局原则的「估与设计」分开记），也无法核对「第 5 集第 2 场该挂哪个状态」。

### B. 消费层

**B1　script 无法指定人物和道具的状态**

- 场次里 `characters`、`props` 只有 ID 数组，只有场景能通过 `lighting` 文本指定一种状态。
- 即使 art 出了道具状态图，script 也说不出「这一场的留言板是归还整理状态」。

**B2　creation 只挂载基准图（道具状态图成了孤儿）**

- `mint-creation.mjs` 的参考图解析只认 `../characters/images/<C ID>-sheet.png` 和 `../art/images/<stem>-sheet.png`。
- 这次新增的道具状态任务会真的花钱出图，但没有任何下游环节读取它们。

**B3　光照状态和参考图不一致**

- script 写「傍晚·天光」时，`refs-scenes` 门判定通过，但 creation 挂载的是「阴天清晨」画的基准图。
- 视频模型会被参考图上的光拉回清晨。这违反了「设定图只画光影锁、镜头挂载对应的那张」这一原则。

### C. 生成与核验

**C1　变体和基准图的依赖没有绑定实际图片**

- 变体任务的摘要绑定的是基准的设计文本，不是基准成图本身。基准图重新生成以后，按旧基准图做出来的变体图看起来还是有效的。
- 人物的 `designFingerprint` 也只哈希了 `image` 块。

**C2　Midjourney 的变体和 style-match 门冲突**

- assets 原规则说 MJ 变体不写风格短语，因为风格随原图参考带过来。
- `style-match` 门要求每条 sheet 都含画风原句，现在只能保留「Overall style」那一段，可能和原图参考冲突。

**C3　变体没有数量上限**

- 预算只计资产身份数，一个道具写十个状态，就会有十个付费任务，没有阻断。
- 这里只要求像资产预算那样提供一个明确上限，不做统计或累计日志。

**C4　变体提示词的结构不检查**

- 道具的 `states[1..]` 只检查纯净画质段，没有检查「指向参考」和「只改什么」两块是否存在。

**C5　未成年人「不出图」没有地方记录**

- 规则要求在条目里写明不出图和理由，但人物没有变体条目，这条记录现在无处可写。

### D. 文档

- **D1**：`mint-characters/references/sheet-prompt.md` 写着「换装、受伤、跨年龄这类外观变化由下游按需处理」，但下游实际上没有处理入口，这句话对读者是误导。
- **D2**：题材参考里列了大量「常见变体」，写手照着拆完却无处可写，需要统一说明。

## 四、改法方向

### 方案一：统一的「外观」模型（推荐）

三类资产都使用同一种结构：身份下挂多个外观，基准是其中一个。

```json
"looks": [
  {"id": "C01-L01", "key": "baseline", "name": "日常", "base": true,
   "sourceRefs": [...], "image": {"sheet": "...", "negativePrompt": "..."}},
  {"id": "C01-L02", "key": "left-arm-bandaged", "name": "左臂包扎",
   "changes": "左前臂缠白色纱布……", "sourceRefs": [...], "origin": "script",
   "image": {"sheet": "...", "negativePrompt": "..."}}
]
```

- **ID**：外观 ID 是「资产 ID + L + 两位数」，永久不变，退役后不复用，由 reconcile 分配，和身份 ID 规则一致。这样解决 A3。
- **场景**：光照状态和空间状态都改为外观，`lighting[]` 并入 `looks[].lighting`。删除 `variantOf` 新建身份的做法，只保留一种表示，解决 A2。
- **道具**：`states[]` 改为 looks，解决 A3。
- **人物**：在 cast 里加 looks，解决 A1。未成年人限制状态写成 `"image": null` 并附 `noImageReason`，解决 C5。
- **来源**：每个外观带 `sourceRefs`，以及 `origin`（script / estimate / design），解决 A4。
- **script**：场次引用改为可带外观，例如 `characters: [{"id":"C01","look":"C01-L02"}]`，`lighting` 文本改为场景外观 ID，解决 B1。`assetMappings` 增加外观映射。
- **creation**：参考图按「资产 + 外观」解析为 `images/<外观 ID>-sheet.png`。缺图时阻断，不静默回落到基准图，解决 B2 和 B3。
- **依赖**：变体任务的摘要绑定基准成图的 SHA256，解决 C1。
- **预算**：增加 `looks` 明确上限，解决 C3。

**代价**：按 CLAUDE.md 不能多版本共存，需要同步升版本：cast 1→2、art 1→2、script 4→5，creation 视解析逻辑改动可能 3→4。同时直接修改所有现行代码、样例、测试和文档，不写迁移。

### 方案二：最小改动（不升版本）

- 只修 A3：states 只允许在末尾追加，validate 带 `--previous` 时检测调整顺序和中途删除。
- 只修 B2：creation 增加按道具状态名解析图片的规则。
- 人物变体继续不支持。

**代价**：A1、A2、B1、B3 都没有解决；状态名会变成隐式外键，以后改成方案一时还要再改一遍。**不推荐**，只适合作为过渡。
