## 2. 按方案逐项核验

| 方案要求 | 当前实现与验证证据 |
| --- | --- |
| §1–3 职责分层、稳定流程与接口 | 六个目录保持；JSON为编辑源；场次／flow、生成段／镜头和资产职责仍分离。六个 skill 独立拷贝执行自己的全部自测通过 |
| §4 选择、视觉与制作参数分离 | setup init/show/resolve及严格选择正反例通过；characters/art不安装创作profile仍可读取背景，缺视觉正文不能生成资产 |
| §5.1–5.3 本地发现、格式与组合 | 新增目录可发现；重复身份、未知字段／规则、非法版本、目录逃逸、链接与缺指南拒绝；完整规则冲突、集合顺序和显式覆盖测试通过 |
| §5.4 显式应用与来源 | 中性重建、旧覆盖逐项决定、预览取消、备份、写入故障与并发变化保护通过；历史读取不重算参数；同版本漂移拒绝继续应用，明确升级可绕过未选旧版本的损坏规则／指南 |
| §5.4 应用后检查 | 三个消费者实际重新检查本阶段及已知项目JSON接口；损坏、过期、歧义或悬空阶段入口返回非零。参数写入成功与后检查失败分别汇报，不自动改写故事 |
| §5.5 阶段矩阵 | outline/script加载四维；creation只加载三维，structure只记录；characters/art不伪造profile摘要。不同阶段摘要不同不导致身份误判 |
| §6 大纲通用契约 | story、event/pressure/turn/payoff、required/optional问题、明确期限、唯一后续解决、可选不重叠arcs及资产引用均有正反例；数组型ID不能靠字符串转换通过 |
| §7 规则与结果 | 全部注册规则显式保存；off/warn/error、未知参数、旧字段、分阶段跳过均验证。warn失败不计通过或阻断，缺上游不冒充策略关闭 |
| §8.1–8.2 剧本投影与认领 | seed不复制Q，不伪造位置；同类型不同ID分别认领；漏领、多领、错集、重复、越界、倒序、重叠均失败；共享铺垫与跨场核心段通过 |
| §8.3 时长 | 上游目标严格相等，不能靠容差放宽。估时保留原始精度，显示时舍入；无效范围不可用。目标容差闭区间仅消除浮点运算误差，模型硬上限仍严格拒绝超限 |
| §8.4 视频创作 | 舒缓组合真实采用8秒观察镜头；技术时长、参考图、提示词约束不能被策略关闭。videos拒绝超限截短；force不复用旧任务，普通续传核对现有台账中的输入身份 |
| §9 切换与独立运行 | 项目先改变选择后，旧下游失败；仅同步剧本不能掩盖旧大纲。切换不改集数、时长、预算、估时或技术参数。真实缺失与已提供损坏输入分开 |
| §10 报告与评审 | 中英HTML／Markdown、分类状态、节点文本对照、转义、原始JSON导出均回归；合并器保护数据块，不把正文url文字当CSS；内容评审另见第5节 |
| §11 迁移 | 各skill携带迁移说明。旧大纲／剧本缺版本或旧版本明确拒绝；结构搬运不冒充语义迁移。旧产物需先备份，再逐个核对节点、集尾与正文 |
| §12 文档与消费者 | SKILL、schema、通用指南、策略指南、中英README、CHANGELOG、流程图及根合并报告均更新。历史CHANGELOG不改写为过去已支持新功能 |
| §13 自有样例与回归 | 正式样例分别为《旧站时刻》《修伞簿》《收书人》《雨棚留言》《渡口》及setup原有两份制作参数；三组合联合fixture使用独立原创故事，不借用正式样例 |
| §14–15 完成与边界 | 本地全量测试、独立审查修复、内容复核和真实浏览器验收完成；没有提交、发布、真实媒体生成或市场效果结论 |

应用后的本地接口检查不是兄弟阶段完整校验器。完整联合流程仍须各阶段自己的校验与内容评审；报告已经明确这个边界，没有将局部接口通过包装成投产完成。
