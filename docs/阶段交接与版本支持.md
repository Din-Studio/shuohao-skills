# 阶段交接与版本支持

## 权威来源与消费者盘点

完整流程顺序固定为 **outline → characters → art → script → creation**。人物和美术阶段必须回查原剧本，不从大纲复制资产身份。单独复制任一 skill 仍可独立运行。

| 现有读取位置 | 新权威来源 | 独立入口无上游 | 联合制作阻断条件 |
| --- | --- | --- | --- |
| outline 校验、报告 | outline v5 只保存故事、节点、分集、问题和来源 | 原剧本不可缺失；结构草稿不等于完成 | 来源缺失、版本或覆盖不符、节点问题引用无效 |
| characters 的 seed、来源事实、角色设计 | 原剧本及本阶段 cast；outline 仅提供故事背景 | 可不提供 outline；故事对账 skipped | 身份或来源不确定时不得假称确认；明确角色预算超额 |
| art 的 seed、场景及道具设计 | 原剧本及本阶段 art；人物事实参考 cast | 可不提供 outline/cast；对应对账 skipped | 资产或来源不确定时不得假称确认；明确美术预算超额 |
| script 的人物、场景、道具引用检查与报告名称 | 正文局部标记；显式 assetMappings 指向 cast/art | 无上游可表达正文；联合对账 skipped | 已提供上游损坏、版本不兼容；映射冲突或依据不足 |
| script 的节点认领、开场、集尾及问题展示 | outline v5；正文位置仍由 script 负责 | 无 outline 时节点对账 skipped | 节点漏领、多领、倒序；来源版本不一致 |
| creation 的名称解析、设定图路径与挂载 | script 映射及对应 cast/art 身份；不再读 outline 资产 | 缺少可选资产时明确 skipped；不冒称联合交付 | 实际画面或声音依赖的身份缺少确认映射、来源或必要素材；画外发声者也必须核对，但不强制人物图片 |
| creation 的工作单、派发材料及输入摘要 | 当前正文、实际映射、cast/art 事实及相关来源 | 单独工作单结构检查不等于联合审核 | 相关身份、映射、原件或负责范围变化后旧审核不可沿用 |
| 提示词编写、独立审核与批准 | 派发材料的冻结输入和当前依赖摘要 | 可核验独立工作单，不假称完整制作 | 摘要变化、台词或声音引用不符、实际素材身份不符 |
| scripts/report.mjs | 各阶段 render；只组装，不推断身份 | 缺失面板明确显示 | 已提供但损坏的面板不能作为成功面板 |
| scripts/pipeline.mjs | 项目 pipeline.json；阶段产物及显式交接 | 不参与单个 skill 的独立入口 | 前序未完成、产物变更、原剧本改版、交接仍有阻断问题 |

路径基准：每份产物的 provenance.documents[].path 相对该产物；pipeline.json 中的路径相对流程状态文件。文档 ID、字节摘要和行数用于版本对账；标题和名称不能替代来源身份。

## 版本规则

每种产物只有一个现行版本，各 skill 只读写这一版：

| 产物 | schemaVersion |
| --- | --- |
| outline | 5 |
| script | 4 |
| production、creation | 3 |
| cast（characters）、art | 1 |

- 校验、seed、render 及消费端只接受上表版本；版本号不符或出现未知字段直接报错，不隐式读取旧版本。
- 不提供迁移命令、旧版读取路径或旧版夹具。契约变化时直接修改现行代码、样例和测试，并同步提升版本号；不保留旧版本实现。
- script 的局部 C/S/P 字符串不自动成为全项目身份。新增映射不改变正文顺序与同次发声语义。
- 完成来源复读、身份核对及必要映射后，重新核验受影响的工作单、图片路径与审核输入。保留 ID 不等于保留旧批准。

## 项目级流程状态

入口是仓库组装器，不属于任何单个 skill，不会成为单个 skill 的运行依赖：

```bash
node scripts/pipeline.mjs init /项目/pipeline.json \
  --title 故事标题 --scope 第一集 \
  --source /项目/原剧本.txt
node scripts/pipeline.mjs begin /项目/pipeline.json outline
# 阅读原件并完成本阶段。可通过 run 执行本阶段命令。
node scripts/pipeline.mjs run /项目/pipeline.json outline -- validate /项目/outline/outline.json --verify-sources
node scripts/pipeline.mjs complete /项目/pipeline.json outline \
  --artifact /项目/outline/outline.json --handoff /项目/outline/交接.json
# 按同样方式依次进入 characters、art、script、creation。
node scripts/pipeline.mjs check /项目/pipeline.json
```

交接文件必须显式确认本次任务范围。它不是工具自动给出的语义审核结论：

```json
{"confirmed":true,"scope":"第一集","unresolved":[]}
```

范围外的未决事项可记录为 `{"text":"第二集人物身份待原件补充","blocking":false}`。范围内阻断事项不得标成非阻断。阶段完成时重新调用本阶段校验；失败则状态保持 active，不写入失败累计日志或统计。状态修改有排他锁，不能并行推进。状态入口不接受符号链接；路径基准统一到真实位置，避免别名形成两份完成记录。人物必须已 identified 且身份审核已确认，美术必须 ready，草稿不能完成完整流程交接。

增量人物或美术完成交接时，可以显式提供 `complete ... --previous 既有产物.json`。工具将基线传给该阶段核验，并登记基线摘要；不能借此覆盖固定的前序输入。

每次开始下一阶段都检查前序产物、交接及原件摘要。修改已完成产物后，使用 `reopen STATE STAGE` 重新核验该阶段及后续流程交接。原剧本改版后，`reopen` 不会自动接受新摘要。必须先重新阅读并明确调用 `refresh-sources STATE --source 原剧本 --basis 复核说明 --confirm`，重新登记全部原件并重新进行五阶段交接。该操作保留上一次来源快照及本次依据，不修改任何原件或阶段产物。

这些操作只撤回流程完成记录，不冒充媒体或内容审核失效判断。各阶段仍按实际依赖决定哪些映射和审核需要更新，不把无关素材一并判成无效。

`workflow: complete` 只表示所登记范围的五阶段结构校验与显式交接完成，不表示全剧完整、语义忠实、媒体已生成或成片审核通过。
