# 创作产物与指南精简实施计划

## 1. 状态与目标

- 状态：已实施并完成本地测试，未提交、未推送。
- 本文保留实施要求；实际结果、证据和验证边界见 [验收记录](skills-创作产物与指南精简验收.md)。
- 最初规划阶段仅新增本文；后续实施已修改 schema、脚本、指南、样例及测试。
- 分析依据：当前 outline/script 数据契约、自有样例、校验器、报告及 creation 消费代码。
- 没有真实用户使用统计。本文的常用程度判断来自创作场景与代码用途，不代表使用率。

### 1.1 核心原则

> JSON 保存故事内容和必要交接关系；Markdown 保存创作方法；工具计算可推导信息。

普通创作者不应为了写故事而管理策略版本、摘要、覆盖路径或关闭规则对象。

实施后应做到：

1. 无须选择四个 profile，即可完成原创或改编。
2. 无须执行 apply-profile，即可修改创作方向。
3. 原创不填写改编取舍和逐人原创来源。
4. 普通故事不强制建立问题回收表、兑现分类和阶段规划。
5. 删除一句台词时，不需要维护可由正文计算的结束坐标。
6. 创作指南修改不会使既有故事失效。
7. 重要事件遗漏、引用错误和损坏输入仍能被检查发现。
8. 每个 skill 仍可独立复制和运行。

### 1.2 不在本轮实施范围

- 不重新设计图片或视频生成协议。
- 不修改模型能力、收费调用和媒体交接边界。
- 不新增第三方 skill 或共享运行库依赖。
- 不新增永久评分、失败累积日志或统计系统。
- 不把所有业务 JSON 改成 Markdown。
- 不引入新的 profile 名称、模板注册中心或 Markdown frontmatter 配置协议。
- 不把剧本节拍坐标全面升级成稳定 flow ID。该改造涉及镜头覆盖协议，本轮保持已有坐标形式。
- 不重新创作正式样例的故事或分镜，只按新契约调整数据表达。

## 2. 总体决策

### 2.1 创作方法与数据契约分离

每个受影响的创作阶段使用一份本地指南：

```text
skills/mint-outline/references/创作指南.md
skills/mint-script/references/创作指南.md
skills/mint-creation/references/创作指南.md
```

三份文档分别负责大纲、剧本和视频表达。相互不依赖，不要求用户安装兄弟 skill。

“一份 MD”指每个 skill 的创作策略与评审方法合并为一份文档，不是整个仓库共享一份，也不是删除技术契约。

以下内容继续独立：

- schema.md：数据结构和接口约束。
- migration.md：旧产物迁移说明。
- 模型专用提示词、媒体交接说明：技术操作资料。
- 分卷等与策略无关的工具操作说明：按实际用途保留。

outline-pass、episode-pass、script-pass、shot-pass、review-core 中的创作方法与评审问题并入本阶段创作指南。纯命令操作只保留一个权威位置，不在多份文档复制。

### 2.2 删除配置框架，而非更换配置格式

删除正式创作流程中的：

- references/profiles/ 下的描述文件和版本目录。
- profile-contract.md。
- production.creative 四维 selection。
- 各阶段 creativeContext。
- params.rules 与策略生成默认值 params.defaults。
- profiles、profile、apply-profile 命令。
- selection、decisions、overrides 的正式创作文件要求。
- 来源摘要、同版本漂移、覆盖路径与策略身份一致性检查。

旧格式只允许由显式迁移入口读取。正式 validate/render 不双读旧格式，也不静默忽略旧字段。

### 2.3 保留数据版本

删除的是创作指南版本体系，不是数据协议版本。

outline、script、creation 的不兼容改动统一使用 schemaVersion 3。production 的版本处理以实施前核对实际契约为准：已有版本号则递增；没有版本号则明确采用 v3 所需的新契约标记，并更新全部消费者，不沿用模糊双读。

characters/art 若仅修改所消费的上游契约，而自身输出结构不变，不为统一数字而强行升级其输出版本。

## 3. 项目创作要求

### 3.1 唯一项目要求

项目模式在 production 中保存可选的自然语言字段：

```json
{
  "creativeBrief": "生活悬疑，表达克制。每集可以解决局部问题，不要求每集反转。最终澄清事实，但不强行和解。"
}
```

要求：

- creativeBrief 提供时必须是非空字符串。
- 不解析成枚举、规则或题材分支。
- 不自动推导兑现密度、集尾类型或模型参数。
- 不在 outline/script/creation 中复制项目要求。
- 独立模式允许阶段产物保存 creativeBrief；提供 production 时，非空项目要求与本地要求同时存在应明确提示并要求人工合并，不能静默选择优先级。
- 独立产物接入项目时，将要求合并进 production，再删除阶段副本。

项目要求变化后，由 Agent 根据实际内容检查受影响阶段。取消机械的策略身份同步，并明确区分“结构检查已完成”和“创作要求尚未重新评审”。

### 3.2 历史偏好迁移

params.preferences 中有实际约束的文本合并到 creativeBrief。不能只删除字段。

历史 genre 保留为作品题材描述，不作为规则选择器。历史 profile 只用于生成迁移说明，不将名称机械拼接成新创作要求。

## 4. outline v3

### 4.1 必需核心

保留：

- schemaVersion、source、可选 lang。
- params.episodes、minutesPerEpisode、genre、adaptMode。
- story.focusCharacterIds、premise、throughline、ending。
- characters、scenes、可选 props。
- beats 与 episodes。
- story.endingBeatId：保留明确的全剧结束节点，不能简单按数组最后一项替代其语义。

保留分阶段检查 skeleton、beats、full。阶段未完成不能冒充完整交付。

### 4.2 字段调整表

| 字段 | 处理 | 迁移与实现要求 |
| --- | --- | --- |
| story.audiencePromise | 可选 | 有明确内容则保留，不再为了通过校验填写口号 |
| story.drive | 删除 | 将独有的目标、阻力和代价合并进 premise/throughline，不机械丢弃 |
| adaptation | 整体可选 | 原创通常省略；改编仍保留真实取舍 |
| adaptation.core | 删除 | 独有信息合并进 story，避免重复概述 |
| adaptation.keep/cut/merge/risks | 按需提供 | 没有对应决定时允许省略，不要求空数组 |
| adaptation.sourceNote/evidence | 保留可选 | 保留真实来源与材料缺口；原文证据不得改写 |
| characters[].from | 可选 | 原创可省略；改编涉及来源时应保留 |
| characters[].arc | 改为可选 | 不强迫静态人物或单元配角编造变化；主要人物是否成立归内容评审 |
| beats[].type | 删除 | 独有含义合并进 setup/outcome；不要求给事件额外命名 |
| beats[].position | 可选 | 有明确位置意图时保留；未填写时仅依赖集号和数组顺序 |
| beats[].kind | 可选 | 默认不分类；填写时校验合法枚举 |
| beats[].weight | 条件可选 | 仅 kind=payoff 时允许，不再强制填写 |
| episodes[].stateChange | 删除 | 独有变化合并进 synopsis 或节点结果；改由内容评审检查推进 |
| arcs | 保持可选 | 长篇确有阶段目标时使用；不强制覆盖全剧或以兑现结束 |
| props[].beatIds | 保持可选 | 显式引用仍校验，不凭共集出现推断精确事件关联 |
| scenes[].reusePlan | 保持可选 | 不要求一次性场景填写复用方案 |
| params.preferences | 删除 | 合并到唯一创作要求 |
| params.rules/defaults | 删除 | 不再要求显式关闭规则，也不自动生成问题期限 |
| creativeContext | 删除 | 历史信息留在迁移备份，不进入新正式产物 |

### 4.3 梗概与节点

保留 episodes[].synopsis 与 beats，职责不同：

- synopsis：面向人的分集阅读摘要。
- beats：不能遗漏的重要事件及其结果。

不要求每个动作成为节点。不因为删除分类字段而合并或重编号既有 B ID。

节点顺序规则：episode 不递减，同集按数组顺序。填写 position 时只检查合法值，不再建立必须填写位置才能排序的前置条件。

### 4.4 集尾与问题追踪

保留 ending.mode/event。suspense、closure、open 描述实际结束方式，不限制每一类故事必须采用哪种结束方式。

question 改为按需登记：

- suspense 不再强制 question。
- 只有明确登记的问题才参与 Q 引用检查。
- 已登记 required 问题仍要求后续唯一节点解决。
- 已明确 dueByEp 时仍校验期限。
- optional 保留其含义；reason 改为可选，不强迫解释每一个开放问题。
- 不自动填写 dueByEp。
- closure 继续不承载新的待回答集尾问题，避免字段语义自相矛盾。

迁移不得直接删除未解决 required 问题来使检查通过。作者明确取消承诺时，须同步修改故事与对应引用。

### 4.5 制作预算

params.thresholds 继续可选。它表示作者明确给出的制作限制，不是创作风格。

- 显式预算可继续作为阻断检查。
- 工具内置参考预算仅展示为提醒，不阻断没有提供预算的作品。
- 报告标明“用户预算”与“工具参考值”，不能混为同一约束。

## 5. script v3

### 5.1 保留的正文结构

保留 episodes、scenes、flow。

- flow 仍是动作与台词的有序序列。
- 不强制动作台词交替。
- characters 不能由 speaker 自动替代：无台词人物仍可能在场。
- sceneId、characters、props 保留资产交接功能。
- lighting 保持可选，仅填写具有叙事或连续性意义的状态，不要求剧本提前设计完整布光。
- delivery 保持可选，仅记录无法从台词和情境直接理解的语气或表演差异。

### 5.2 上游计划不重复保存

有 outline 时：

- 剧本不持久化 opening、ending 的逐字副本。
- validate/render/creation 需要计划内容时从显式或已发现的唯一 outline 读取。
- source 与集号用于基本对账，但不能仅凭同名认定内容已经同步。
- 下游生成快照必须来自当前实际加载的计划，不取旧剧本副本。

独立 script：

- 可保存自己的 opening、ending，供独立创作与后续制作使用。
- 无 outline 时不要求伪造上游计划。
- 项目模式下发现重复计划字段则报出待迁移错误，避免形成两个可编辑真源。

导出面向人阅读的 Markdown/HTML 可以附带大纲计划。该展示副本不是另一份编辑源。

### 5.3 坐标与节点认领

- 删除 endBeat 持久化字段；统一由最后一个实际 flow 项计算。
- openingBeat 改为可选。省略表示没有单独标注开场表达落点，不等价于已人工确认第一拍。
- 报告可展示第一拍，但不得将其冒称为已核验的开场落点。
- beatClaims 保留现有 beatId/start/end 结构与对账能力。
- 独立模式没有规划节点时允许省略 beatClaims；提供 outline 时必须认领全部当集重要节点。
- 继续校验坐标存在、顺序、重复和重叠，不因为简化而降低引用检查。
- Agent 修改正文后必须同步重新计算受影响的认领坐标并执行检查。

本轮不承诺解决全部坐标维护成本。先消除确定可推导的 endBeat，再保留经过验证的下游覆盖协议。

### 5.4 参数与备注

- 删除 params.rules、creativeContext、seedNote。
- seedNote 中有创作信息的内容迁往工作记录，不静默丢弃。
- charsPerSecond、actionSeconds、tolerance 使用工具默认值；只有用户明确修改时才在 params 保存覆盖。
- 当前默认值可沿用 4.5、2.5、0.15，实施时核对现有统一入口。
- validate/render 不向文件写入默认值。所有时间轴通过同一个有效参数解析函数读取。
- targetSeconds 保留：支持独立剧本和批次交接。有 outline 时继续严格对齐上游目标。
- 估时超出范围改为明确提醒，不以粗略估时强制删除有效表演；结构损坏和不合法数值仍阻断。

## 6. creation 与其他消费者

本轮不能只修改 outline/script，否则现有制作交接会断裂。

### 6.1 creation

- 升级为 v3 接口。
- 删除 profile 选择、摘要、覆盖与规则应用流程。
- 合并本阶段创作方法为一份指南。
- 从 outline 或独立 script 获取开场与集尾计划。
- 从实际 script 正文计算结束坐标。
- openingBeat 缺省时不伪造开场映射结果。
- 保留镜头对 script 节拍的真实顺序覆盖检查。
- 保留模型技术限制、资产引用、参考图身份与顺序。
- 镜头时长的模型硬限制不删除；创作建议时长不作为所有作品通用硬门。
- 既有创作计划是否过期按实际引用、正文覆盖和内容评审判定，不再按 profile 身份判定。

### 6.2 setup

- 删除四维选择的必填提示及输出。
- 改为收集自然语言 creativeBrief。
- 更新 production 契约、示例和所有消费者。
- 不修改视觉 style 和外部媒体生成配置。

### 6.3 characters / art

- 更新读取 outline/production 的本地契约副本。
- 接受可选的人物来源、节点分类等新结构。
- 需要背景要求时读取 creativeBrief，不解释四维配置。
- 保持已有资产输出和外部媒体交接职责。

## 7. 创作指南内容与报告

### 7.1 指南编写要求

各指南包含：

1. 本阶段目标与职责边界。
2. 从用户要求识别创作方向的方法。
3. 不同题材、叙事方式、结构与节奏的处理建议。
4. 何时不适用某条建议。
5. 正反例。
6. 检查人物动机、因果、信息与承诺的具体问题。
7. 阶段交接注意事项。
8. 学习来源说明。

不是把原 profile 按目录顺序粘贴到一个大文件。应合并重复建议、消解冲突，并保留不同创作目标的选择空间。

指南不带机器执行规则，不要求精确版本，不通过文档哈希阻断继续创作。

### 7.2 报告调整

报告顺序改为：

1. 作品和分集正文。
2. 关键事件、资产与必要交接关系。
3. 时长估算与明确预算。
4. 结构问题和内容评审状态。

删除首页选择快照、来源摘要、覆盖路径、关闭规则列表。

可选字段没有填写时，不显示大面积空表、破折号和“未配置”警告。

继续区分：

- 结构检查通过。
- 提醒。
- 缺少上游而未检查。
- 内容评审未执行。

不把指南已读取或字段完整等同于内容质量通过。

## 8. 实施顺序

### 阶段 A：冻结影响范围

1. 全仓检索 creative、creativeContext、selection、apply-profile、openingBeat、endBeat、beatClaims 及被删字段。
2. 建立生产者—消费者表，覆盖 scripts/lib 中物理独立的契约副本。
3. 核对 production 版本机制及全部自测入口。
4. 记录当前自有样例的集数、关键事件、资产 ID、正文和交接关系，供迁移前后比较。
5. 冻结 v3 schema 与迁移映射，再开始代码修改。

完成条件：所有已知读写入口都进入清单，不以只搜索文档代替代码核对。

### 阶段 B：更新指南与项目要求

1. 编写三个本地创作指南。
2. 修改 setup 和 production 契约。
3. 修改 SKILL.md 的创作确认流程。
4. 移除 profile 操作要求，保留必要的结构检查与内容评审。

### 阶段 C：实现 outline/script v3

1. 修改数据校验、骨架生成和有效参数解析。
2. 实现按需问题追踪与改编说明。
3. 删除可推导字段持久化。
4. 更新 Markdown/HTML 报告。
5. 增加定向回归测试。

### 阶段 D：更新下游与跨阶段接口

1. 更新 creation 对计划和坐标的读取。
2. 更新 outline/script 内部的下游接口检查。
3. 更新 characters/art 的上游契约副本。
4. 移除三份 creative.mjs 及无调用价值的 profile 测试。
5. 保留与新契约相关的损坏输入、安全读取和引用检查测试，不机械删除整组回归。

### 阶段 E：迁移样例与文档

1. 迁移每个 skill 自有样例，不引用兄弟样例替代。
2. 保持既有故事、事件 ID 和原文证据。
3. 删除机械重复 delivery，保留真正的特殊表演说明。
4. 清理已失效 selection 示例和 profile 目录。
5. 更新 README、中英文说明、命令帮助与迁移文档。
6. 检查根目录 demo-script.json、联合测试夹具和外部说明中的旧协议。
7. 历史方案文档保留为历史资料，并标注已被本方案取代的范围，不伪装成当前操作指南。

### 阶段 F：完整验证与交付

执行第 10 节验收。只有全部通过后才声明迁移完成。提交与推送单独取得授权。

## 9. 数据迁移

### 9.1 迁移方式

提供显式 v2 → v3 迁移工具或阶段命令：

- 默认预览，不覆盖原文件。
- 写入新文件，或明确确认后备份再替换。
- 不自动操作用户项目目录。
- 不执行图片或视频生成。
- 输出待人工确认的语义迁移项。
- 无法确定内容如何合并时停止自动完成，不丢弃原字段。

结构变更可以自动执行；story.drive、adaptation.core、stateChange、preferences 中的独有内容需要人工或 Agent 审阅合并。

### 9.2 多文件迁移顺序

1. production 与创作要求。
2. outline。
3. script。
4. creation。
5. characters/art 的引用检查。
6. 全项目联合检查。

迁移过程中允许文件处于暂时不匹配状态，但不得宣称可交付。不能将多文件写入描述为跨文件事务。

### 9.3 旧策略约束的处理

旧 profile 和 rules 不能全部无声删除：

- 来自模板的默认创作约束：列入迁移预览，由用户决定是否成为自然语言要求。
- 明确手工覆盖：逐项提示，不假定它只是模板值。
- 模型技术限制与明确制作预算：保留在对应技术结构中。
- 哈希与 profile 版本：保存在原始备份即可，不迁入 v3。

迁移后的新正式产物不得含旧配置字段。运行时遇到旧字段应明确提示迁移，避免用户误以为旧规则仍生效。

## 10. 测试与验收

### 10.1 数据契约测试

- 最小原创大纲无需 adaptation、人物 from、audiencePromise、Q、arcs 和兑现分类。
- 改编数据能保留原文证据与取舍。
- 未分类节点仍能被 script 按 ID 完整认领。
- suspense 无 question 合法。
- 已登记 required 问题漏回收、重复回收、提前回收或超期仍失败。
- 无效资产引用、重复 ID、损坏版本和不合法参数仍失败。
- 未提供预算不因工具参考值而阻断；明确超出用户预算仍失败。

### 10.2 剧本测试

- 不保存 endBeat 也能得到正确结束坐标。
- 在末尾追加动作后，结束坐标随正文自动变化。
- openingBeat 省略时不产生虚假的已核验开场落点。
- beatClaims 的漏领、错集、重复、倒序、重叠和无效坐标仍失败。
- 省略估时参数与显式默认值产生相同时间轴。
- 参数覆盖被统一用于分集、节点范围和报告估时。
- delivery 缺省合法；特殊 delivery 在台词本中保留。
- 估时超标显示提醒，不伪装为实际成片时长。

### 10.3 跨阶段测试

- production → outline → script → creation 完整链路通过。
- 独立 script 无 outline 时可创作、渲染，并诚实报告未对账范围。
- 项目缺失、损坏和多候选上游分别处理，不能混淆。
- 删除大纲节点或修改剧本正文后，实际失效引用能被识别。
- creation 不再依赖 script 中的计划副本或 endBeat。
- 模型限制、资产与参考图顺序回归保持通过。
- characters/art 接受 v3 上游且不改变自身媒体协议。

### 10.4 迁移测试

- v2 样例迁移前后集数、关键事件、正文与资产 ID 不变。
- 原文 evidence 逐字保持。
- 旧语义字段有迁移去向或明确待确认项。
- 原文件备份可以恢复。
- 正式 v3 中不存在 creativeContext、params.rules/defaults 和废弃字段。
- 非法 v2 输入不会因迁移而被修饰成有效 v3。

### 10.5 文档与界面测试

- 每个 skill 独立复制后执行自测，不能访问兄弟目录。
- 重新运行全部现有自测入口与新增定向测试，记录实际入口数，不沿用历史通过数量。
- Markdown 和中英文 HTML 展示可选字段缺省状态。
- 浏览器检查报告正文优先、无大面积空配置区、无脚本错误。
- 全仓检索确认正式操作入口不再要求 profiles/apply-profile。
- 生成 HTML 不进入版本控制。
- 不调用真实付费模型作为本次 schema 迁移的必需验收。

## 11. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 删除看似重复的字段时丢失独有创作信息 | 预览语义迁移项；保留原文件；人工确认合并 |
| script 删除计划副本后无法独立阅读 | 人类导出附带上游计划；独立模式允许本地计划 |
| 下游仍假设 kind、from、openingBeat 必填 | 全仓消费者清单与缺省字段联合测试 |
| 指南合并后变成无结构长文 | 按任务与适用情境组织，删除重复内容，保留反例 |
| 删除策略系统时误删技术硬限制 | 分开列出创作建议、用户预算和模型限制 |
| 新旧版本混用导致静默错误 | 正式运行严格版本；迁移显式执行 |
| 误将结构通过当成内容符合新要求 | 报告单列内容评审状态，不自动宣布通过 |

## 12. 完成标准

全部满足才算完成：

1. 创作者可以不理解 dimension/version/profile 就完成主流程。
2. 三个阶段各有一份自包含创作指南。
3. 正式产物不含策略摘要、覆盖路径和关闭规则占位。
4. 原创、普通单元故事不被迫填写改编和问题追踪表。
5. 可推导的结束坐标不再由作者维护。
6. 关键事件、资产引用、明确承诺和镜头覆盖检查仍然有效。
7. 所有已知消费者完成 v3 对接。
8. 自有样例、完整自测、独立复制测试和报告检查通过。
9. 迁移说明明确数据丢失防护与验证范围。
10. 未引入第三方 skill 依赖、付费调用、永久评分或门失败累积日志。
