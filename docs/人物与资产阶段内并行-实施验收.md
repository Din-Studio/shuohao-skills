## 一、实施范围

- mint-characters 与 mint-art 均为 4.2.0；cast／art 正式契约仍为 schemaVersion 1。
- 原文识别、修订及增量核验采用独立 subagent 按批并行提取、单一整理、按批并行独立核验。
- 主会话不读取原文；每个调用累计最多接触四集，检索、前情和定向回读计入；长集继续缩小。
- 取消小体量主会话通读、逐批累计草稿接力及无法独立派发时的同会话回退。
- 单集按关注点独立并行，多集至少两个批次并发；核验覆盖整批而不是抽查漏登记。
- 整理者主要读取提取结果，必要时按需求限量读取特定集数原文；超限证据另派任务。
- 提取工作记录不提前分配正式 ID。保留现有注册、增量基线、预算和退休规则；核验期间冻结草稿，只有主会话发布正式文件。
- 设计由独立任务分组并行执行，复用 apply-designs、媒体交接和报告命令。

本次修改流程指南、双语入口说明、来源与生命周期约定以及回归测试；另对真实交接暴露的人物摘要消费缺陷做一行修复。没有新增产品调度脚本、候选索引、自动身份归并、永久工作记录协议或失败累积日志。

各 skill 的派发说明和样例自包含，不依赖兄弟 skill 的代码或参考文档。

## 三、独立审查

独立 code-reviewer 首轮发现一个必修问题：art 设计文件指南遗漏必需 id，而 apply-designs 实际按 data.id 校验。

最小修复：指南明确必需 id 与 designStatus，要求 id 匹配文件名和负责资产；补充静态规则和缺少 id 时不写回的接口回归。

第二轮结论为 **PASS**。审查验证了设计交接、原文累计上限、单写者、增量基线和审核确认顺序；未读取 Demo 原文，也未执行媒体生成。此结论不替代真实多代理执行及来源核验。

真实交接还发现：人物侧 identityHash 已纳入 notes 所引用文档，美术侧 characterIdentityDigest 却只计人物及别名来源。Demo 的 C08 仅在 notes 引用 D02，因此人物 validate 通过而 art seed --cast 拒绝。修复只在美术侧来源集合补入 notes 引用，没有重写指纹或放宽确认。

新增回归使用独立计算的预期摘要，覆盖 notes-only 来源接收及改版失效；实际测试 cast 的 20 条身份两侧摘要全部一致。第三轮独立审查 **PASS**：43 项 stage 测试与 32 组构造变体通过；在临时工作树删除修复行后，新回归按预期失败。临时工作树已清理。
