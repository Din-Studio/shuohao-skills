# 剧本解析融合 outline 与 script 方案

> 后续变更：显式迁移命令、旧版读取路径及旧版夹具已全部移除，每种产物只保留一个现行版本。下文提到的迁移内容仅记录当时实施，当前规则见[阶段交接与版本支持](阶段交接与版本支持.md)。

## 一、目标与边界

**将 mint-outline 改为已有剧本的解析入口，mint-script 形成唯一执行正文，现有制作链路负责分镜与提示词。**

本方案只解决三个问题：

1. 原剧本是否读全，提取的对象和事件是否有依据？
2. 哪些内容要发生、要发声，哪些说明只指导表演？
3. 这些内容能否准确交给现有制作链路，修改后能否发现过期材料？

来源完整保留，不等于每句说明都要朗读或单独上镜。表达可以在授权范围内转换，但不能丢失关键事件、因果、人物选择、揭晓顺序和锁定措辞。

### 已确认与待确认

- **已确认：** outline 只接受剧本，不再接受小说或大纲。项目配置和任务要求是辅助输入。
- **已确认：** 各 skill 自包含，可独立复制；不依赖兄弟 skill 的实现或样例。
- **本方案建议：** 支持受约束的视听转译，不新增必经 skill。
- **权限未确认时：** 只整理来源、区分内容性质、报告表达缺口。转译候选不进入正式执行正文。
- **获得转译授权后：** 可以调整表达渠道、合并重复说明；不得改变剧情事实、选择、结果、揭晓和必须保留的歧义。实际对白、明确发声的 VO 与关键字幕默认保留原句。删改这些内容或新增关键行为须有明确授权。
- **不在本次决定：** script 的其他创作入口是否保留。不得把 outline 的入口限制扩大为删除 script 的独立创作能力。

权限沿用项目要求与明确的任务授权，不先设计三档模式字段、权限引擎或逐项审批系统。自动驾驶不能自行扩大授权范围。具体剧本的允许变化和禁止变化，在执行任务前确认。

**本次范围止于解析、执行正文及现有制作接口的接通。** 不新增翻译、粗剪、剪辑或成片审核能力，不改变现有可选生成流程。需要这些能力时另行确定交付；提示词批准始终不代表成片通过。

本文是待实施方案。代码核查基线为 `637274e`；本次仅精简方案，未修改 skill 或代码，未执行真实转译或制作。

## 二、审核取舍

取舍标准：一个概念只有在防止内容错误、支撑实际交接或验证当前交付时才保留。能由现有数据和流程承担，就不再增加平行机制。

| 原方案内容 | 处理 | 理由与落点 |
| --- | --- | --- |
| 来源、事件、正式内容、镜头之间的对应 | 保留关系，减少抽象层 | 给正式内容增加来源引用；继续使用 B ID、beatClaims 和制作覆盖检查，不新增“叙事要求节点”体系 |
| 三档权限 | 合并为授权边界说明 | 整理、转译、改写的区别保留；不将自由改写列为本次要实现的新流程 |
| 每场六问、转译六项工作表 | 合并到现有内容评审与必要注释 | 普通场次不重复填表；有转换风险时才记录来源、变化、依据和限制 |
| 观众／角色／制作人员知情分类 | 保留语义，按需交接 | 记录会影响当前表达的前情和禁区，不建立全人物×全场次的知情矩阵 |
| 来源事实、转译决定、制作决定、视听实现四类管理 | 按现有阶段归属处理 | outline 保存提取事实，script 保存正式内容，人物／美术与 creation 保存各自决定；不新增四份登记文件 |
| 来源整理稿、执行稿、转译记录等产物 | 收敛编辑源 | 保留原件与现有阶段 JSON；正文展示和报告只派生，现有制作工作单保留 |
| 局部批准失效 | 扩展已有实现 | 补齐实际消费字段和输入摘要，不另建失效系统 |
| “冻结制作计划→纯模型适配”独立步骤 | 移除 | 现有编写方同时负责分段、分镜和模型适配，不另设导演交接层 |
| 翻译、时间排演／粗剪、成片审核 | 移出本次实施与验收 | 方法参考仍保留，但不是解析融合完成的前提 |
| 四层验证状态 | 收敛到本次审核对象 | 分别报告来源／正文核验和制作计划审核；不新增统一审批状态机 |
| 固定题材清单、出图次数阈值、间隔三集补说明 | 不吸收 | 与准确解析和实际制作需求没有必然关系 |

上述取舍不等于删除必要检查。仅修改入口文案、把心理说明塞进 action，或直接取消重复认领检查，都不能完成本次融合。

## 三、最小流程与职责

```text
原剧本 + 项目要求与授权
    ↓
outline：按范围读取 → 归并对象与事件 → 核对覆盖和跨集事实
    ↓
script：读取原文与解析结果 → 整理执行正文 → 授权范围内转译
    ↓
独立核验来源与正文，修正遗漏、越权和连续性错误
    ↓
人物／美术：按需求落实视觉资产
    ↓
creation 调度现有编写方：分段、分镜、声音安排与提示词
    ↓
确定性检查 → 现有独立审核 → 回写与导出制作计划
```

这是职责关系，不要求新增常驻角色或全部串行。人物与美术可以提前整理已确定的事实；先定故事和表达需求，再制作相应图像。来源与正文核验可以由一个独立审核上下文完成，不必为每种内容分类各设一道审批。

| 阶段 | 唯一负责的内容 | 不负责 |
| --- | --- | --- |
| outline | 已读范围、全剧结构、对象身份、重要事件、必要连续性事实及出处 | 改写剧情、决定镜头、机械决定出图 |
| script | 正式行动、发声内容、必要非发声说明及来源关系 | 从梗概重写原文、设计机位或模型语法 |
| 人物／美术 | 视觉设定、基准与变体，标明制作补定 | 将补定冒称原剧本事实 |
| creation 及其编写方 | 在正式内容范围内设计分镜、声画关系、时间与模型提示词 | 自行删除台词、改变剧情或揭晓 |
| 独立审核 | 对照当前依据找出遗漏、越权、表达与交接错误 | 替编写方创作或批准尚未生成的成片 |

发现来源遗漏返回 outline；改变正式内容返回 script；镜头和提示词问题留在制作阶段。站位、手势等细化，只要不改变事实和知情范围，可以由现有编写方完成，不逐项退回上游。

## 四、必须保留的内容规则

### 4.1 原文、覆盖与对象

- 原件不可覆盖。来源引用必须能定位到确定版本的原文范围，不只写剧名或一段摘要。
- 沿用已有集场边界；整理补出的场界明确标记。缺集、部分场次或结尾未知，按实际范围交付，不伪造全剧完整性。
- 重叠读取按来源位置去重。不同位置重复发生的台词和行动分别保留，不能按文本相同去重。
- 对象先记录出现依据，再归并身份。复用稳定 C/S/P ID；同名不等于同一对象，别名合并需要证据，证据不足保持分开。
- 场次序号表示叙事顺序，S ID 表示地点身份。同一地点的多场戏、同一实物的交接或损坏，不因此新建对象身份。
- 保留无台词人物；区分可见、只出声和仅被提及。对象出现不等于必须出图，非人主体和群演的资产归类须依据真实样例确认。
- 区分客观事实与角色猜测、谎言、转述。未写明的侧别、动机和过渡保持未知；制作补定不得覆盖源事实。

不将每次出现的所有细节强制建成永久数据库。读取记录支持回查；下游确实依赖的身份、状态与限制进入正式交接。

### 4.2 长文本与连续性

短剧本直接读取；长剧本按集场和实际上下文负载分块，超长场次再沿完整话轮或行动拆分。每块区分负责范围与仅供理解的相邻上下文，并登记覆盖；不能用模型窗口大小或“每批三集”证明已经读全。

局部读取可以并行，但对象 ID、重要事件及跨集事实统一归并后再交给 script。分片放入阶段 `.work/`，由一个发布者组装正式结果，不能让各 agent 在阶段根目录并列发布互不一致的正式 JSON。

只交接影响当前任务的前情和状态，并附原文依据：

- 人物位置、道具持有人、伤势等状态的生效、延续与结束。
- 观众和角色分别在何处获知信息，哪些仍不能确定。
- 闪回所处的故事时间，不能套用后来状态。
- 尚未揭晓的身份使用当时可见称呼，不能因统一 ID 而在台词、报告或提示词中提前泄露。

不只传上一集摘要，也不向每个镜头分发全部秘密。制作确需隐藏背景时，附明确的“不发声／不提前揭晓”限制。首版使用文件、来源引用与现有 ID，不建设图数据库、通用记忆服务或多模型投票系统。

### 4.3 执行正文与视听转译

script 同时读取原文和 outline，不能根据梗概重新生成原台词。正式内容至少要区分：

| 内容 | 处理 |
| --- | --- |
| 行动 | 谁做什么、次序和结果；不能用抽象心理标签冒充动作 |
| 发声内容 | 保留文字、发声者与必要发声方式；画外对白不等于内心 VO |
| 非发声说明 | 作为表演依据或暂不公开的背景，不进入台词估时与逐字发声检查 |
| 字幕与声音说明 | 保留必要文字、时机和性质；不能因现有字段装不下而丢弃 |

这是语义要求，不是预定四种 flow 节点。字段布局通过样例决定。声音是否来自画外、谁能听见、是客观事件还是主观听觉，在会影响剧情时必须明确，不能用匿名 VO 掩盖差别。

每场只需交代本场发生的关键变化和不能改变的意义；普通场次可直接从正文读出，不另填功能表。存在转换风险时，在相关正文旁记录“来源 → 表达变化及依据 → 不能改变的内容”。授权来自任务或项目要求，不每行复制一份。

优先使用原文已有行动及其节奏承载说明。多段心理说明可以共同指导一次表演，不为每个形容词创建事件或镜头。具体背景若必须让观众知道，须有画面、声音或已建立的前情作为证据；一个眼神不能自动交代身份、日期或因果。

承诺、否定、条件和有意误导的台词可能就是剧情行动，不能为了“展示而非讲述”删除。有限让步也不能通过微笑、拥抱或音乐变成已经和解。

## 五、最小数据与接口改动

### 5.1 沿用现有编辑源

- 原件保存来源；outline JSON 保存提炼事实；script JSON 是唯一正式执行正文；人物、美术和 creation 保存各自制作结果。
- 来源展示、执行稿展示及报告 Markdown/HTML 从对应数据派生，不维护第二份可编辑执行稿。现有 `<段号>/prompt.md` 是制作协作文件，继续由编写／审核方维护，批准后通过 apply 回写 creation JSON，不将它误归为只读报告。
- 暂定的转译候选留在工作记录；下游依赖的正式说明、决定和限制必须有明确字段与读取入口，不能藏在临时笔记中。
- 优先在现有文档中增加必要局部信息。若确需辅助文件，明确唯一归属、引用和发现规则，避免被阶段目录的唯一 JSON 发现误识别。

### 5.2 只保留必要映射

| 关系 | 最小处理 |
| --- | --- |
| 原文 → 正式内容或非发声说明 | 增加可回查的来源范围；允许多段来源共同对应一处表达，记录转换或不直接呈现的理由 |
| 重要事件 → 正文 | 复用 B ID 与 beatClaims，不另建事件认领系统 |
| 正文 → 镜头／声音 | 扩展现有制作覆盖，区分一次内容发生与多个镜头引用 |

一次发声可以跨多个镜头持续，但不能因多镜引用而重复播放。同一句台词在原文不同位置实际说了两次，就保留两次。非发声说明可指导整场，不强制认领镜头。

先以跨镜 VO 样例确定最小扩展，不预建通用多轨时间线或任意多对多图。跨镜不等于取消漏项、顺序和重复检查；`skills/mint-script/scripts/lib/downstream.mjs` 与 outline 的本地下游检查也要同步适配。现有事件核心范围约束若妨碍忠实表达，应由样例证明后调整，不能改写剧情迁就校验器。

### 5.3 必须改动的旧假设

| 当前假设 | 调整原则 |
| --- | --- |
| outline 必须给出完整结局、连续全集及问题兑现 | 分开“提供范围已解析”和“全剧完整”；原作缺口作为内容问题报告，不补写答案，也不删除问题规避检查 |
| 规划分集与改编方式 | 改为提取已有分集和实际事件；删除小说／大纲入口对应的默认逻辑 |
| 制作目标由大纲固定分钟数提供 | 区分用户目标与来源事实。解析不必虚构目标；进入制作前再确认目标并对账，不能直接取消下游时长约束 |
| flow 只有 action/line | 增加必要说明与声音语义，并同步估时、渲染、seed、派发材料及审核消费者 |
| 每拍只归属一个镜头 | 保留覆盖检查，补充跨镜发声的身份与实现关系 |
| 新材料只要进入 brief 就已受批准保护 | 同步扩展现有 inputHashOf，绑定当前段实际依赖的内容与限制 |

字符语速与固定动作秒数继续作为粗估，不为本次融合重建时长预测器。非发声说明不得当作台词计时；跨镜发声不得在每个镜头重复累计。实际试读可以提供更可靠依据，但不新增强制录音流程。模型时长上限仍是硬限制，不能为了通过限制加速或删改剧情。

`prompt.includes` 保留为正式发声文本的有限逐字检查；发声者、位置和次数由相应结构及内容审核核对，不能据此声称实际音频正确。

### 5.4 材料消费与批准

复用现有 `dispatchBrief → 编写／审核 → inputHashOf → status/apply/export` 路径。新增的正文说明、声音方式、必要前情和揭晓限制，必须真正到达编写方和审核方，并进入相关段的批准依据。

上游变化后重新生成相关材料；正文、来源关系或相关限制变化，触发受影响内容复核。无关集场不应让全剧批准失效，不为此新增依赖调度服务。来源改版应先核对引用是否仍有效，不能仅因旧坐标存在就继续使用。

来源核验读取原文与正式正文，制作审核读取正式正文、必要上下文与工作单。两者对象不同，不能以提示词审核替代来源核验；但都沿用工作记录和独立上下文，不建立新的审批平台或永久失败日志。

### 5.5 outline JSON：精简创作规划字段

以下是契约调整建议，不表示当前 v3 已支持删除这些字段。原则是：outline 保存已有剧本的解析结果，不继续承担改编规划和制作预算决策；最终字段布局通过样例确定。

| 当前字段 | 建议处理 | 信息去向与边界 |
| --- | --- | --- |
| `params.adaptMode` | 删除 | 剧本解析不再选择原创、抽核、借壳等改编方式；转译授权按第一章处理 |
| `adaptation` | 从解析结果移除 | 不再维护保留／砍掉／合并计划；历史原文证据、有效限制迁入对应来源记录或项目要求，历史决定保存在迁移记录中，不直接丢弃 |
| `arcs` | 首版移除独立结构 | 必要阶段概括并入故事摘要，不另维护 A ID、阶段目标与终点关系 |
| `beats.position/kind/weight` | 建议删除 | 不要求区段、事件类别和兑现强度标签；集号、数组顺序及来源位置承担实际顺序，仍保留事件内容和 B ID |
| `scenes.reusePlan` | 移交美术阶段 | 复用和变体是制作决定，不冒称原文事实 |
| `params.minutesPerEpisode` | 移出 outline | 建议由 script 的逐集 `targetSeconds` 保存已确认的执行目标，不再维护两处等价目标；原剧本明确标出的时长仍作为来源事实保留 |

以下信息降低强制性，不等于全部删除：

- **故事概述：** 保留简短主线与必要结局说明，不要求 `premise/throughline/ending/audiencePromise` 分栏填满。后者当前已可选；不要为填表虚构观众承诺。
- **结尾定位：** `story.endingBeatId` 仅在确实识别全剧结尾时使用。部分来源不能被迫指定全剧终点。
- **开场与集尾：** 分集 `opening/ending` 仅保留有实际交接价值的事实和限制，不重复撰写梗概或强制选择创作模式。
- **问题追踪：** 保留问题提出、实际回答与仍未知的来源关系；取消解析阶段强制兑现及 `dueByEp` 等规划要求。原作未回答就是未回答，不能删去问题或补写答案。既有 Q ID 与 `resolves` 是否需要调整，由真实消费需求确定，不另建平行问题系统。
- **解释性内容：** `genre`、人物变化等按需记录，有依据才填写。
- **集数：** 已提供集数从实际记录计算；原作总集数是否已知、是否缺集，由来源覆盖表达，不能继续将 `params.episodes` 同时当作数组长度和完整性证明。

精简后的概念骨架是：**来源与覆盖、故事概述、人物／地点／道具及稳定 ID、分集概述与必要资产引用、重要事件及出处、影响下游的状态与揭晓限制。** 不以字段更少为由把这些信息全部塞入不可定位的长摘要。

`characters.tier`、`scenes.primary` 不能直接删除。当前角色 seed 将 tier 映射为 importance，美术 seed 读取 primary 与 reusePlan；调整归属时必须同步消费者，不能用默认值静默替代原含义。相关路径为 `skills/mint-characters/scripts/mint-characters.mjs` 的 `seedFromOutline`、`skills/mint-art/scripts/mint-art.mjs` 的 `seedFromOutline`。

### 5.6 script JSON：保留骨架，只补必要语义

继续使用“集 → 场次 → 有序正文”，附资产引用与 `beatClaims`。script 的重点不是大幅删除字段，而是避免增加重复配置，并补齐 action/line 无法表达的内容。

| 字段或信息 | 建议处理 |
| --- | --- |
| `openingBeat` | 继续可选；普通解析不填写，仅在需要定位开场表达时保存，不默认指向第一拍 |
| `params` | 沿用现有规则，只保存用户明确覆盖的估时参数，不写入工具默认值 |
| `creativeBrief`、`opening/ending` | 沿用现有单一来源规则：项目要求不在阶段重复保存，有 outline 时不复制开场／集尾计划；独立 script 的既有能力不在本次删除 |
| `beatClaims` | 保留，定位重要事件在正文中的实际表达；它不能被来源引用替代 |
| `scenes[].characters/props` | 保留明确资产引用，包括无台词人物；不从说话人或动作文本猜测资产全集，props 仍按需填写 |
| `lighting/delivery` | 继续可选，只记录有实际作用的差异；delivery 不承担“不发声”或声音身份的替代语义 |
| `targetSeconds` | 建议作为已确认逐集执行目标的唯一编辑源；纯整理阶段不强制虚构，进入制作前必须确认，并继续执行时长检查 |
| 来源引用、非发声说明及必要限制、发声方式与声音身份 | 补充最小语义，接入第五章已有消费与批准路径；不为每句增加功能、情绪、风险、审批和评分字段 |

其中参数默认值不落盘、项目要求不复制、有 outline 时不保存重复计划，都是现有能力，不列为重新建设事项。时长归属和可缺省阶段则是待实施的契约变化：必须同步 outline/script/creation 的本地接口与制作入口检查，不能只删除原来的分钟数对账。

## 六、实施顺序

### 第一步：以少量场景确定最小契约

先定测试故事、关键事实和预期，再设计表达，不先写分镜或出图。覆盖普通对白、长心理说明、跨集身份或道具状态、跨镜 VO。验证从原文到正式正文再到制作工作单的交接；本步不要求生成视频。

确认具体转译授权。仅把样例确实需要的数据纳入契约；未支持内容必须明确报出，不能静默丢弃。同步确定版本与显式迁移，不仅修改版本号。此时不先发布与运行契约矛盾的新入口说明。

### 第二步：沿真实消费链实施

1. outline：改入口、分块与覆盖记录、对象归并及来源完整性检查；按 5.5 精简创作规划字段，迁移有效证据与限制。
2. script：接入原文、必要分类与来源关系，按 5.6 保留正文和事件认领骨架，明确逐集目标时长的唯一归属及制作前确认要求。
3. 人物／美术：只补必要事实与状态消费；不重写已有视觉设计流程。
4. creation 与编写／审核方：接入新增材料、跨镜声音和输入摘要；保留现有调度与工作单循环。
5. 同步各阶段本地接口校验、seed、render、迁移及文档。不能只升级生产者而留下消费者按旧语义读取。

主要范围是 outline/script 的 SKILL、references 与 scripts，以及 creation 的 `contracts.mjs`、`worksheet.mjs`、派发材料和覆盖检查。编写／审核指南及其自包含副本同步更新；人物与美术按实际消费缺口修改，不预先全面重写。

### 第三步：回归与交付

运行各阶段自测、跨阶段接口测试和独立复制测试。根 README、阶段 README、样例与迁移说明同步更新。各 skill 使用自己的故事和测试夹具，不读取兄弟代码、样例或 `tmp/` 学习材料。渲染 HTML 不进入版本控制。

结构检查、来源／正文核验、制作计划审核分别汇报。未执行真实制作就明确写明，不新增成片状态或以计划通过冒充效果验证。

## 七、验收要点

| 验收组 | 必须验证的结果 |
| --- | --- |
| 来源覆盖 | 拒绝小说／大纲入口；完整与部分来源准确区分；重叠块不重复、边界内容不遗漏；原文不同位置的重复台词仍保留 |
| 身份与连续性 | 同名不同人不误并、有证据的别名可归并；无台词人物保留；场次与地点身份分开；交接、状态恢复及闪回使用正确依据 |
| 正文与权限 | 心理说明不自动发声；具体背景不以泛化情绪替代；事件、否定／条件／承诺、选择与结果保留；未授权候选不被制作消费 |
| 知情边界 | 事实与说法区分；称呼、台词、表情和声音不提前揭晓；制作补定不冒称源事实；有限让步不变成和解 |
| 制作交接 | 新增说明和限制实际进入派发材料与审核；一次 VO 可跨镜但只播放、计时一次；不同位置实际重复的台词仍各自发生；必要内容不漏领 |
| JSON 精简 | 删除规划字段后，历史证据与限制不丢失；角色／美术 seed 不依赖已移除字段或静默改用默认值；只有一处执行目标，纯整理不虚构时长、进入制作仍检查目标；已有不落盘默认值和不复制上游计划的行为不回退 |
| 修改与工程 | 只改声音方式或揭晓限制也会使相关批准失效；跨段依赖变化不遗漏、无关集场不连带失效；来源改版不会误用旧位置；发现、迁移、独立复制与损坏输入诊断通过 |

测试不只检查“字段存在”。至少沿真实 `seed／brief → 工作单 → 检查／批准 → 导出` 路径验证新增材料，并注入遗漏、重复和上游变化。内容审核必须回查原文；确定性测试不能代替语义判断。
